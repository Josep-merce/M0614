VS Code sobre Debian, terminal integrada i primer repositori Git/GitHub

Configurarem l'editor i la terminal que farem servir tot el curs, instal·larem Git i el connectarem amb GitHub. En acabar tindràs el teu primer repositori en línia amb un commit fet des de la terminal de VS Code.

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Obrir VS Code sobre Debian i treballar amb la terminal integrada.
  • Instal·lar i configurar Git (nom i correu d'usuari).
  • Crear un compte de GitHub i connectar-lo amb VS Code.
  • Crear el teu primer repositori, fer un commit i pujar-lo (push) a GitHub.

Prerequisits

  • Una màquina Debian (a l'aula, via IsardVDI) amb connexió a Internet.
  • VS Code instal·lat (ja ve preparat a l'entorn de l'aula).
  • Un compte de correu per registrar-te a GitHub.

Branca de treball

Tota la feina d'aquesta AEA es fa a la branca aea0. Quan creïs el repositori i la branca, recorda situar-t'hi:

bash
git switch aea0

En aquesta activitat encara no fem servir cap servei d'AWS. L'objectiu és deixar a punt l'entorn de control de versions que utilitzaràs a totes les AEA.

1

Context i teoria mínima

Durant tot el mòdul desplegaràs aplicacions i serveis. Per no perdre feina i poder demostrar què has fet, des del primer dia ho guardarem tot amb un sistema de control de versions.

Què és Git?

Git és un sistema de control de versions: porta un registre de tots els canvis que fas als teus fitxers. Cada vegada que guardes un punt de l'historial fas un commit, una "fotografia" del projecte en aquell moment, amb un missatge que explica què has canviat.

Què és GitHub?

GitHub és un servei en línia on pots allotjar els teus repositoris Git. Et permet tenir una còpia del projecte al núvol, compartir-lo i recuperar-lo des de qualsevol ordinador.

ConcepteQuè és
Repositori (repo)La carpeta del projecte amb tot el seu historial de canvis.
CommitUn punt guardat de l'historial, amb un missatge descriptiu.
Branca (branch)Una línia de treball independent. Cada AEA va a la seva (aea0, aea1…).
Push / PullPujar els commits a GitHub (push) o baixar-los (pull).
README.mdFitxer de text en format Markdown que descriu el projecte.

Pas a pas guiat

2.1 · Obrir VS Code i la terminal integrada

  1. Obre VS Code a l'escriptori de Debian.
  2. Crea una carpeta per a la feina del curs. Al menú File → Open Folder…, crea i obre una carpeta anomenada m0614 dins la teva carpeta personal.
  3. Obre la terminal integrada amb la combinació de tecles Ctrl + J (o des del menú Terminal → New Terminal). Apareixerà a la part inferior, ja situada dins la carpeta del projecte.
💡

La terminal integrada és la mateixa que faries servir a part, però oberta dins l'editor. Així pots escriure ordres i veure els fitxers alhora. La farem servir a totes les activitats.

2.2 · Comprovar que Git està instal·lat

Escriu a la terminal:

bash
git --version

➜ Demana a Git que digui quina versió té. Si surt una línia com git version 2.x.x, ja el tens i pots passar al pas 2.3. Si no apareix res, instal·la'l amb els dos passos següents.

bash
sudo apt update

➜ Actualitza la llista de programes disponibles. sudo vol dir "fes-ho com a administrador" i apt és el programa que instal·la coses a Debian.

bash
sudo apt install git -y

➜ Instal·la Git. L'opció -y respon "sí" automàticament a les preguntes de confirmació.

2.3 · Crear el compte de GitHub

  1. Obre el navegador i ves a github.com.
  2. Fes clic a Sign up i segueix els passos: correu, contrasenya i nom d'usuari.
  3. Verifica el compte amb el codi que rebràs al correu.
💡

Tria un nom d'usuari seriós i fàcil de recordar: el faràs servir tot el curs i quedarà a la URL pública dels teus repositoris.

2.4 · Configurar Git amb el teu nom i correu

Git afegeix el teu nom i correu a cada commit. Configura'ls una sola vegada (substitueix les dades per les teves):

bash
git config --global user.name "El teu Nom"

➜ Guarda el teu nom. --global vol dir que serveix per a tots els teus projectes, no només per a un.

bash
git config --global user.email "elteucorreu@example.com"

➜ Guarda el teu correu electrònic.

bash
git config --global --list

➜ Mostra la configuració guardada, perquè comprovis que el nom i el correu són correctes.

⚠️

Fes servir el mateix correu amb què t'has registrat a GitHub. Així els teus commits es vincularan correctament al teu compte.

2.5 · Connectar VS Code amb GitHub

La manera més senzilla és la identificació des del navegador integrada a VS Code:

  1. A VS Code, fes clic a la icona de Accounts (la persona, a baix a l'esquerra).
  2. Tria Sign in with GitHub.
  3. S'obrirà el navegador. Inicia sessió a GitHub i accepta l'autorització.
  4. Torna a VS Code: ja hi apareixeràs identificat amb el teu usuari.
💡

Aquesta autenticació pel navegador és l'opció recomanada a l'aula. Més endavant (AEA2) aprendràs SSH per connectar-te a servidors EC2; per a GitHub, de moment, n'hi ha prou amb aquest mètode.

2.6 · Crear el repositori a GitHub

  1. A github.com, fes clic al botó + (a dalt a la dreta) → New repository.
  2. Posa-li de nom m0614.
  3. Deixa'l públic i marca l'opció Add a README file.
  4. Fes clic a Create repository.

2.7 · Clonar el repositori a la teva màquina

A la pàgina del repositori, fes clic al botó verd Code i copia la URL HTTPS. Després, a la terminal de VS Code:

bash
# Substitueix EL_TEU_USUARI pel teu nom d'usuari de GitHub
git clone https://github.com/EL_TEU_USUARI/m0614.git

➜ Descarrega tot el repositori de GitHub al teu ordinador i crea una carpeta anomenada m0614.

bash
cd m0614

➜ Entra dins d'aquesta carpeta. cd vol dir "change directory" (canviar de carpeta). A partir d'ara les ordres de Git s'executen aquí dins.

Obre aquesta carpeta clonada a VS Code (File → Open Folder… → m0614).

2.8 · Omplir el README a la branca main

En crear el repositori, GitHub ha generat un README.md gairebé buit a la branca main. Com que main és el que es veu per defecte en obrir el repositori, l'omplirem abans de crear la branca aea0.

  1. Comprova que ets a main amb git branch (hi ha d'aparèixer un asterisc al costat).
  2. A VS Code, obre el fitxer README.md i escriu-hi una breu presentació del projecte:
README.md
# M0614 — Desplegament d'Aplicacions Web

Repositori de la feina del mòdul M0614.

- **Autor:** El teu Nom
- **Curs:** DAW · Institut La Mercè

La feina s'organitza amb una branca per cada AEA (`aea0`, `aea1`, ...).

Desa (Ctrl + S) i registra el canvi al main:

bash
git add README.md

➜ Prepara el fitxer que vols desar (és com posar-lo dins d'una caixa abans d'enviar-la).

bash
git commit -m "Omple el README del main amb la presentació del projecte"

➜ Desa el canvi al teu ordinador amb un missatge que explica què has fet. Això es diu fer un commit.

bash
git push

➜ Envia el commit a GitHub (a internet). Fins que no fas push, el canvi només és al teu ordinador.

💡

Ara, si obres el repositori a GitHub, el main ja mostra una presentació decent en lloc del README buit. A partir d'aquí ja podem crear la branca de treball de l'AEA.

2.9 · Crear la branca aea0

Tota la feina d'aquesta AEA va a la branca aea0. La creem a partir del main (que ja té el README ple) i ens hi situem:

bash
git switch -c aea0

➜ Crea la branca aea0 i hi entra alhora (l'opció -c vol dir "crea"). La branca hereta el README que acabes d'omplir. Per tornar-hi més endavant n'hi haurà prou amb git switch aea0 (sense -c).

2.10 · Ampliar el README a la branca aea0 i fer el commit

Ja a la branca aea0, amplia el README.md amb el que sigui propi d'aquesta AEA (ho concretaràs al repte). Perquè no el confonguis amb el README del main, canvia'n el títol perquè indiqui que és la branca de l'AEA0 (per exemple # M0614 · AEA0 — Preparació de l'entorn). Després registra el canvi:

bash
git status

➜ Mostra què has canviat des de l'últim cop. És útil per veure què estàs a punt de desar.

bash
git add README.md

➜ Prepara el fitxer per desar-lo.

bash
git commit -m "Amplia el README amb la feina de l'AEA0"

➜ Desa el canvi amb el seu missatge.

💡

El fitxer segueix anomenant-se README.md a totes les branques (és el nom que GitHub mostra a la portada). El que canvia és el títol de dins: així distingeixes d'un cop d'ull el main (presentació general) de la branca aea0 (feina de l'AEA0) sense reanomenar cap fitxer.

2.11 · Pujar (push) la branca a GitHub

bash
git push -u origin aea0

➜ Envia la branca aea0 a GitHub. L'opció -u origin aea0 connecta la teva branca local amb la del servidor; a partir d'ara n'hi haurà prou amb git push.

3

Verificació

  • A la terminal, git log --oneline mostra el teu commit amb el missatge que has escrit.
  • A la terminal, git branch mostra aea0 marcada amb un asterisc (és la branca activa).
  • A github.com, la branca main mostra el README amb la presentació del projecte (no el README buit inicial).
  • A github.com, al teu repositori m0614, despleguant el selector de branques apareix aea0.
  • Dins la branca aea0 a GitHub, el README.md mostra el text que hi has escrit.
💡

Si veus el teu commit tant a la terminal com a la pàgina web de GitHub, l'entorn de control de versions ja està a punt.
