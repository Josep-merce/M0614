El mateix servidor amb Docker

Instal·larem Docker i Docker Compose sobre Debian i, tot seguit, farem exactament el mateix que a l'A1 (muntar el servidor Apache), però dins d'un contenidor Docker.

RA RA1 CA 1.5 · 1.6 · 1.7
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Instal·lar Docker Engine i el plugin Docker Compose sobre Debian.
  • Executar Docker sense sudo afegint el teu usuari al grup docker.
  • Explicar amb les teves paraules què és un contenidor i en què es diferencia d'instal·lar un programa directament.
  • Descarregar una imatge d'Apache des de Docker Hub.
  • Executar un contenidor i publicar-hi la teva pàgina web.

Prerequisits

  • Haver completat l'A1.
  • Connexió a Internet per descarregar Docker i les imatges.
  • Permisos d'administrador (sudo) a la màquina Debian.
💡

Un contenidor és com una "caixa" que porta a dins tot el que un programa necessita per funcionar, llesta per executar-se a qualsevol màquina amb Docker instal·lat. Encara no fem servir AWS: Docker ens permetrà, més endavant, empaquetar serveis en contenidors abans de portar-los al núvol.

1

Context i teoria mínima

A l'A1, Apache es va quedar instal·lat "per sempre" a la teva màquina, barrejat amb tot el sistema. Amb Docker, Apache viu tancat dins la seva pròpia caixa (imatge), separat de la resta del sistema.

ConcepteQuè és
ImatgeLa "recepta" que conté Apache i tot el que necessita (httpd).
ContenidorUna còpia de la imatge en execució.
PortLa "porta" per on el navegador es connecta.
💡

Farem servir la imatge oficial httpd (el nom del projecte Apache a Docker Hub). D'una mateixa imatge es poden crear molts contenidors, i les imatges es descarreguen d'un registre, normalment Docker Hub.

Què és Docker Compose?

Docker Compose permet definir i executar diversos contenidors alhora amb un únic fitxer de configuració (docker-compose.yml). Avui l'instal·larem, però encara farem servir Docker "sol"; el farem servir més endavant per aixecar serveis complets (per exemple, un servidor web i una base de dades junts).

2

Pas a pas guiat

2.1 · Actualitzar el sistema i instal·lar dependències

Obre la terminal integrada de VS Code (Ctrl + J) i executa:

bash
sudo apt update

➜ Actualitza la llista de programes disponibles a Debian.

bash
sudo apt install -y ca-certificates curl gnupg

➜ Instal·la programes que Docker necessita per baixar-se de manera segura: ca-certificates (certificats de seguretat), curl (descarrega coses d'internet des de la terminal) i gnupg (comprova que el que descarregues és autèntic).

2.2 · Afegir el repositori oficial de Docker

Afegim la clau i el repositori oficials perquè apt instal·li la versió més recent de Docker:

bash
# Crear el directori per a la clau i descarregar-la
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/debian/gpg | \
    sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# Afegir el repositori a les fonts d'apt
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/debian $(. /etc/os-release && echo $VERSION_CODENAME) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
💡

Copia cada bloc sencer. Les barres \ al final de línia indiquen que l'ordre continua a la línia següent: és una sola ordre tot i ocupar diverses línies.

2.3 · Instal·lar Docker i Docker Compose

bash
sudo apt update

➜ Torna a actualitzar la llista perquè Debian "vegi" els programes del repositori de Docker que acabes d'afegir.

bash
sudo apt install -y docker-ce docker-ce-cli containerd.io \
    docker-buildx-plugin docker-compose-plugin

➜ Instal·la Docker i tots els seus components. El paquet docker-compose-plugin instal·la Compose com a subordre de Docker: l'invocaràs amb docker compose (amb espai).

2.4 · Executar Docker sense sudo

Per no haver d'escriure sudo a cada ordre, afegeix el teu usuari al grup docker:

bash
sudo usermod -aG docker $USER

➜ Afegeix el teu usuari ($USER) al grup docker, que té permís per fer servir Docker sense sudo.

⚠️

Aquest canvi no té efecte fins que tanquis i tornis a obrir la sessió (logout / login). Si no vols tancar sessió ara, pots executar newgrp docker a la terminal per aplicar-ho al terminal actual.

2.5 · Comprovar la instal·lació

bash
docker --version
Docker version 27.x.x, build ...

➜ Comprova que Docker s'ha instal·lat, mostrant-ne la versió.

bash
docker compose version
Docker Compose version v2.x.x

➜ Comprova que Docker Compose també ha quedat instal·lat.

2.6 · La primera prova: hello-world

bash
docker run hello-world

➜ Descarrega la imatge hello-world i en crea un contenidor que escriu un missatge i s'atura. Si tot va bé, veuràs un text que comença per Hello from Docker!: això confirma que Docker pot descarregar imatges i executar contenidors.

💡

Què ha passat? Docker no tenia la imatge localment, l'ha baixat de Docker Hub, n'ha creat un contenidor, l'ha executat (ha imprès el missatge) i el contenidor ha acabat la seva feina.

2.7 · Descarrega la imatge d'Apache

bash
docker pull httpd

➜ Descarrega la imatge oficial d'Apache (httpd) des de Docker Hub. Una imatge és la "recepta" amb el programa i tot el que necessita.

2.8 · Crea una carpeta local amb la teva pàgina

bash
mkdir -p ~/aea1-docker

➜ Crea una carpeta anomenada aea1-docker a la teva carpeta personal (el símbol ~). L'opció -p evita errors si ja existeix.

bash
nano ~/aea1-docker/index.html

➜ Obre l'editor nano per crear el fitxer index.html dins d'aquesta carpeta.

index.html
<!DOCTYPE html>
<html lang="ca">
<head>
  <meta charset="UTF-8">
  <title>El meu servidor amb Docker</title>
</head>
<body>
  <h1>Servidor web amb Docker — AEA1</h1>
  <p>Nom Cognom</p>
</body>
</html>

2.9 · Executa el contenidor amb la teva pàgina dins

bash
docker run -d -p 8080:80 --name servidor-aea1 -v ~/aea1-docker:/usr/local/apache2/htdocs/ httpd

➜ Engega un contenidor d'Apache amb la teva pàgina dins. Cada opció vol dir:

  • -d → l'executa en segon pla (no bloqueja la terminal).
  • -p 8080:80 → connecta el port 8080 del teu ordinador amb el port 80 del contenidor.
  • --name servidor-aea1 → li posa un nom fàcil de recordar.
  • -v ~/aea1-docker:/usr/local/apache2/htdocs/ → "munta" la teva carpeta dins del contenidor, on Apache busca les pàgines.
  • httpd → la imatge que fa servir.

2.10 · Comprova que el contenidor s'està executant

bash
docker ps

➜ Mostra els contenidors en marxa. Hi ha d'aparèixer servidor-aea1 amb estat Up.

3

Verificació

navegador
http://localhost:8080

➜ Obre la pàgina servida pel contenidor. Fixa't que ara el port és 8080, el que vas obrir amb -p.

bash
curl http://localhost:8080

➜ Comprova el mateix des de la terminal, sense navegador.

💡

Ara la pàgina viu al port 8080, no al 80 com a l'A1: hem dit a Docker que redirigís la porta 8080 de la nostra màquina cap a la porta 80 del contenidor.
