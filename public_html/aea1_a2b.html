Les tres maneres de Docker: terminal, Dockerfile i YAML

Aconseguirem el mateix objectiu (engegar un servidor web Nginx amb una pàgina personalitzada) de tres maneres diferents, de la més manual a la més automàtica. Així entendrem per a què serveix cada eina.

RA RA1
0

Objectius i prerequisits

En acabar aquesta pràctica, seràs capaç de:

  • Entendre la diferència fonamental entre docker run, Dockerfile i compose.yaml.
  • Executar un contenidor amb una configuració complexa (ports, volums) des del terminal.
  • "Enfornar" (bake in) el codi de la teva aplicació dins d'una imatge personalitzada amb un Dockerfile.
  • Definir i executar un servei de forma declarativa i reproduïble amb un fitxer compose.yaml.
  • Comprendre la diferència entre el llenguatge de "recepta" d'un Dockerfile i el llenguatge de "configuració" YAML.

Prerequisits

  • Haver completat l'A2a: Docker i Docker Compose instal·lats i funcionant sense sudo.

Opcional: començar amb el Docker net

bash
docker system prune -a --volumes -f
⚠️

Aquesta ordre esborra tots els contenidors aturats, les imatges i els volums que no estiguin en ús, sense demanar confirmació (-f). Fes-la servir només si no tens res a Docker que vulguis conservar.

1

Conceptes clau

Abans de començar, hem de tenir clara la diferència entre Dockerfile i compose.yaml.

CaracterísticaDockerfilecompose.yaml
Propòsit principalCONSTRUIR 1 imatgeEXECUTAR 1 o més serveis
Què és?Una "recepta"Un "pla d'execució"
Comandadocker builddocker compose up
ResultatUna imatge (ex: la-meva-web-custom)Contenidors funcionant
LlenguatgeFormat propi (FROM, COPY...)YAML (services: ...)
AnalogiaLa recepta per fer el pa.La comanda al restaurant: "Porti'm un entrepà fet amb aquest pa i un refresc".
  • Mètode terminal (docker run): és imperatiu. Dones ordres directes. És ràpid per a proves, però difícil de recordar, compartir i reproduir.
  • Mètode Dockerfile (docker build): és una recepta. Defineix els ingredients de la teva aplicació. El resultat és una imatge (el "pa") que pots executar fàcilment.
  • Mètode YAML (docker compose): és declaratiu. Descrius l'estat final que vols ("vull un servei web al port 8082"). És la forma estàndard de gestionar aplicacions, perquè és fàcil de llegir, compartir i gestionar.
2

Preparació inicial (comuna per a les 3 fases)

Crearem un projecte amb un fitxer web senzill.

2.1 · Crea una carpeta de projecte

bash
mkdir projecte_final
cd projecte_final

➜ Totes les fases d'aquesta activitat es fan des de dins de la carpeta projecte_final.

2.2 · Crea la teva pàgina web personalitzada

bash
echo '<h1>Benvingut a la meva web personalitzada!</h1>' > index.html

➜ Aquest index.html és el que volem que mostri el nostre Nginx.

3

Fase 1 · Mètode "terminal imperatiu" (docker run llarg)

Fem servir docker run i li passem tota la configuració (ports, nom i el fitxer web) directament a la comanda, amb un volum (-v).

3.1 · Executa la comanda

bash
docker run -d --name terminal_nginx -p 8080:80 \
    -v "$(pwd)/index.html":/usr/share/nginx/html/index.html nginx:latest

➜ Què fa cada opció:

  • -d → mode "detached" (segon pla).
  • --name terminal_nginx → nom del contenidor.
  • -p 8080:80 → connecta el port 8080 del teu ordinador amb el port 80 del contenidor.
  • -v ... → la clau. Munta el nostre index.html local ($(pwd)/index.html) a sobre de l'index.html per defecte de dins del contenidor.
  • nginx:latest → la imatge que fem servir.

3.2 · Comprovació

navegador
http://localhost:8080

➜ Hauries de veure "Benvingut a la meva web personalitzada!".

📸

Captura d'evidència 1. Fes una captura del navegador mostrant la teva web personalitzada funcionant a http://localhost:8080.

3.3 · Neteja de la fase 1

Atura i esborra el contenidor abans de passar a la fase següent:

bash
docker stop terminal_nginx
docker rm terminal_nginx
💡

Conclusió: ha funcionat, però la comanda és llarga, complexa i difícil de compartir.

4

Fase 2 · Mètode "Dockerfile" (construir i executar)

Ara, en lloc de "muntar" el fitxer des de fora, el "courem" (bake in) dins de la nostra pròpia imatge.

4.1 · Crea el Dockerfile

Assegura't que ets a la carpeta projecte_final:

bash
nano Dockerfile

Contingut del fitxer:

Dockerfile
# 1. Comença des de la plantilla base d'Nginx
FROM nginx:latest

# 2. Copia el nostre fitxer local 'index.html' cap al directori web del contenidor
COPY index.html /usr/share/nginx/html/index.html

➜ Desa i tanca (Ctrl+O, Enter, Ctrl+X).

4.2 · Construeix la imatge

bash
docker build -t la-meva-web-custom .

➜ build llegeix el Dockerfile de la carpeta actual (.) i crea una nova imatge al teu sistema anomenada (-t) la-meva-web-custom.

📸

Captura d'evidència 2. Fes una captura del terminal amb el resultat de docker build. Hi has de veure els passos [1/2] FROM i [2/2] COPY i la línia final naming to docker.io/library/la-meva-web-custom.

4.3 · Executa la NOSTRA imatge

Ara la comanda docker run és molt més senzilla. Fem servir el port 8081 per no tenir conflictes:

bash
docker run -d --name dockerfile_nginx -p 8081:80 la-meva-web-custom

➜ Engega un contenidor des de la nostra imatge. Ja no necessitem -v perquè l'index.html ja és a dins.

4.4 · Comprovació

navegador
http://localhost:8081

➜ Hauries de veure "Benvingut a la meva web personalitzada!".

4.5 · Neteja de la fase 2

bash
docker stop dockerfile_nginx
docker rm dockerfile_nginx
💡

Conclusió: molt millor! Ara qualsevol pot executar la nostra web amb una comanda simple. Però encara hem d'executar docker build i després docker run a mà.

5

Fase 3 · Mètode "YAML" (orquestració amb compose.yaml)

Aquest és el mètode professional. Definim tot el projecte (com construir-lo i com executar-lo) en un sol fitxer YAML.

5.1 · Crea el fitxer compose.yaml

Continua a la carpeta projecte_final, on ja tens l'index.html i el Dockerfile:

bash
nano compose.yaml

Contingut del fitxer:

compose.yaml
services:
  web:
    build: .
    container_name: compose_nginx
    ports:
      - "8082:80"
    restart: unless-stopped
  • services: → la llista de serveis (contenidors) del projecte. Aquí només n'hi ha un, web.
  • build: . → construeix la imatge amb el Dockerfile de la carpeta actual (el mateix de la fase 2).
  • container_name → el nom del contenidor.
  • ports → l'equivalent de -p 8082:80.
  • restart: unless-stopped → si el contenidor s'atura per un error o es reinicia l'ordinador, Docker el torna a engegar (llevat que l'hagis aturat tu).
⚠️

En YAML la indentació (els espais a l'inici de línia) forma part de la sintaxi. Fes servir sempre espais, mai tabuladors.

5.2 · Arrenca el servei

bash
docker compose up -d --build

➜ Construeix la imatge i engega el contenidor en segon pla, tot amb una sola comanda. L'opció --build obliga a tornar a construir la imatge si has canviat l'index.html o el Dockerfile.

bash
docker compose ps

➜ Mostra els serveis del projecte. Hi ha d'aparèixer compose_nginx amb estat Up (en marxa).

5.3 · Comprovació

navegador
http://localhost:8082

➜ Hauries de veure "Benvingut a la meva web personalitzada!".

📸

Captura d'evidència 3. Fes una captura del resultat de docker compose up -d --build. A continuació, executa docker compose ps i inclou-ne també la sortida a la captura, per demostrar que el contenidor està en marxa.

5.4 · Neteja final

La neteja també és més fàcil:

bash
docker compose down

➜ Atura i esborra tots els contenidors (i la xarxa) que havia creat docker compose up.

💡

Conclusió: aquest és el mètode superior. És declaratiu, reproduïble i gestiona alhora la construcció i l'execució.

Preguntes de repàs

  1. Comparació: quina de les tres comandes d'execució et sembla més fàcil de llegir i compartir? La de la fase 1 (docker run -v ...), la de la fase 2 (docker run ... la-meva-web-custom) o la de la fase 3 (docker compose up -d)?
  2. Propòsits: en aquesta activitat, per a què ha servit el Dockerfile i per a què ha servit el compose.yaml?
  3. YAML: què volia dir la instrucció build: . dins del fitxer YAML? Quina alternativa podríem haver posat si ja haguéssim construït la imatge a la fase 2? (Pista: image: ...).
  4. Projecte real: si haguessis d'enviar aquest projecte a un company perquè l'executi, quins fitxers li hauries d'enviar en el cas de la fase 3? Per què és això millor que donar-li la comanda de la fase 1?
