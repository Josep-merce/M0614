Munta i administra un servidor web segur per SSH

Muntaràs tres màquines a la mateixa xarxa privada: un servidor, un administrador i un client. L'administrador entrarà al servidor de manera xifrada per SSH per instal·lar-hi Apache i activar HTTPS; el client hi accedirà des del navegador. En acabar tindràs un servidor web administrat de forma remota i segura.

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Muntar una petita xarxa privada amb tres màquines: servidor, administrador i client.
  • Configurar una IP fixa a la targeta de xarxa interna de cada màquina.
  • Administrar el servidor de manera remota i xifrada amb SSH.
  • Instal·lar Apache i activar el web segur amb HTTPS (certificat autofirmat).

1

Context i teoria mínima

Un servidor web és un ordinador (o programa) que rep peticions i respon amb pàgines web. Fins ara l'has fet servir a la mateixa màquina (localhost); ara el posarem en una màquina a part i l'administrarem des d'una altra, com passa a la realitat: els servidors solen estar en una sala tancada i s'hi accedeix per la xarxa.

Per què SSH?

SSH (Secure Shell) obre un terminal del servidor des d'una altra màquina a través d'un canal xifrat. Així pots instal·lar i configurar el servidor sense seure-hi al davant, i ningú de la xarxa pot llegir el que hi escrius. És l'estàndard per administrar servidors Linux.

Per què HTTPS?

HTTP transporta les pàgines en clar; HTTPS les xifra amb TLS gràcies a un certificat. En aquesta activitat farem un certificat autofirmat (el genera el mateix servidor): és perfecte per practicar en una xarxa interna, tot i que el navegador mostrarà un avís perquè no l'ha emès cap autoritat de confiança.

Ampliar el servidor amb mòduls

Apache té un disseny modular: pots afegir o treure funcionalitats activant o desactivant mòduls. Els mòduls disponibles són a /etc/apache2/mods-available i els activats a /etc/apache2/mods-enabled. Per gestionar-los fem servir dues ordres:

  • sudo a2enmod <mòdul> → activa un mòdul (per exemple ssl, que ens caldrà per a l'HTTPS).
  • sudo a2dismod <mòdul> → desactiva un mòdul.

Després d'activar o desactivar un mòdul cal recarregar Apache perquè el canvi tingui efecte.

Les dues targetes de xarxa

Cada màquina d'IsardVDI té dues targetes amb funcions diferents:

  • Targeta default → té sortida a Internet. La fem servir per baixar i instal·lar paquets (apt). La seva IP l'assigna IsardVDI automàticament (DHCP), no la controlem nosaltres.
  • Targeta interna → connecta les tres màquines entre elles a la xarxa privada 192.168.1.0/24. Aquí posarem IP fixes i és per on viatgen l'administració SSH i el servei HTTPS.

Imatge 1 · Arquitectura de xarxa

Cada màquina té dues targetes: la de dalt (discontínua) surt a Internet per DHCP; la de baix les connecta totes tres a la xarxa interna amb IP fixa.

Imatge 2 · Flux d'accés

El Client accedeix al Servidor Web per HTTPS (port 443). L'Administrador es connecta per SSH al Servidor Web per configurar-lo, però no participa en el trànsit del web.

2.1 · Identificar les dues targetes de cada màquina

Totes les màquines

A cada màquina, obre un terminal i mira les targetes de xarxa:

bash
ip a

➜ ip a llista totes les targetes de xarxa de la màquina amb la seva adreça IP.

Veuràs dues interfícies (a més de lo). A IsardVDI solen anomenar-se enp1s0 i enp2s0. La sortida s'assembla a aquesta:

sortida de ip a
2: enp1s0: <...> state UP           # targeta DEFAULT (surt a Internet)
    inet 192.168.120.186/22 ...        # IP posada per DHCP → NO la toquem
3: enp2s0: <...> state UP           # targeta INTERNA (xarxa privada)
    (sense línia inet)                 # encara sense IP → aquí posarem la fixa

Identifica-les així:

  • La que ja té una IP del tipus 10.x, 172.x o 192.168.120.x amb sortida a Internet és la default (aquí enp1s0). No la toquis.
  • L'altra (sovint sense IP) serà la interna (aquí enp2s0), on posarem la IP fixa.
⚠️

Apunta bé el nom exacte de la targeta interna de cada màquina (per exemple enp2s0). El necessitaràs al pas següent i pot variar entre màquines.

2.2 · Assignar la IP fixa a la targeta interna

Totes les màquines · exemple: servidor

A Debian, les IP fixes es configuren al fitxer /etc/network/interfaces. Obre'l amb l'editor nano:

bash
sudo nano /etc/network/interfaces

➜ Obre el fitxer de configuració de xarxa amb l'editor nano. sudo el fa servir com a administrador (cal per editar fitxers del sistema).

Afegeix al final aquest bloc, canviant enp2s0 pel nom real de la teva targeta interna i la IP segons la màquina (servidor .10, administrador .20, client .30). Aquest exemple és el del servidor:

/etc/network/interfaces
# --- Targeta interna (xarxa privada) ---
auto enp2s0
iface enp2s0 inet static
    address 192.168.1.10
    netmask 255.255.255.0

Desa (Ctrl+O, Enter) i surt (Ctrl+X). Aplica els canvis reiniciant la xarxa:

bash
sudo systemctl restart networking

➜ Reinicia el servei de xarxa perquè la nova IP fixa tingui efecte.

Comprova que la targeta interna ja té la IP correcta:

bash
ip a show enp2s0

➜ Mostra només la targeta enp2s0 per comprovar que ja té la IP fixa assignada.

💡

No toquis la targeta default: ha de continuar amb DHCP perquè les màquines segueixin tenint Internet per instal·lar paquets. Repeteix aquest pas a les tres màquines amb la seva IP (.10, .20, .30).

2.3 · Comprovar la connexió entre màquines

Administrador

Des de l'administrador, comprova que arribes al servidor per la xarxa interna:

bash — administrador
ping -c 3 192.168.1.10

➜ Envia paquets de prova al servidor per veure si hi ha connexió. -c 3 en limita el nombre a 3.

Si reps respostes, la xarxa interna funciona. Fes la mateixa prova des del client.

2.4 · Instal·lar el servei SSH al servidor

Servidor

Ves a la màquina servidor. Instal·la el servidor SSH (es baixa per la targeta default):

bash — servidor
sudo apt update

➜ Actualitza la llista de paquets disponibles. Convé fer-ho abans d'instal·lar res.

bash — servidor
sudo apt install openssh-server -y

➜ Instal·la el servei SSH al servidor. -y respon "sí" automàticament a les preguntes de la instal·lació.

Comprova que el servei està actiu:

bash — servidor
systemctl status ssh

➜ Mostra l'estat del servei SSH.

Ha d'aparèixer active (running). Prem q per sortir.

2.5 · Connectar-se des de l'administrador per SSH

Administrador

Torna a la màquina administrador i connecta't al servidor (substitueix usuari pel teu nom d'usuari del servidor):

bash — administrador
ssh usuari@192.168.1.10

➜ Obre una sessió de terminal xifrada al servidor per SSH. Substitueix usuari pel teu nom d'usuari del servidor.

El primer cop et demanarà confirmar la fingerprint del servidor: escriu yes i prem Enter. Després introdueix la contrasenya. Quan hi entris, el prompt del terminal canviarà al del servidor: ja estàs administrant el servidor de manera remota.

💻→

A partir d'aquí, tot el que escrius s'executa al servidor, no a l'administrador. Per tornar a l'administrador quan acabis, escriu exit.

2.6 · Instal·lar Apache (des de la sessió SSH)

Administrador → Servidor · per SSH

Ja connectat per SSH al servidor, instal·la Apache:

bash — administrador → servidor (SSH)
sudo apt install apache2 -y

➜ Instal·la el servidor web Apache. -y accepta automàticament la instal·lació.

2.7 · Activar el web segur amb HTTPS

Administrador → Servidor · per SSH

Activa el mòdul SSL d'Apache:

bash — administrador → servidor (SSH)
sudo a2enmod ssl

➜ Activa el mòdul ssl, que permet a Apache servir pàgines per HTTPS.

Genera un certificat autofirmat vàlid per un any (respon les preguntes; a Common Name pots posar la IP 192.168.1.10):

bash — administrador → servidor (SSH)
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/aea2.key \
  -out /etc/ssl/certs/aea2.crt

➜ Genera el certificat i la clau. És una sola ordre (les barres \ uneixen les línies): -x509 crea un certificat autofirmat, -nodes no posa contrasenya a la clau i -days 365 el fa vàlid un any.

En executar-la, l'openssl et farà unes quantes preguntes (el subject del certificat). Pots respondre-les així:

preguntes del certificat
Country Name (2 letter code):    # país, 2 lletres → ES
State or Province Name:          # província → Barcelona
Locality Name (eg, city):        # ciutat → Barcelona
Organization Name:               # organització → Institut La Merce
Organizational Unit Name:        # departament (opcional) → DAW
Common Name:                     # ⚠ EL MÉS IMPORTANT: la IP o domini del servidor → 192.168.1.10
Email Address:                   # correu (opcional) → pots deixar-ho buit
💡

El camp que de debò importa és el Common Name (CN): ha de coincidir amb l'adreça per la qual accediràs al servidor (aquí la IP 192.168.1.10). La resta de camps són informatius i els pots deixar buits prement Enter.

Activa el lloc HTTPS que ja ve preparat a Apache i indica-li el certificat. Edita la configuració SSL:

bash — administrador → servidor (SSH)
sudo nano /etc/apache2/sites-available/default-ssl.conf

➜ Obre el fitxer de configuració del lloc HTTPS per indicar-hi el teu certificat.

Localitza les dues línies SSLCertificateFile i SSLCertificateKeyFile i deixa-les apuntant al teu certificat:

default-ssl.conf
SSLCertificateFile      /etc/ssl/certs/aea2.crt
SSLCertificateKeyFile   /etc/ssl/private/aea2.key

Desa i, tot seguit, activa el lloc i recarrega Apache:

bash — administrador → servidor (SSH)
sudo a2ensite default-ssl

➜ Activa el lloc HTTPS (default-ssl) a Apache.

bash — administrador → servidor (SSH)
sudo systemctl reload apache2

➜ Recarrega Apache perquè apliqui la nova configuració sense aturar el servei.

2.8 · Accedir al web des del client

Client

Ves a la màquina client, obre el navegador i escriu:

navegador — client
https://192.168.1.10

El navegador mostrarà un avís de seguretat (el certificat és autofirmat). Accepta'l per continuar (a Firefox: Avançat → Accepta el risc). Veuràs la pàgina per defecte d'Apache servida per HTTPS.

💡

Aquest avís és normal i esperat: no hem pagat cap autoritat de certificació. En una xarxa interna de pràctiques és perfectament vàlid.

Verificació

Administrador → Servidor · per SSH

Comprova que Apache està actiu i que escolta els ports 22 i 443:

bash — administrador → servidor (SSH)
systemctl status apache2
sudo ss -tlnp | grep -E ':(22|443)'

Sortida esperada de systemctl status apache2 (resumida):

sortida esperada
● apache2.service - The Apache HTTP Server
     Loaded: loaded (/lib/systemd/system/apache2.service; enabled; ...)
     Active: active (running) since ...   # ⚠ EL MÉS IMPORTANT
   Main PID: 1234 (apache2)
      Tasks: 55 (limit: ...)
     CGroup: /system.slice/apache2.service
             ├─1234 /usr/sbin/apache2 -k start
             ├─1235 /usr/sbin/apache2 -k start
             └─1236 /usr/sbin/apache2 -k start

Sortida esperada de ss -tlnp (una línia per port):

sortida esperada
LISTEN 0 128 0.0.0.0:22    0.0.0.0:*  users:(("sshd",pid=...,fd=3))     # port SSH
LISTEN 0 128 0.0.0.0:443   0.0.0.0:*  users:(("apache2",pid=1234,fd=6)) # port HTTPS
Administrador

Demana la pàgina per HTTPS (l'opció -k accepta el certificat autofirmat):

bash — administrador
curl -k https://192.168.1.10

Sortida esperada (el codi HTML de la pàgina que has creat al pas 4):

sortida esperada
<h1>El meu servidor segur · AEA2</h1>
💡

L'opció -k fa que curl accepti el certificat autofirmat sense donar l'error SSL certificate problem. Si l'ordre respon amb HTML (sense error de connexió), la verificació és correcta.

  • systemctl status apache2 mostra active (running).
  • ss mostra que el servidor escolta els ports 22 (SSH) i 443 (HTTPS).
  • curl -k retorna el codi HTML de la pàgina d'Apache.
  • El client veu la pàgina al navegador per https://192.168.1.10.
