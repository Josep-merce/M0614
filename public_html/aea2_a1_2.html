Publica el teu lloc web: host virtual, nom i contrasenya

Continuant amb el servidor de l'A1.1, ara hi publicaràs el teu propi lloc web amb un host virtual, li donaràs un nom perquè el client hi accedeixi (www.aea2.local) i el protegiràs amb usuari i contrasenya. Finalment faràs que l'HTTPS mostri aquest mateix lloc.

Branca aea2 RA RA2 CA 2.3 · 2.4 · 2.8
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Crear el teu propi lloc web i servir-lo (no la pàgina per defecte d'Apache).
  • Configurar un host virtual perquè Apache serveixi aquest lloc.
  • Fer que el client hi accedeixi pel nom (www.aea2.local) editant /etc/hosts.
  • Protegir el lloc amb usuari i contrasenya (autenticació bàsica).

Prerequisit important

⚠️

Aquesta activitat continua l'A1.1. Has de tenir les tres màquines a la xarxa interna, el servidor accessible per SSH i Apache instal·lat i funcionant. Si no ho tens, fes primer l'A1.1.

Branca de treball

bash
git switch aea2

➜ Et situa a la branca aea2, la mateixa de tota l'AEA (ja creada a l'A1.1).

1

Context i teoria mínima

Fins ara el servidor mostrava la pàgina per defecte d'Apache. Ara hi posaràs el teu lloc. Per fer-ho fem servir tres eines d'Apache i del sistema:

ConcepteQuè és
Host virtualConfiguració que li diu a Apache quin nom té un lloc i en quina carpeta són els seus fitxers (DocumentRoot). Permet tenir diversos llocs al mateix servidor.
DocumentRootLa carpeta on hi ha els fitxers del lloc (per exemple /var/www/aea2).
Resolució de nomsTraduir un nom (www.aea2.local) a una IP. Per a proves ho fem al fitxer /etc/hosts del client.
Autenticació bàsicaDemana usuari i contrasenya per entrar. La contrasenya es desa xifrada amb htpasswd. No xifra el trànsit: per això la combinem amb HTTPS.
💡

El nom acaba en .local perquè és un nom de proves intern; no és un domini real d'Internet. La "traducció" nom → IP la fem manualment a /etc/hosts.

2

Pas a pas guiat

💡

Cada pas ve dins d'una capsa de color que indica qui l'ha de fer: AdministradorServidorClient. Els fitxers de configuració no porten capsa.

Els passos 2.1 a 2.4 i el 2.6 es fan al servidor (pots entrar-hi per SSH des de l'administrador, com a l'A1.1). El pas 2.5 es fa al client.

2.1 · Crea la carpeta i la pàgina del teu lloc

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo mkdir /var/www/aea2

➜ Crea la carpeta on hi haurà els fitxers del teu lloc web.

Crea una pàgina d'inici senzilla dins d'aquesta carpeta:

bash — administrador → servidor (SSH)
echo "<h1>El meu servidor segur · AEA2</h1>" | sudo tee /var/www/aea2/index.html

➜ Escriu una pàgina d'inici dins la carpeta. La canonada | sudo tee desa el text al fitxer amb permisos d'administrador.

2.2 · Crea el host virtual

Administrador → Servidor · per SSH

Crea el fitxer de configuració del teu lloc:

bash — administrador → servidor (SSH)
sudo nano /etc/apache2/sites-available/aea2.conf

➜ Obre amb nano el fitxer on definirem el nostre lloc (host virtual).

Escriu-hi aquest contingut:

aea2.conf
<VirtualHost *:80>
    ServerName www.aea2.local
    DocumentRoot /var/www/aea2
</VirtualHost>

➜ Explicació de cada línia:

  • <VirtualHost *:80> → obre la definició d'un lloc web que escolta al port 80 (HTTP).
  • ServerName www.aea2.local → el nom pel qual s'accedirà al lloc.
  • DocumentRoot /var/www/aea2 → la carpeta on hi ha els fitxers del lloc.
  • </VirtualHost> → tanca la definició del lloc.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

2.3 · Activa el lloc

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo a2ensite aea2

➜ Activa el lloc aea2 a Apache (l'afegeix a sites-enabled).

bash — administrador → servidor (SSH)
sudo systemctl reload apache2

➜ Recarrega Apache perquè apliqui la nova configuració sense aturar el servei.

2.4 · Protegeix el lloc amb usuari i contrasenya

Administrador → Servidor · per SSH

Crea un usuari (aquí laura); et demanarà la contrasenya dues vegades:

bash — administrador → servidor (SSH)
sudo htpasswd -c /etc/apache2/.htpasswd laura

➜ Crea l'usuari laura i desa la seva contrasenya xifrada. -c crea el fitxer de contrasenyes (només s'usa el primer cop; després no).

Torna a obrir aea2.conf per afegir-hi el bloc <Directory> dins del <VirtualHost>:

bash — administrador → servidor (SSH)
sudo nano /etc/apache2/sites-available/aea2.conf

➜ Torna a obrir el fitxer del host virtual per afegir-hi la protecció amb contrasenya.

aea2.conf
<VirtualHost *:80>
    ServerName www.aea2.local
    DocumentRoot /var/www/aea2

    <Directory /var/www/aea2>
        AuthType Basic
        AuthName "Zona privada"
        AuthUserFile /etc/apache2/.htpasswd
        Require user laura
    </Directory>
</VirtualHost>

➜ Explicació de cada línia (les tres primeres i l'última ja les coneixes del pas anterior; les noves són les del bloc <Directory>):

  • <VirtualHost *:80> → obre la definició del lloc al port 80.
  • ServerName www.aea2.local → el nom pel qual s'accedeix al lloc.
  • DocumentRoot /var/www/aea2 → la carpeta amb els fitxers del lloc.
  • <Directory /var/www/aea2> → comença un bloc de regles per a aquesta carpeta.
  • AuthType Basic → tipus d'autenticació: usuari i contrasenya.
  • AuthName "Zona privada" → text que apareix a la finestra que demana les credencials.
  • AuthUserFile /etc/apache2/.htpasswd → fitxer on són desades les contrasenyes (el que has creat amb htpasswd).
  • Require user laura → només l'usuari laura pot entrar.
  • </Directory> → tanca el bloc de regles de la carpeta.
  • </VirtualHost> → tanca la definició del lloc.

Desa i recarrega Apache:

bash — administrador → servidor (SSH)
sudo systemctl reload apache2

➜ Recarrega Apache perquè el lloc quedi protegit amb usuari i contrasenya.

⚠️

L'autenticació bàsica no xifra el trànsit: la contrasenya viatjaria en clar per HTTP. Per això és important servir el lloc també per HTTPS (pas 2.6).

2.5 · Fes que el client accedeixi pel nom

Client

Ves a la màquina client i edita el fitxer /etc/hosts:

bash — client
sudo nano /etc/hosts

➜ Obre al client el fitxer que associa noms a adreces IP.

Afegeix aquesta línia al final (associa el nom a la IP del servidor):

/etc/hosts — client
192.168.1.10   www.aea2.local

➜ Associa el nom www.aea2.local a la IP del servidor, de manera que el client hi arribi pel nom.

Prova-ho al navegador del client: http://www.aea2.local. Ha de demanar usuari i contrasenya i, en encertar-los, mostrar el teu lloc.

2.6 · Fes que l'HTTPS mostri el teu lloc

Administrador → Servidor · per SSH

Edita la configuració SSL (la de l'A1.1) i canvia el DocumentRoot perquè apunti al teu lloc:

bash — administrador → servidor (SSH)
sudo nano /etc/apache2/sites-available/default-ssl.conf

➜ Obre la configuració del lloc HTTPS per canviar-hi el DocumentRoot.

default-ssl.conf
DocumentRoot /var/www/aea2

➜ Fa que la versió HTTPS del lloc mostri la mateixa carpeta que el teu host virtual (/var/www/aea2).

bash — administrador → servidor (SSH)
sudo systemctl reload apache2

➜ Recarrega Apache perquè l'HTTPS mostri el teu lloc propi.

Ara https://192.168.1.10 mostrarà el teu lloc, servit de forma segura.

3

Verificació

  • Al client, http://www.aea2.local demana usuari/contrasenya i, en encertar-los, mostra el teu lloc.
  • https://192.168.1.10 mostra el teu lloc per HTTPS.
Administrador

Comprovació ràpida des de l'administrador (l'opció -u envia l'usuari):

bash — administrador
curl -k -u laura https://192.168.1.10

➜ Demana la pàgina per HTTPS identificant-se com laura. -k accepta el certificat autofirmat i -u laura envia l'usuari (et demanarà la contrasenya).

Sortida esperada: primer et demana la contrasenya i, si l'encertes, el codi HTML de la pàgina:

sortida esperada
Enter host password for user 'laura':   # escriu la contrasenya i prem Enter
<h1>El meu servidor segur · AEA2</h1>
💡

Si la contrasenya és incorrecta, curl respon 401 Unauthorized en lloc del HTML. Si dona un error de connexió, revisa la taula d'Errors freqüents.
