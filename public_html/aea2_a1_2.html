Publica un lloc segur amb HTTPS

Crearàs un lloc web nou, www.segur.local, que només es serveix per HTTPS amb un certificat autofirmat. Després faràs que qui hi entri per HTTP sigui redirigit automàticament a la versió segura.

RA RA2 CA 2.1 · 2.2 · 2.5 · 2.6
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Explicar per què cal HTTPS i per què es redirigeix l'HTTP cap a l'HTTPS.
  • Activar el mòdul ssl d'Apache i generar un certificat autofirmat.
  • Crear un host virtual al port 443 per a un lloc nou (www.segur.local).
  • Configurar la redirecció HTTP → HTTPS i comprovar-la.

Prerequisit important

⚠️

Necessites la xarxa de l'A0 i Apache instal·lat al servidor (A1.1). Aquesta activitat crea un lloc nou: no toca el lloc ni la zona privada de l'A1.1.

Context i teoria mínima

Per què HTTPS?

Amb HTTP tot el que viatja entre el navegador i el servidor va en clar: qualsevol que estigui a la mateixa xarxa pot llegir les pàgines, els formularis i les contrasenyes. A l'A1.1, per exemple, la contrasenya de la zona privada viatjava sense xifrar.

HTTPS és HTTP dins d'un canal xifrat amb TLS (Transport Layer Security, "seguretat de la capa de transport"). TLS és el protocol que, abans d'enviar cap pàgina, fa que el navegador i el servidor es posin d'acord en una clau secreta i comprovin el certificat; a partir d'aquí, tot el que viatja entre tots dos va xifrat amb aquesta clau. És el successor de l'antic SSL: per això a Apache encara trobaràs noms com mod_ssl o SSLEngine, tot i que el que s'utilitza de debò és TLS. HTTPS aporta tres coses:

  • Confidencialitat → ningú pot llegir el que viatja.
  • Integritat → ningú pot canviar la pàgina pel camí sense que es noti.
  • Identitat → el certificat diu quin servidor és. Si el certificat l'ha signat una autoritat de confiança, el navegador s'ho creu; si és autofirmat (fet pel mateix servidor), xifra igual però el navegador mostra un avís.

Què és una autoritat de confiança?

Un certificat és com un DNI del servidor: diu "sóc www.segur.local". Però qualsevol pot fabricar-se un document que digui això. El que fa creïble un DNI és que l'ha emès la Policia, algú en qui tothom confia.

A Internet, aquest paper el fan les autoritats de certificació (en anglès Certificate Authorities): organitzacions com Let's Encrypt o DigiCert que comproven que el domini és realment teu i, aleshores, signen el teu certificat. Cada navegador porta de fàbrica una llista d'autoritats en què confia. Quan rep un certificat signat per una d'elles, mostra el cadenat sense queixar-se.

En aquesta activitat el certificat el signa el mateix servidor (per això es diu autofirmat). El xifrat funciona exactament igual, però el navegador no té manera de saber si el servidor és qui diu ser i per això mostra un avís. Per a una xarxa interna de pràctiques és perfecte; per a un web real a Internet faríem servir un certificat signat per una autoritat, per exemple el gratuït de Let's Encrypt.

Ampliar el servidor amb mòduls

Apache té un disseny modular: pots afegir o treure funcionalitats activant o desactivant mòduls. Els mòduls disponibles són a /etc/apache2/mods-available i els activats a /etc/apache2/mods-enabled. Per gestionar-los fem servir dues ordres:

  • sudo a2enmod <mòdul> → activa un mòdul (per exemple ssl, que ens caldrà per a l'HTTPS).
  • sudo a2dismod <mòdul> → desactiva un mòdul.

Després d'activar o desactivar un mòdul cal recarregar Apache perquè el canvi tingui efecte.

Pas a pas guiat

💡

Cada pas ve dins d'una capsa de color que indica qui l'ha de fer: AdministradorServidorClient. Els fitxers de configuració no porten capsa.

Part 1 · El lloc per HTTPS

2.1 · Connecta't al servidor per SSH

Administrador

Des de la màquina administrador, obre una sessió SSH al servidor amb l'usuari isard_ssh que vas crear a l'A0:

bash — administrador
ssh isard_ssh@192.168.1.10

➜ Obre una sessió de terminal xifrada al servidor per SSH.

💻→

A partir d'aquí, tot el que escrius s'executa al servidor, no a l'administrador. Per tornar a l'administrador quan acabis, escriu exit.

2.2 · Crea la carpeta i la pàgina del lloc segur

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo mkdir /var/www/segur

➜ Crea la carpeta on hi haurà els fitxers del lloc segur.

bash — administrador → servidor (SSH)
sudo nano /var/www/segur/index.html

➜ Crea la pàgina d'inici del lloc.

Escriu-hi aquest contingut:

index.html
<!DOCTYPE html>
<html lang="ca">
<head>
    <meta charset="UTF-8">
    <title>Lloc segur</title>
</head>
<body>
    <h1>Lloc segur · AEA2</h1>
    <p>Aquesta pàgina només es serveix per HTTPS.</p>
</body>
</html>

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

Encara no es pot veure: primer cal preparar l'HTTPS.

2.3 · Activa el mòdul SSL

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo a2enmod ssl

➜ Activa el mòdul ssl, que permet a Apache servir pàgines per HTTPS.

bash — administrador → servidor (SSH)
sudo systemctl restart apache2

➜ Reinicia Apache perquè carregui el mòdul nou.

2.4 · Genera el certificat autofirmat

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/segur.key \
  -out /etc/ssl/certs/segur.crt

➜ Genera el certificat i la clau. És una sola ordre (les barres \ uneixen les línies): -x509 crea un certificat autofirmat, -nodes no posa contrasenya a la clau i -days 365 el fa vàlid un any.

En executar-la, l'openssl et farà unes quantes preguntes (el subject del certificat). Pots respondre-les així:

preguntes del certificat
Country Name (2 letter code):    # país, 2 lletres → ES
State or Province Name:          # província → Barcelona
Locality Name (eg, city):        # ciutat → Barcelona
Organization Name:               # organització → Institut La Merce
Organizational Unit Name:        # departament (opcional) → DAW
Common Name:                     # ⚠ EL MÉS IMPORTANT: el nom del lloc → www.segur.local
Email Address:                   # correu (opcional) → pots deixar-ho buit
💡

El camp que de debò importa és el Common Name (CN): ha de coincidir amb l'adreça per la qual accediràs al servidor (aquí www.segur.local). La resta de camps són informatius i els pots deixar buits prement Enter.

2.5 · Crea el host virtual HTTPS

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo nano /etc/apache2/sites-available/segur.conf

➜ Crea el fitxer de configuració del lloc segur.

Escriu-hi aquest contingut:

segur.conf
<VirtualHost *:443>
    ServerName www.segur.local
    DocumentRoot /var/www/segur

    SSLEngine on
    SSLCertificateFile    /etc/ssl/certs/segur.crt
    SSLCertificateKeyFile /etc/ssl/private/segur.key
</VirtualHost>

➜ Explicació de cada línia:

  • <VirtualHost *:443> → aquest lloc escolta al port 443 (HTTPS), no al 80.
  • ServerName www.segur.local → el nom del lloc.
  • DocumentRoot /var/www/segur → la carpeta amb els fitxers del lloc.
  • SSLEngine on → activa el xifrat en aquest lloc.
  • SSLCertificateFile → el certificat que has generat al pas 2.4.
  • SSLCertificateKeyFile → la clau privada del certificat.
  • </VirtualHost> → tanca la definició del lloc.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

2.6 · Activa el lloc

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo a2ensite segur

➜ Activa el lloc segur a Apache.

bash — administrador → servidor (SSH)
sudo apache2ctl configtest

➜ Comprova que la configuració no té errors. Ha de dir Syntax OK (si també surt un avís AH00558, és normal).

bash — administrador → servidor (SSH)
sudo systemctl reload apache2

➜ Recarrega Apache perquè apliqui la configuració nova.

2.7 · Accedeix al lloc segur des del client

Client

Ves a la màquina client i afegeix el nom del lloc nou al fitxer /etc/hosts:

bash — client
sudo nano /etc/hosts

➜ Obre al client el fitxer que associa noms a adreces IP.

Afegeix aquesta línia al final:

/etc/hosts — client
192.168.1.10   www.segur.local

➜ Associa el nom www.segur.local a la IP del servidor.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

🔎 Comprova-ho al navegador del client https://www.segur.local

El navegador mostrarà un avís de seguretat perquè el certificat és autofirmat. Accepta'l (a Firefox: Avançat → Accepta el risc). Ha de sortir Lloc segur · AEA2. Clica el cadenat de la barra d'adreces i mira el certificat: el nom ha de ser www.segur.local.

🔎 Comprova-ho al navegador del client http://www.segur.local

Ara prova-ho sense la s. No surt el teu lloc segur: surt una altra pàgina (la per defecte d'Apache), servida en clar. Per HTTP el lloc segur no existeix. Això és el que arreglarem a la part 2.

Part 2 · Redirecció HTTP → HTTPS

Per què redirigir HTTP → HTTPS?

Quasi ningú escriu https:// a la barra d'adreces: escriu www.segur.local i el navegador prova primer per HTTP (port 80). Si el servidor només escolta pel 443, l'usuari no troba el lloc o, pitjor, troba una altra pàgina sense xifrar.

La solució és que el port 80 no serveixi cap contingut: només respon "ves a la versió https". Aquesta resposta és el codi 301 Moved Permanently, i el navegador hi va automàticament. Així l'usuari sempre acaba al lloc xifrat sense haver de fer res.

2.8 · Redirigeix el port 80 cap a l'HTTPS

Administrador → Servidor · per SSH

Torna a obrir la configuració del lloc segur:

bash — administrador → servidor (SSH)
sudo nano /etc/apache2/sites-available/segur.conf

➜ Obre el fitxer del host virtual per afegir-hi la redirecció.

Afegeix el bloc del port 80 a dalt de tot, abans del bloc del 443. El fitxer ha de quedar així:

segur.conf
<VirtualHost *:80>
    ServerName www.segur.local
    Redirect permanent / https://www.segur.local/
</VirtualHost>

<VirtualHost *:443>
    ServerName www.segur.local
    DocumentRoot /var/www/segur

    SSLEngine on
    SSLCertificateFile    /etc/ssl/certs/segur.crt
    SSLCertificateKeyFile /etc/ssl/private/segur.key
</VirtualHost>

➜ Explicació del bloc nou:

  • <VirtualHost *:80> → un segon lloc, ara al port 80 (HTTP), amb el mateix nom.
  • Redirect permanent / https://www.segur.local/ → a qualsevol petició li respon 301 amb l'adreça https. No té DocumentRoot perquè no serveix cap pàgina: només redirigeix.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

bash — administrador → servidor (SSH)
sudo apache2ctl configtest

➜ Comprova que no t'has equivocat. Ha de dir Syntax OK.

bash — administrador → servidor (SSH)
sudo systemctl reload apache2

➜ Recarrega Apache perquè apliqui la redirecció.

🔎 Comprova-ho al navegador del client http://www.segur.local

Escriu l'adreça amb http i prem Ctrl+F5. Fixa't en la barra d'adreces: canvia sola a https://www.segur.local i surt el teu lloc segur.

Verificació

  • https://www.segur.local mostra el lloc segur amb el certificat www.segur.local.
  • http://www.segur.local salta automàticament a https://www.segur.local.
  • El servidor escolta els ports 80 i 443.
Administrador → Servidor · per SSH

Comprova que Apache escolta els ports 80 (HTTP) i 443 (HTTPS):

bash — administrador → servidor (SSH)
sudo ss -tlnp | grep -E ':(80|443)'

➜ Llista els ports on escolta el servidor i filtra els que ens interessen.

Sortida esperada:

sortida esperada
LISTEN 0 511  *:80    *:*  users:(("apache2",pid=1234,fd=4))   # HTTP → redirecció
LISTEN 0 511  *:443   *:*  users:(("apache2",pid=1234,fd=6))   # HTTPS
Client

Comprova la redirecció. L'opció -I mostra només la capçalera de la resposta:

bash — client
curl -I http://www.segur.local

➜ Demana la pàgina per HTTP i mostra què respon el servidor.

Sortida esperada:

sortida esperada
HTTP/1.1 301 Moved Permanently                 # ⚠ EL MÉS IMPORTANT: redirecció
Server: Apache/2.4.62 (Debian)
Location: https://www.segur.local/            # on et fa anar

Ara demana la pàgina per HTTPS:

bash — client
curl -k https://www.segur.local

➜ -k accepta el certificat autofirmat. Ha de retornar el codi HTML del lloc segur, on hi ha <h1>Lloc segur · AEA2</h1>.
