El mateix servidor segur amb Docker

Muntaràs el mateix lloc de l'A1.2, www.segur.local, servit només per HTTPS amb un certificat autofirmat i amb redirecció automàtica de l'HTTP cap a l'HTTPS. Aquesta vegada Apache s'executa dins d'un contenidor amb la imatge oficial, sense modificar-la: la configuració, el certificat i la pàgina li arriben des de la teva carpeta amb volums, i ho engegues tot amb Docker Compose.

RA RA2 CA 2.1 · 2.2 · 2.5 · 2.6 · 2.9
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Trobar i fer servir la imatge oficial d'Apache (httpd) des del terminal.
  • Escriure un httpd.conf mínim que activa el mòdul ssl, entenent cada línia.
  • Crear el host virtual al port 443 per a www.segur.local, igual que a l'A1.2.
  • Passar els teus fitxers al contenidor amb volums i engegar-lo amb Docker Compose.
  • Configurar la redirecció HTTP → HTTPS i aplicar el canvi reiniciant el contenidor.

Prerequisits

  • Docker i Docker Compose instal·lats i funcionant, i saber la diferència entre imatge i contenidor (AEA0).
  • Haver fet l'A1.2: aquí no es torna a explicar què és HTTPS, un certificat o una redirecció 301.
💡

Aquí no fem servir la xarxa de tres màquines. El servidor és un contenidor a la teva pròpia màquina i el proves amb el navegador de la mateixa màquina.

1

Context i teoria mínima

El mateix, però en un contenidor

A l'A1.2 vas configurar Apache "a mà" dins d'un servidor Debian. Ara farem servir la imatge oficial httpd:2.4 tal com ve de Docker Hub: ja porta Apache instal·lat, els seus mòduls i una pàgina de prova, It works!.

La imatge oficial no és un Debian amb Apache: no té a2enmod, a2ensite ni systemctl. Tota la configuració és en un fitxer, /usr/local/apache2/conf/httpd.conf. En lloc de canviar la imatge, escriurem el nostre propi httpd.conf i li direm al contenidor que faci servir el nostre.

Volums: els fitxers es queden a la teva carpeta

Un volum connecta un fitxer o una carpeta de la teva màquina amb una ruta de dins del contenidor. El contenidor no en té una còpia: llegeix directament el teu fitxer. Per això, si edites el segur.conf de la teva carpeta, n'hi ha prou amb reiniciar el contenidor perquè Apache el torni a llegir, igual que fèiem amb systemctl reload.

Per no haver d'escriure una ordre docker run llarguíssima amb tots els ports i volums, ho escrivim un sol cop en un fitxer, el compose.yaml, i engeguem amb docker compose up.

Pas a pas guiat

Tots els passos es fan a la mateixa màquina, la que té Docker: Màquina Docker. Els fitxers de configuració no porten capsa.

Part 1 · El lloc per HTTPS

2.1 · Comprova Docker i busca la imatge d'Apache

Màquina Docker
bash — màquina Docker
docker --version

➜ Mostra la versió de Docker instal·lada; així comproves que funciona.

bash — màquina Docker
docker compose version

➜ Mostra la versió de Docker Compose. Fixa't que s'escriu docker compose, amb espai.

bash — màquina Docker
docker search httpd --limit 5

➜ Busca a Docker Hub les imatges que es diuen httpd. La bona és la que té [OK] a la columna OFFICIAL: és la imatge oficial d'Apache.

bash — màquina Docker
docker pull httpd:2.4

➜ Descarrega la imatge oficial d'Apache, versió 2.4. És el nostre apt install apache2.

2.2 · Crea la carpeta del projecte

Màquina Docker
bash — màquina Docker
mkdir -p segur-docker/web segur-docker/certs segur-docker/extra

➜ Crea la carpeta del projecte amb tres subcarpetes: web/ per a la pàgina, certs/ per al certificat i extra/ per al host virtual. -p crea també la carpeta pare.

bash — màquina Docker
cd segur-docker

➜ Entra dins la carpeta del projecte. Tots els passos següents es fan des d'aquí.

2.3 · Crea la pàgina del lloc segur

Màquina Docker
bash — màquina Docker
nano web/index.html

➜ Crea la pàgina d'inici del lloc.

Escriu-hi aquest contingut (el mateix de l'A1.2):

web/index.html
<!DOCTYPE html>
<html lang="ca">
<head>
    <meta charset="UTF-8">
    <title>Lloc segur</title>
</head>
<body>
    <h1>Lloc segur · AEA2</h1>
    <p>Aquesta pàgina només es serveix per HTTPS.</p>
</body>
</html>

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

2.4 · Genera el certificat autofirmat

Màquina Docker
bash — màquina Docker
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout certs/segur.key \
  -out certs/segur.crt

➜ Genera el certificat i la clau dins certs/. És una sola ordre (les barres \ uneixen les línies): -x509 crea un certificat autofirmat, -nodes no posa contrasenya a la clau i -days 365 el fa vàlid un any. No cal sudo: els fitxers són a la teva carpeta.

En executar-la, l'openssl et farà unes quantes preguntes (el subject del certificat). Pots respondre-les així:

preguntes del certificat
Country Name (2 letter code):    # país, 2 lletres → ES
State or Province Name:          # província → Barcelona
Locality Name (eg, city):        # ciutat → Barcelona
Organization Name:               # organització → Institut La Merce
Organizational Unit Name:        # departament (opcional) → DAW
Common Name:                     # ⚠ EL MÉS IMPORTANT: el nom del lloc → www.segur.local
Email Address:                   # correu (opcional) → pots deixar-ho buit
💡

El camp que de debò importa és el Common Name (CN): ha de coincidir amb l'adreça per la qual accediràs al servidor (aquí www.segur.local, com a l'A1.2). La resta de camps són informatius i els pots deixar buits prement Enter.

2.5 · Escriu el httpd.conf

Màquina Docker
bash — màquina Docker
nano httpd.conf

➜ Crea la configuració general d'Apache, a l'arrel de segur-docker/.

Escriu-hi aquest contingut. Les línies que comencen amb # són comentaris: Apache no les llegeix.

httpd.conf
# On és Apache dins la imatge, nom del servidor i port HTTP
ServerRoot "/usr/local/apache2"
ServerName localhost
Listen 80

# Mòduls que activem
LoadModule mpm_event_module     modules/mod_mpm_event.so
LoadModule unixd_module         modules/mod_unixd.so
LoadModule authz_core_module    modules/mod_authz_core.so
LoadModule dir_module           modules/mod_dir.so
LoadModule mime_module          modules/mod_mime.so
LoadModule log_config_module    modules/mod_log_config.so
LoadModule alias_module         modules/mod_alias.so
LoadModule ssl_module           modules/mod_ssl.so
LoadModule socache_shmcb_module modules/mod_socache_shmcb.so

# Usuari amb què funciona Apache
User daemon
Group daemon

# Lloc per defecte (la pàgina It works! de la imatge)
DocumentRoot "/usr/local/apache2/htdocs"
<Directory "/usr/local/apache2/htdocs">
    Require all granted
</Directory>
DirectoryIndex index.html
TypesConfig conf/mime.types

# Registres: a la sortida del contenidor
ErrorLog /proc/self/fd/2
LogFormat "%h %t \"%r\" %>s" senzill
CustomLog /proc/self/fd/1 senzill

# Els nostres llocs
Include conf/extra/segur.conf

➜ Explicació de cada bloc:

  • ServerRoot → on és Apache dins la imatge. Les rutes relatives, com modules/… o conf/…, parteixen d'aquí.
  • ServerName localhost → el nom general del servidor. Gràcies a aquesta línia no surt l'avís AH00558.
  • Listen 80 → Apache escolta al port 80 del contenidor (HTTP).
  • LoadModule → cada línia activa una peça d'Apache: el motor (mpm_event, unixd), els permisos (authz_core, que fa funcionar Require), la pàgina d'índex (dir), els tipus de fitxer (mime), els registres (log_config) i la redirecció (alias, que fa funcionar Redirect). Les dues últimes, ssl i socache_shmcb, són el nostre a2enmod ssl.
  • User daemon i Group daemon → Apache funciona amb un usuari sense privilegis, no com a root.
  • DocumentRoot i <Directory> → el lloc per defecte és la carpeta htdocs de la imatge, on hi ha la pàgina It works!, i Require all granted permet llegir-la. Aquest permís també cobreix htdocs/segur/, on muntarem la nostra pàgina.
  • DirectoryIndex i TypesConfig → quina pàgina s'obre per defecte i on és la llista de tipus de fitxer (la porta la imatge).
  • ErrorLog, LogFormat i CustomLog → envien els errors i els accessos a la sortida del contenidor, perquè els puguis veure amb docker compose logs.
  • Include conf/extra/segur.conf → fa que Apache llegeixi el nostre host virtual. És el nostre a2ensite segur.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

2.6 · Crea el host virtual HTTPS

Màquina Docker
bash — màquina Docker
nano extra/segur.conf

➜ Crea el fitxer del lloc segur dins extra/. Fa el mateix paper que sites-available/segur.conf a l'A1.2.

Escriu-hi aquest contingut:

extra/segur.conf
Listen 443

<VirtualHost *:443>
    ServerName www.segur.local
    DocumentRoot /usr/local/apache2/htdocs/segur

    SSLEngine on
    SSLCertificateFile    /usr/local/apache2/conf/certs/segur.crt
    SSLCertificateKeyFile /usr/local/apache2/conf/certs/segur.key
</VirtualHost>

➜ És el mateix host virtual de l'A1.2. Només canvien les rutes, que són les de dins del contenidor (on muntarem les carpetes al pas 2.7):

  • Listen 443 → fa que Apache escolti també al port 443. A Debian això ja ho feia a2enmod ssl; aquí ho escrivim nosaltres.
  • <VirtualHost *:443> → aquest lloc escolta al port 443 (HTTPS).
  • ServerName www.segur.local → el nom del lloc.
  • DocumentRoot /usr/local/apache2/htdocs/segur → on veurà el contenidor la teva carpeta web/.
  • SSLEngine on → activa el xifrat en aquest lloc.
  • SSLCertificateFile i SSLCertificateKeyFile → on veurà el contenidor el certificat i la clau privada de la teva carpeta certs/.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

2.7 · Escriu el compose.yaml

Màquina Docker
bash — màquina Docker
nano compose.yaml

➜ Crea el fitxer que descriu el contenidor, a l'arrel de segur-docker/.

Escriu-hi aquest contingut. Compte amb els espais: en YAML el sagnat compta, i s'han de fer servir espais, mai tabuladors.

compose.yaml
services:
  web:
    image: httpd:2.4
    container_name: servidor-segur
    ports:
      - "8080:80"
      - "8443:443"
    volumes:
      - ./httpd.conf:/usr/local/apache2/conf/httpd.conf:ro
      - ./extra:/usr/local/apache2/conf/extra:ro
      - ./certs:/usr/local/apache2/conf/certs:ro
      - ./web:/usr/local/apache2/htdocs/segur:ro

➜ Explicació de cada línia:

  • services: → comença la llista de contenidors. Només en tenim un, web.
  • image: httpd:2.4 → fa servir la imatge oficial tal com ve.
  • container_name: servidor-segur → el nom del contenidor (el veuràs a docker ps).
  • ports: → 8080:80 publica l'HTTP al port 8080 de la teva màquina i 8443:443 publica l'HTTPS al 8443.
  • volumes: → cada línia és fitxer-o-carpeta-teva:ruta-dins-del-contenidor:ro:
    • ./httpd.conf → substitueix el httpd.conf de la imatge pel teu.
    • ./extra → la carpeta on hi ha el segur.conf.
    • ./certs → el certificat i la clau.
    • ./web → la pàgina del lloc segur.
    • :ro → el contenidor només pot llegir els teus fitxers, no modificar-los.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

2.8 · Comprova la configuració i engega el contenidor

Màquina Docker
bash — màquina Docker
docker compose run --rm web httpd -t

➜ Crea un contenidor de prova, amb els mateixos volums, que només comprova la configuració d'Apache i després s'esborra sol (--rm). Ha de dir Syntax OK. És l'equivalent de apache2ctl configtest, abans d'engegar res.

bash — màquina Docker
docker compose up -d

➜ Llegeix el compose.yaml, crea el contenidor servidor-segur i l'engega en segon pla (-d).

2.9 · Accedeix al lloc segur

Màquina Docker

Afegeix el nom del lloc al fitxer /etc/hosts de la teva màquina:

bash — màquina Docker
sudo nano /etc/hosts

➜ Obre el fitxer que associa noms a adreces IP. Cal sudo perquè és un fitxer del sistema.

Afegeix aquesta línia al final:

/etc/hosts
127.0.0.1   www.segur.local

➜ Associa el nom www.segur.local a la teva pròpia màquina, on hi ha el contenidor.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

🔎 Comprova-ho al navegador https://www.segur.local:8443

El navegador mostrarà un avís de seguretat perquè el certificat és autofirmat. Accepta'l (a Firefox: Avançat → Accepta el risc). Ha de sortir Lloc segur · AEA2. Clica el cadenat de la barra d'adreces i mira el certificat: el nom ha de ser www.segur.local.

🔎 Comprova-ho al navegador http://www.segur.local:8080

Ara prova-ho sense la s i pel port 8080. No surt el teu lloc segur: surt It works!, la pàgina per defecte de la imatge httpd, servida en clar. Per HTTP el lloc segur no existeix. Això és el que arreglarem a la part 2.

Part 2 · Redirecció HTTP → HTTPS

Com a l'A1.2, el port de l'HTTP no ha de servir cap contingut: només ha de respondre 301 Moved Permanently amb l'adreça https, i el navegador hi va sol. L'única diferència és que aquí l'adreça de destinació porta el port publicat, 8443.

2.10 · Afegeix la redirecció al segur.conf

Màquina Docker
bash — màquina Docker
nano extra/segur.conf

➜ Torna a obrir la configuració del lloc segur per afegir-hi la redirecció.

Afegeix el bloc del port 80 entre la línia Listen 443 i el bloc del 443. El fitxer ha de quedar així:

extra/segur.conf
Listen 443

<VirtualHost *:80>
    ServerName www.segur.local
    Redirect permanent / https://www.segur.local:8443/
</VirtualHost>

<VirtualHost *:443>
    ServerName www.segur.local
    DocumentRoot /usr/local/apache2/htdocs/segur

    SSLEngine on
    SSLCertificateFile    /usr/local/apache2/conf/certs/segur.crt
    SSLCertificateKeyFile /usr/local/apache2/conf/certs/segur.key
</VirtualHost>

➜ Explicació del bloc nou:

  • <VirtualHost *:80> → un segon lloc, ara al port 80 del contenidor (el 8080 de la teva màquina), amb el mateix nom.
  • Redirect permanent / https://www.segur.local:8443/ → a qualsevol petició li respon 301 amb l'adreça https. Hi posem :8443 perquè és el port pel qual el navegador arriba a l'HTTPS del contenidor. No té DocumentRoot perquè no serveix cap pàgina: només redirigeix.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

2.11 · Comprova i aplica el canvi

💡

El contenidor llegeix el segur.conf directament de la teva carpeta (és un volum), així que ja veu el fitxer nou. Però Apache només llegeix la configuració quan arrenca: cal reiniciar el contenidor, igual que a l'A1.2 calia recarregar Apache.

Màquina Docker
bash — màquina Docker
docker compose exec web httpd -t

➜ Executa dins del contenidor la comprovació de la configuració d'Apache. Ha de dir Syntax OK. És l'equivalent de apache2ctl configtest.

bash — màquina Docker
docker compose restart

➜ Reinicia el contenidor perquè Apache torni a llegir la configuració. És el nostre systemctl reload apache2.

🔎 Comprova-ho al navegador http://www.segur.local:8080

Escriu l'adreça amb http i prem Ctrl+F5. Fixa't en la barra d'adreces: canvia sola a https://www.segur.local:8443 i surt el teu lloc segur.

Verificació

  • https://www.segur.local:8443 mostra el lloc segur amb el certificat www.segur.local.
  • http://www.segur.local:8080 salta automàticament a https://www.segur.local:8443.
  • El contenidor servidor-segur està en marxa i publica els ports 8080 i 8443.
Màquina Docker

Comprova que el contenidor funciona i quins ports publica:

bash — màquina Docker
docker compose ps

➜ Llista els contenidors del compose.yaml i el seu estat.

Sortida esperada (resumida):

sortida esperada

servidor-segur   httpd:2.4   web       Up 2 minutes   0.0.0.0:8080->80/tcp, 0.0.0.0:8443->443/tcp   # ⚠ EL MÉS IMPORTANT

Comprova la redirecció. L'opció -I mostra només la capçalera de la resposta:

bash — màquina Docker
curl -I http://www.segur.local:8080

Sortida esperada:

sortida esperada

Ara demana la pàgina per HTTPS:

bash — màquina Docker

➜ -k accepta el certificat autofirmat. Ha de retornar el codi HTML del lloc segur, on hi ha <h1>Lloc segur · AEA2</h1>.

Per acabar, mira els registres del contenidor:

bash — màquina Docker
docker compose logs

➜ Mostra el que ha escrit Apache: hi has de veure les teves peticions, amb un 301 per a les de HTTP i un 200 per a les de HTTPS.
