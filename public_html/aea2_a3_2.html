HTTPS amb certificat de confiança: S3 + CloudFront

A l'A3.1 vas posar HTTPS amb un certificat fet per tu i el navegador en desconfiava. Ara publicaràs el web en un bucket S3 i hi posaràs al davant CloudFront, que el servirà per HTTPS amb un certificat de confiança, sense cap avís de seguretat.

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Publicar una web estàtica en un bucket S3.
  • Entendre què és una CDN i què fa CloudFront.
  • Crear una distribució de CloudFront que serveixi el web per HTTPS i redirigeixi HTTP a HTTPS.
  • Diferenciar un certificat autofirmat (A3.1) d'un certificat de confiança.

Prerequisits

  • Accés a AWS Academy · Learner Lab (AEA0).
  • Un terminal a la teva màquina per fer curl.
  • Recomanat: haver fet l'A3.1, per poder comparar els dos certificats.
⚠️

El Learner Lab té temps limitat. Crear la distribució de CloudFront triga uns minuts: comença l'activitat amb temps i fes les captures a mesura que avances.

1

Context i teoria mínima

El problema: S3 només parla HTTP

Amazon S3 és el servei d'AWS per emmagatzemar fitxers. Té una opció, l'allotjament de lloc web estàtic, que fa que serveixi els teus HTML com una web, sense haver de muntar cap servidor. Però l'adreça que et dona (l'endpoint del lloc web) només funciona amb http://: no té certificat i no accepta HTTPS.

La solució: CloudFront

Amazon CloudFront és la CDN (Content Delivery Network, xarxa de distribució de continguts) d'AWS. AWS té centenars de servidors repartits pel món, anomenats edge locations (n'hi ha a Madrid, a Barcelona, a París…). CloudFront es posa davant del teu bucket i atén ell les peticions dels usuaris:

  1. El navegador es connecta per HTTPS a l'edge location més propera.
  2. Si aquell servidor ja té una còpia de la pàgina a la memòria cau (cache), la serveix al moment.
  3. Si no la té, la demana al bucket S3 (l'origen), la serveix a l'usuari i se'n guarda una còpia per a les properes peticions.
💡

CloudFront és un proxy invers amb memòria cau. Un proxy directe és al costat del client (com el proxy de l'institut per on surt la xarxa de l'aula). Un proxy invers és al costat del servidor: rep les peticions en nom seu i les hi reenvia. L'usuari creu que parla amb el servidor, però parla amb el proxy.

És el mateix que faries posant un Apache o un Nginx davant d'una aplicació, però gestionat per AWS i repetit a centenars de llocs del món.

Autofirmat o de confiança?

Totes dues opcions xifren la connexió igual de bé. La diferència és qui signa el certificat i, per tant, si el navegador se'n refia.

Conceptes

BucketUna "carpeta" a S3. El nom ha de ser únic a tot AWS.
Allotjament de lloc web estàticOpció del bucket que fa que els HTML es vegin com una pàgina web (només per HTTP).
DistribucióLa configuració de CloudFront per a un lloc web: d'on treu els fitxers i com els serveix.
OrigenEl servidor on hi ha els fitxers originals. Aquí, el teu bucket S3.
Edge locationCada un dels servidors de CloudFront repartits pel món.

Pas a pas guiat

2.1 · Entrar al Learner Lab i obrir la consola

  1. Entra a AWS Academy i obre el teu Learner Lab.
  2. Prem Start Lab i espera que el punt del costat d'AWS es posi verd.
  3. Fes clic a AWS per obrir la consola d'AWS.

2.2 · Crear el bucket S3

  1. A la consola, cerca S3 i entra-hi. Prem Create bucket.
  2. Posa-li un nom únic, per exemple aea2-nomcognom-2026. Només minúscules, números i guions: sense majúscules, espais, accents, ñ ni ç (Núria Muñoz → aea2-nuriamunoz-2026).
  3. Desmarca Block all public access i marca la casella de confirmació que apareix a sota.
  4. Prem Create bucket.

2.3 · Activar l'allotjament de lloc web estàtic

  1. Entra al bucket i ves a la pestanya Properties.
  2. Baixa fins a Static website hosting i prem Edit.
  3. Marca Enable i escriu index.html a Index document.
  4. Desa i apunta l'adreça de Bucket website endpoint.

2.4 · Crear i pujar l'index.html

A la teva màquina, crea amb VS Code un fitxer anomenat exactament index.html, posant-hi el teu nom:

index.html
<!DOCTYPE html>
<html lang="ca">
<head>
  <meta charset="UTF-8">
  <title>Lloc segur a AWS — AEA2</title>
</head>
<body>
  <h1>Lloc segur a AWS — AEA2</h1>
  <p>Nom Cognom</p>
  <p>Servit per CloudFront amb HTTPS.</p>
</body>
</html>
  1. Al bucket, a la pestanya Objects, prem Upload.
  2. Add files → tria el teu index.html → Upload.

2.5 · Fer públic el contingut del bucket

  1. Ves a la pestanya Permissions del bucket.
  2. A Bucket policy, prem Edit i enganxa-hi això (canviant NOM-DEL-TEU-BUCKET):
bucket policy — JSON
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AccesPublicLectura",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::NOM-DEL-TEU-BUCKET/*"
    }
  ]
}

➜ Permet que qualsevol ("Principal": "*") pugui llegir (s3:GetObject) els fitxers del bucket. Desa amb Save changes.

🔎 Comprova-ho al navegador http://NOM-DEL-TEU-BUCKET.s3-website-us-east-1.amazonaws.com

Obre l'endpoint que has apuntat al pas 2.3. Ha de sortir la teva pàgina. Ara prova la mateixa adreça canviant http per https: no carregarà. Aquest és el problema que resoldrem amb CloudFront.

2.6 · Crear la distribució de CloudFront

  1. A la consola, cerca CloudFront i entra-hi. Prem Create distribution.
  2. Si et demana triar un pla de preus, tria Free.
  3. Posa-li de nom aea2-nomcognom.
⚠️

No triïs mai un pla de pagament (Pro, Business…). Si la consola no et deixa continuar amb el pla Free, avisa el professorat.

2.7 · Triar l'origen: el teu bucket

  1. A Origin type, tria Amazon S3.
  2. Prem Browse S3 i selecciona el teu bucket aea2-nomcognom-2026.
  3. Com que el bucket té l'allotjament web activat, la consola et proposarà fer servir l'endpoint del lloc web (Use website endpoint). Accepta-ho. L'origen ha de quedar com …s3-website-us-east-1.amazonaws.com.
💡

Fixa't que l'origen és la mateixa adreça http:// que has provat al pas 2.5. CloudFront parlarà amb el bucket per HTTP, però amb els usuaris parlarà per HTTPS.

2.8 · Configurar HTTPS i crear la distribució

Abans de crear-la, revisa aquests tres valors (segons la versió de la consola, alguns ja surten per defecte):

OpcióValorPer a què
Viewer protocol policyRedirect HTTP to HTTPSQui entri per http:// és enviat automàticament a https://.
Default root objectindex.htmlQue l'arrel (/) mostri la teva pàgina.
Security / WAFDo not enableEl tallafoc web (WAF) té cost i no el necessitem.

Prem Create distribution.

💡

Si durant l'assistent no t'ha sortit el Default root object, un cop creada la distribució ves a la pestanya General → Settings → Edit, escriu-hi index.html i desa.

2.9 · Esperar el desplegament

  1. Ves a la llista de distribucions. La teva sortirà amb l'estat Deploying: CloudFront està copiant la configuració a totes les edge locations. Pot trigar entre 5 i 15 minuts.
  2. Quan a Last modified surti una data (en lloc de Deploying), la distribució ja està llesta.
  3. Copia el Distribution domain name: és l'adreça del teu web, del tipus dXXXXXXXXXXXX.cloudfront.net.

2.10 · Accedir al web per HTTPS

🔎 Comprova-ho al navegador https://dXXXXXXXXXXXX.cloudfront.net

Ha de sortir la teva pàgina amb el cadenat i sense cap avís de seguretat, a diferència de l'A3.1. Clica el cadenat i mira el certificat: és vàlid per a *.cloudfront.net i l'emissor és Amazon, no tu.

🔎 Comprova-ho al navegador http://dXXXXXXXXXXXX.cloudfront.net

Escriu ara l'adreça sense la s. El navegador ha de saltar sol a https://: és la redirecció que has configurat al pas 2.8.

⚠️

Fer End Lab no atura CloudFront ni esborra el bucket. Quan el professorat t'ho indiqui en acabar l'AEA, ves a CloudFront, selecciona la distribució, prem Disable, espera que es desactivi i prem Delete.

3

Verificació

Des del terminal de la teva màquina, demana només les capçaleres de la resposta (-I), ara sense -k:

bash
curl -I https://dXXXXXXXXXXXX.cloudfront.net

➜ Fa una petició HTTPS a CloudFront i mostra només les capçaleres. No cal -k: el certificat és de confiança i curl l'accepta sense queixar-se.

Sortida esperada (resumida):

sortida esperada
HTTP/2 200                                     # ⚠ EL MÉS IMPORTANT: la pàgina s'ha servit bé
content-type: text/html
server: AmazonS3                               # el fitxer ve del bucket
x-cache: Miss from cloudfront                  # no era a la cache: l'ha anat a buscar a S3
via: 1.1 xxxxxxxx.cloudfront.net (CloudFront)  # ha passat pel proxy
x-amz-cf-pop: MAD53-P1                         # l'edge location que t'ha atès (MAD = Madrid)

Repeteix exactament la mateixa ordre:

bash
curl -I https://dXXXXXXXXXXXX.cloudfront.net

➜ Torna a demanar la pàgina. Aquest cop l'edge location ja en té una còpia.

sortida esperada
HTTP/2 200
x-cache: Hit from cloudfront                   # ⚠ ara s'ha servit des de la memòria cau
💡

Si ja havies obert la pàgina al navegador, és possible que surti Hit des de la primera vegada: la còpia ja era a la cache. El codi del x-amz-cf-pop pot ser un altre (per exemple, BCN), segons l'edge location que t'atengui.

Comprova ara la redirecció d'HTTP a HTTPS:

bash
curl -I http://dXXXXXXXXXXXX.cloudfront.net

➜ Fa la petició per HTTP, sense xifrar. CloudFront no serveix la pàgina: respon que vagis a l'adreça HTTPS.

sortida esperada
HTTP/1.1 301 Moved Permanently                       # ⚠ redirecció permanent
Server: CloudFront
Location: https://dXXXXXXXXXXXX.cloudfront.net/      # cap a on t'envia
  • L'endpoint del bucket funciona per http:// però no per https://.
  • La distribució de CloudFront està creada i ja no surt Deploying.
  • El navegador obre https://dXXXXXXXXXXXX.cloudfront.net amb el cadenat i sense cap avís.
  • curl -I sense -k retorna HTTP/2 200 i, en repetir-lo, x-cache: Hit from cloudfront.
  • curl -I http://… retorna 301 cap a https://.
