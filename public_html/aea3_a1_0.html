Prepara les quatre màquines: noms, IP fixes i SSH

Muntaràs l'escenari de l'AEA3: quatre màquines (client, administrador, apache i tomcat) connectades per una xarxa interna amb IP fixes, i l'accés per SSH als dos servidors.

RA RA3 Activitat de preparació 4 màquines
0

Què faràs

  • Posar un nom a cada màquina perquè sàpigues sempre on ets.
  • Posar una IP fixa a la targeta interna de cada màquina.
  • Instal·lar SSH a apache i a tomcat i entrar-hi des de l'administrador.

Què necessites

  • Quatre màquines Ubuntu 26.04 a IsardVDI, cadascuna amb dues targetes de xarxa: default (Internet) i interna.
  • Saber fer servir sudo i nano (AEA2).
1

Les quatre màquines

A l'AEA2 Apache i el web eren a la mateixa màquina. Ara farem com a les empreses: cada servidor a la seva màquina.

Pas a pas

💡

Cada pas ve dins d'una capsa de color que diu a quina màquina l'has de fer: ClientAdministradorApacheTomcatDiverses màquines.

2.1 · Posa nom a cada màquina

Totes les màquines · cadascuna amb el seu nom

Totes les màquines d'IsardVDI es diuen igual (isardvdi) i és fàcil equivocar-se. Posa a cada una el seu nom de la taula: client, admin, apache o tomcat. Exemple per a la màquina apache:

bash
sudo hostnamectl set-hostname apache

➜ Canvia el nom de la màquina a apache.

bash
sudo nano /etc/hosts

➜ Obre la llista de noms de la màquina. Busca la línia que comença per 127.0.1.1 i canvia el nom antic pel nou:

/etc/hosts
127.0.1.1   apache        # abans hi deia isardvdi

Desa (Ctrl+O, Enter) i surt (Ctrl+X). Tanca el terminal i obre'n un de nou: el prompt ja dirà isard@apache.

2.2 · Posa la IP fixa a la targeta interna

Totes les màquines · exemple: apache
bash
cd /etc/netplan

➜ Entra a la carpeta de configuració de xarxa d'Ubuntu (Netplan).

bash
sudo nano 99-isardvdi-conf.yaml

➜ Obre el fitxer de xarxa que crea IsardVDI. Ara posa les dues targetes amb DHCP.

Deixa enp1s0 tal com està i canvia el bloc d'enp2s0 perquè quedi així. Posa la IP de la teva màquina (apache .10, tomcat .11, admin .20, client .30):

/etc/netplan/99-isardvdi-conf.yaml
# This is the network config written by IsardVDI
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: true            # Internet: NO la toquis
    enp2s0:
      dhcp4: false           # abans era true
      addresses:             # línia nova
        - 192.168.1.10/24    # línia nova: la IP de la teva màquina
⚠️

Els espais compten: copia el sagnat exactament, sense tabuladors. Els comentaris en gris no cal que els escriguis.

Desa i surt. Aplica els canvis:

bash
sudo netplan apply

➜ Aplica la nova configuració. Si no diu res, ha anat bé.

bash
ip a show enp2s0

➜ Ha de sortir la línia inet 192.168.1.10/24 (o la IP de la màquina on ets).

2.3 · Comprova que les màquines es veuen

Administrador
bash — admin
ping -c 3 192.168.1.10
ping -c 3 192.168.1.11

➜ Envia 3 paquets de prova a apache i a tomcat. Si reps respostes (0% packet loss), la xarxa funciona.

2.4 · Instal·la SSH a apache i a tomcat

Apache i Tomcat · a totes dues
bash
sudo apt update
sudo apt install -y openssh-server

➜ Actualitza la llista de paquets i instal·la el servidor SSH, que permet entrar a la màquina des d'una altra.

2.5 · Entra per SSH des de l'administrador

Administrador
bash — admin
ssh isard@192.168.1.10

➜ Entra a apache. El primer cop escriu yes i després la contrasenya de l'usuari isard. El prompt passarà a isard@apache.

bash — admin → apache (SSH)
exit

➜ Surt d'apache i tornes a l'admin.

bash — admin
ssh isard@192.168.1.11

➜ Ara entra a tomcat. El prompt serà isard@tomcat. Surt amb exit.

💻→

Mira sempre el prompt abans d'escriure: isard@admin, isard@apache o isard@tomcat et diu a quina màquina s'executarà l'ordre.

3

Comprova que ho tens tot

  • Cada màquina té el seu nom: el prompt diu client, admin, apache o tomcat.
  • ip a show enp2s0 mostra la IP correcta a cada màquina.
  • Des de l'admin, ping a 192.168.1.10 i 192.168.1.11 respon.
  • Des de l'admin entres per SSH a apache i a tomcat.

Si alguna cosa falla

ProblemaSolució
netplan apply dona un errorHi ha un espai de més o de menys al YAML. Torna a obrir el fitxer i copia el sagnat exactament com a l'exemple.
ping no responComprova amb ip a show enp2s0 que totes dues màquines tenen la IP. Si no, repeteix el pas 2.2.
sudo diu unable to resolve hostNo has canviat el nom a /etc/hosts (pas 2.1).
El prompt encara diu isardvdiTanca el terminal i obre'n un de nou.
ssh diu Connection refusedNo has instal·lat openssh-server a aquella màquina (pas 2.4).
