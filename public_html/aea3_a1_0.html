Prepara l'entorn: xarxa, SSH i Java 21

Abans d'instal·lar Tomcat, prepararàs l'escenari de tota l'AEA3: tres màquines Ubuntu Server (servidor, administrador i client) en una xarxa privada amb IP fixes, l'accés remot al servidor per SSH i Java 21 instal·lat al servidor, que és el que necessita un servidor d'aplicacions per funcionar.

RA RA3 CA 3.1 · 3.2 Activitat de preparació
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Muntar l'arquitectura de xarxa de l'AEA3: quina feina fa cada màquina i per quina targeta viatja cada cosa.
  • Configurar una IP fixa a la targeta interna d'Ubuntu Server amb Netplan.
  • Administrar el servidor de manera remota i xifrada amb SSH.
  • Explicar la diferència entre un servidor web i un servidor d'aplicacions.
  • Instal·lar l'OpenJDK 21 al servidor i definir la variable JAVA_HOME.

Prerequisits

  • Tres màquines Ubuntu Server 24.04 LTS a IsardVDI, cadascuna amb dues targetes de xarxa: una default (amb sortida a Internet) i una interna (la xarxa privada que connecta les tres màquines).
  • Haver fet l'AEA2: ja coneixes SSH, sudo, nano i el paper de cada màquina.
⚠️

A l'AEA2 les màquines eren Debian i la IP fixa es posava a /etc/network/interfaces. Ubuntu Server no fa servir aquest fitxer: la xarxa es configura amb Netplan, en fitxers YAML dins de /etc/netplan/. Ho veuràs al pas 2.2.

1

Context i teoria mínima

Les dues targetes de xarxa

Com a l'AEA2, cada màquina d'IsardVDI té dues targetes amb funcions diferents:

  • Targeta default → té sortida a Internet. La fem servir per instal·lar paquets (apt). La seva IP l'assigna IsardVDI per DHCP: no la toquem.
  • Targeta interna → connecta les tres màquines entre elles a la xarxa privada 192.168.1.0/24. Aquí posem IP fixes i és per on viatgen l'SSH i el web.

Imatge 1 · Arquitectura de xarxa

Servidor web vs servidor d'aplicacions

A l'AEA2, Apache servia fitxers: el navegador demanava index.html i Apache el llegia del disc i l'enviava tal qual. Això és un servidor web.

Un servidor d'aplicacions fa una feina diferent: executa codi. Quan arriba una petició, posa en marxa un programa (per exemple, Java) que consulta dades, aplica lògica i genera la resposta en aquell moment. La pàgina no existeix al disc: la fabrica l'aplicació.

A l'AEA3 farem servir Apache Tomcat. Tomcat és un contenidor de servlets: executa aplicacions web Java empaquetades en fitxers .war. Per funcionar, necessita Java instal·lat al servidor.

Servidor webServidor d'aplicacions
ExempleApache HTTP Server, NginxApache Tomcat, WildFly, GlassFish
Què serveixFitxers estàtics (HTML, CSS, imatges)Respostes generades per una aplicació
Què necessitaNomés el propi servidorUn entorn d'execució (aquí, Java)
Port habitual80 / 4438080 (Tomcat)
Què despleguemUna carpeta amb fitxersUn paquet .war

Imatge 2 · Flux d'accés de l'AEA3

L'Administrador configura el servidor per SSH. El Client hi accedeix amb el navegador. Al final de l'A1.2, el client entrarà per Apache (port 80) i Apache passarà la petició a Tomcat (port 8080), que s'executa a sobre de Java.

Conceptes clau

ConcepteQuè és
ServidorLa màquina que allotjarà Java, Tomcat i Apache (192.168.1.10).
AdministradorLa màquina des d'on entrem al servidor per SSH per configurar-lo (192.168.1.20).
ClientLa màquina que consulta les aplicacions amb el navegador (192.168.1.30).
NetplanSistema de configuració de xarxa d'Ubuntu. Llegeix fitxers YAML de /etc/netplan/.
JVMJava Virtual Machine. Executa el codi Java compilat (bytecode, fitxers .class).
JRE / JDKEl JRE serveix per executar Java. El JDK hi afegeix les eines per compilar (javac, jar…).

JAVA_HOMEVariable d'entorn amb la carpeta on és instal·lat Java. Tomcat la consulta per trobar-lo.

Pas a pas guiat

💡

Cada pas ve dins d'una capsa de color que indica qui l'ha de fer: AdministradorServidorClientTotes les màquines. Els fitxers de configuració no porten capsa.

Part 1 · La xarxa i l'SSH

2.1 · Identifica les dues targetes de cada màquina

Totes les màquines

A cada màquina, mira les targetes de xarxa:

bash
ip a

➜ Llista totes les targetes de xarxa de la màquina amb la seva adreça IP.

Veuràs dues interfícies a més de lo. A IsardVDI solen ser enp1s0 i enp2s0:

sortida de ip a
2: enp1s0: <...> state UP           # targeta DEFAULT (surt a Internet)
    inet 192.168.120.186/22 ...    # IP posada per DHCP → NO la toquem
3: enp2s0: <...> state UP           # targeta INTERNA (xarxa privada)
    (sense línia inet)             # encara sense IP → aquí posarem la fixa

Ara mira quina configuració de xarxa té Ubuntu:

bash
ls /etc/netplan/
sudo cat /etc/netplan/*.yaml

➜ Llista i mostra els fitxers de Netplan. Normalment n'hi ha un (per exemple 50-cloud-init.yaml) que posa la targeta default en DHCP. No el modifiquis: en crearàs un de nou només per a la targeta interna.

⚠️

Apunta el nom exacte de la targeta interna de cada màquina (per exemple enp2s0). El necessitaràs al pas següent i pot variar entre màquines.

2.2 · Assigna la IP fixa a la targeta interna

Totes les màquines · exemple: servidor
bash
sudo nano /etc/netplan/60-interna.yaml

➜ Crea un fitxer de Netplan nou per a la targeta interna. Netplan llegeix els fitxers per ordre de nom: el 60 s'aplica després del 50 i mana sobre ell.

Escriu-hi aquest contingut, canviant enp2s0 pel nom real de la targeta interna i la IP segons la màquina (servidor .10, administrador .20, client .30). Aquest exemple és el del servidor:

/etc/netplan/60-interna.yaml
# --- Targeta interna (xarxa privada) ---
network:
  version: 2
  ethernets:
    enp2s0:                  # nom de la targeta INTERNA
      dhcp4: false           # sense DHCP: IP fixa
      addresses:
        - 192.168.1.10/24    # .10 servidor · .20 administrador · .30 client
⚠️

El YAML és molt estricte: fa servir espais (mai tabuladors) i el sagnat ha de ser exactament com a l'exemple. Si un nivell no quadra, Netplan donarà error.

Totes les màquines

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

bash
sudo chmod 600 /etc/netplan/60-interna.yaml

➜ Deixa el fitxer llegible només per root. Si té permisos oberts, Netplan avisa amb Permissions ... are too open.

bash
sudo netplan apply

➜ Aplica la configuració de xarxa. Si no diu res, ha anat bé. Si hi ha un error de sintaxi, t'indica la línia del YAML.

bash
ip a show enp2s0

➜ Mostra només la targeta interna. Ha d'aparèixer inet 192.168.1.10/24 (o la IP de la màquina on ets).

💡

Repeteix aquest pas a les tres màquines amb la seva IP (.10, .20, .30). No toquis la targeta default: ha de continuar amb DHCP perquè tinguis Internet.

2.3 · Comprova la connexió entre màquines

Administrador
bash — administrador
ping -c 3 192.168.1.10

➜ Envia 3 paquets de prova al servidor per la xarxa interna. Si reps respostes, la xarxa funciona. Fes la mateixa prova des del client.

2.4 · Crea l'usuari isard_ssh al servidor

Servidor

Com a l'AEA2, crearàs al servidor un usuari propi per entrar-hi per SSH. Així, quan el prompt digui isard_ssh@..., sabràs segur que treballes al servidor.

bash — servidor
sudo adduser isard_ssh

➜ Crea l'usuari isard_ssh amb la seva carpeta personal. Et demanarà la contrasenya dues vegades: apunta-la. La resta de preguntes les pots deixar buides amb Enter i confirmar amb Y.

bash — servidor
sudo usermod -aG sudo isard_ssh

➜ Afegeix isard_ssh al grup sudo perquè pugui instal·lar Java i Tomcat. -aG l'afegeix al grup sense treure'l dels altres.

bash — servidor
groups isard_ssh

➜ Mostra els grups de l'usuari. Ha de sortir isard_ssh : isard_ssh sudo (pot haver-hi algun grup més).

2.5 · Instal·la i comprova el servei SSH

Servidor
bash — servidor
sudo apt update

➜ Actualitza la llista de paquets disponibles.

bash — servidor
sudo apt install -y openssh-server

➜ Instal·la el servei SSH. Si ja el vas triar en instal·lar Ubuntu Server, et dirà que ja és a l'última versió: no passa res.

bash — servidor
sudo ss -tlnp | grep ':22 '

➜ Comprova que hi ha algú escoltant al port 22. Ha de sortir una línia LISTEN amb *:22 o 0.0.0.0:22.

💡

A Ubuntu 24.04, l'SSH s'activa per socket: systemd escolta el port 22 i engega sshd quan arriba la primera connexió. Per això systemctl status ssh pot dir inactive abans de connectar-te, i a ss el procés que escolta pot ser systemd. És normal.

2.6 · Connecta't des de l'administrador per SSH

Administrador
bash — administrador
ssh isard_ssh@192.168.1.10

➜ Obre una sessió de terminal xifrada al servidor amb l'usuari isard_ssh. El primer cop, accepta la fingerprint amb yes i escriu la contrasenya. El prompt passarà a ser isard_ssh@....

💻→

A partir d'aquí, tot el que escrius s'executa al servidor, no a l'administrador. Per tornar a l'administrador quan acabis, escriu exit.

Part 2 · Java al servidor

2.7 · Comprova que Java encara no hi és

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
java -version

➜ Demana la versió de Java. Ubuntu respon Command 'java' not found i et suggereix paquets. És el resultat esperat.

2.8 · Busca el paquet de Java 21

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
apt-cache policy openjdk-21-jdk-headless

➜ Mostra si el paquet existeix, quina versió s'instal·laria (Candidate) i si ja està instal·lat (Installed).

sortida esperada
openjdk-21-jdk-headless:
  Installed: (none)                         # encara no està instal·lat
  Candidate: 21.0.x+y~...-0ubuntu1~24.04    # la versió exacta pot variar
💡

La versió headless és el JDK complet sense les biblioteques d'interfície gràfica, que en un servidor sense escriptori no calen.

2.9 · Instal·la l'OpenJDK 21

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo apt install -y openjdk-21-jdk-headless

➜ Instal·la el JDK 21 sense interfície gràfica. -y accepta la instal·lació sense preguntar. Pot trigar un minut.

bash — administrador → servidor (SSH)
java -version
javac -version

➜ La primera mostra la versió de la JVM; la segona, la del compilador. Si totes dues responen 21, tens el JDK complet.

sortida esperada
openjdk version "21.0.x" 20XX-XX-XX                   # ⚠ EL MÉS IMPORTANT: versió 21
OpenJDK Runtime Environment (build 21.0.x+y-Ubuntu-...)
OpenJDK 64-Bit Server VM (build 21.0.x+y-Ubuntu-..., mixed mode, sharing)
javac 21.0.x                                          # compilador del JDK

2.10 · Localitza la carpeta de Java

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
readlink -f $(which java)

➜ which java diu on és l'ordre (/usr/bin/java) i readlink -f segueix els enllaços simbòlics fins al fitxer real.

sortida esperada
/usr/lib/jvm/java-21-openjdk-amd64/bin/java

JAVA_HOME és aquesta ruta sense el /bin/java final: /usr/lib/jvm/java-21-openjdk-amd64.

💡

El final -amd64 depèn del processador. En una màquina ARM sortiria -arm64. Fes servir sempre la ruta que t'ha sortit a tu.

2.11 · Defineix JAVA_HOME per a tot el sistema

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo nano /etc/environment

➜ Obre el fitxer de variables d'entorn globals. S'aplica a tots els usuaris quan inicien sessió.

Deixa la línia PATH=... tal com està i afegeix-ne una de nova al final:

/etc/environment
PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin"   # no la toquis
JAVA_HOME="/usr/lib/jvm/java-21-openjdk-amd64"                                                         # línia nova
Administrador → Servidor · per SSH

Desa i surt. La variable es carrega en iniciar sessió: tanca l'SSH i torna a entrar.

bash — administrador → servidor (SSH)
exit

➜ Tanca la sessió SSH i tornes a l'administrador.

bash — administrador
ssh isard_ssh@192.168.1.10

➜ Obre una sessió nova, que ja llegeix el /etc/environment actualitzat.

bash — administrador → servidor (SSH)
echo $JAVA_HOME

➜ Mostra el valor de la variable. Ha de sortir /usr/lib/jvm/java-21-openjdk-amd64.

⚠️

/etc/environment no és un script: només accepta línies NOM="valor", sense export ni $VARIABLES. A més, els serveis de systemd no el llegeixen: a l'A1.1 també indicaràs JAVA_HOME dins del servei de Tomcat.

2.12 · Compila i executa un programa de prova

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
mkdir -p ~/proves-java && cd ~/proves-java

➜ Crea una carpeta de proves a la teva carpeta personal i hi entra.

bash — administrador → servidor (SSH)
nano Hola.java

➜ Crea el fitxer de codi font. El nom del fitxer ha de coincidir amb el de la classe (Hola).

Escriu-hi aquest contingut:

Hola.java
public class Hola {
    public static void main(String[] args) {
        System.out.println("Hola des de Java " + System.getProperty("java.version"));
        System.out.println("JAVA_HOME = " + System.getenv("JAVA_HOME"));
    }
}
Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
javac Hola.java

➜ Compila el codi i genera Hola.class, el bytecode que entén la JVM. Si no diu res, ha anat bé.

bash — administrador → servidor (SSH)
java Hola

➜ La JVM carrega Hola.class i l'executa (sense posar .class al final).

sortida esperada
Hola des de Java 21.0.x                         # versió 21
JAVA_HOME = /usr/lib/jvm/java-21-openjdk-amd64  # si surt null, revisa el pas 2.11
💡

Això és el que farà Tomcat a gran escala. Un fitxer .war és un paquet comprimit amb molts .class com aquest, més pàgines i configuració. Tomcat el desplega i la JVM n'executa el codi cada cop que arriba una petició.

3

Verificació

Client

Comprova que el client arriba al servidor per la xarxa interna:

bash — client
ping -c 3 192.168.1.10

➜ Envia tres paquets de prova al servidor.

sortida esperada
64 bytes from 192.168.1.10: icmp_seq=1 ttl=64 time=0.5 ms
64 bytes from 192.168.1.10: icmp_seq=2 ttl=64 time=0.4 ms
64 bytes from 192.168.1.10: icmp_seq=3 ttl=64 time=0.4 ms
3 packets transmitted, 3 received, 0% packet loss   # ⚠ EL MÉS IMPORTANT
🔎 Comprova-ho al navegador http://192.168.1.10:8080

Al navegador del client, obre aquesta adreça. Ha de fallar amb un missatge com No es pot connectar: encara no hi ha cap servidor d'aplicacions. A l'A1.1 hi instal·laràs Tomcat i aquesta mateixa adreça mostrarà la seva pàgina d'inici.

Administrador → Servidor · per SSH

Dins del servidor, comprova la xarxa, Java i JAVA_HOME:

bash — administrador → servidor (SSH)
ip -4 a show enp2s0 | grep inet
java -XshowSettings:properties -version 2>&1 | grep -E 'java.home|java.version '
echo $JAVA_HOME

➜ La primera mostra la IP de la targeta interna. La segona demana a Java les seves propietats i en filtra dues (2>&1 cal perquè Java les escriu per la sortida d'errors). La tercera mostra la variable.

sortida esperada
    inet 192.168.1.10/24 ... scope global enp2s0     # estàs al servidor
    java.home = /usr/lib/jvm/java-21-openjdk-amd64   # on és Java de veritat
    java.version = 21.0.x                             # versió 21
/usr/lib/jvm/java-21-openjdk-amd64                    # ⚠ EL MÉS IMPORTANT: ha de coincidir amb java.home
bash — administrador → servidor (SSH)
sudo ss -tlnp | grep -E ':(22|8080) '

➜ Llista els ports en escolta i filtra el 22 (SSH) i el 8080 (on anirà Tomcat).

sortida esperada
LISTEN 0 4096  *:22  *:*  users:(("sshd",...),("systemd",pid=1,...))   # SSH escolta
                                                                    # cap línia amb :8080 → encara no hi ha Tomcat

Llista de comprovació

  • Les tres màquines tenen la IP fixa correcta a la targeta interna (.10, .20 i .30) i continuen tenint Internet per la default.
  • L'administrador i el client arriben al servidor amb ping.
  • L'administrador entra al servidor per SSH amb l'usuari isard_ssh.
  • java -version i javac -version mostren la versió 21.
  • echo $JAVA_HOME mostra la carpeta de Java en una sessió SSH nova i coincideix amb java.home.
  • java Hola imprimeix la versió 21 i la ruta de JAVA_HOME, no null.
  • El port 8080 encara està lliure: el client no s'hi pot connectar.
