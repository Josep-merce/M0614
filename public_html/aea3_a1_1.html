Instal·la Tomcat 10 i desplega la primera aplicació

Instal·laràs Apache Tomcat 10.1 al servidor des del paquet oficial, el convertiràs en un servei de systemd, coneixeràs la seva estructura de carpetes i hi desplegaràs la primera aplicació Java empaquetada en un fitxer .war.

RA RA3 CA 3.1 · 3.2 · 3.3 · 3.4
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Descarregar Tomcat 10.1 del web oficial i comprovar-ne la integritat amb SHA-512.
  • Instal·lar-lo a /opt/tomcat amb un usuari de sistema propi.
  • Crear un servei de systemd perquè Tomcat arrenqui sol amb el servidor.
  • Reconèixer les carpetes clau: conf, webapps i logs.
  • Desplegar una aplicació .war i comprovar-la des del client pel port 8080.

Prerequisit important

⚠️

Necessites la xarxa, l'usuari isard_ssh i Java 21 de l'A1.0. Comprova-ho abans de començar: java -version ha de dir 21 i echo $JAVA_HOME ha de mostrar la carpeta de Java.

1

Context i teoria mínima

Quin Tomcat instal·lem?

Tomcat té diverses branques actives. Farem servir la 10.1, que implementa Jakarta EE 10 (Servlet 6.0) i necessita Java 11 o superior. Amb el Java 21 de l'A1.0 en tens de sobres.

Ubuntu porta un paquet tomcat10, però l'instal·larem des del paquet oficial d'Apache (.tar.gz). Així tindràs la versió més nova, totes les carpetes juntes a /opt/tomcat i veuràs com es crea un servei de systemd a mà.

💡

Des de Tomcat 10, les classes de Java EE van passar de javax.* a jakarta.*. Una aplicació feta per a Tomcat 9 o anterior no funciona a Tomcat 10 sense adaptar-la. L'aplicació d'exemple que farem servir ja és de Tomcat 10.1.

Com s'organitza Tomcat per dins

Una petició entra per un connector (el port 8080), passa al host localhost, que mira la carpeta webapps, i acaba a l'aplicació (context) que correspon al principi de la URL.

Conceptes clau

ConcepteQuè és
CATALINA_HOMECarpeta on és instal·lat Tomcat (aquí /opt/tomcat). Catalina és el nom intern del motor de Tomcat.
ConnectorLa part de Tomcat que escolta un port i parla HTTP. Per defecte, el 8080.
Fitxer .warWeb Application Archive. Un ZIP amb una aplicació web Java: classes, JSP, HTML i configuració.
DesplegarPosar una aplicació en marxa al servidor. A Tomcat, n'hi ha prou amb copiar el .war a webapps.
ContextCada aplicació desplegada. El nom del .war en fixa la ruta: sample.war → /sample.
Servlet / JSPCodi Java que genera la resposta. Un JSP és una pàgina HTML amb Java a dins, que Tomcat converteix en servlet.
Servei systemdFitxer .service que diu a Linux com engegar, aturar i reiniciar un programa, i si ha d'arrencar amb el sistema.

Així quedarà la instal·lació:

estructura
/opt/tomcat/                          # CATALINA_HOME, propietat de l'usuari tomcat
├── bin/                              # scripts: startup.sh, shutdown.sh, catalina.sh…
├── conf/                             # configuració
│   ├── server.xml                    # ports, connectors i hosts
│   ├── tomcat-users.xml              # usuaris i rols (A1.3)
│   └── web.xml                       # configuració comuna a totes les aplicacions
├── lib/                              # biblioteques .jar de Tomcat
├── logs/                             # catalina.out, accessos, errors
├── temp/                             # fitxers temporals i el PID
├── webapps/                          # aplicacions desplegades
│   ├── ROOT/  docs/  examples/  manager/  host-manager/
│   └── sample.war → sample/          # la que desplegaràs tu
└── work/                             # JSP compilats
/etc/systemd/system/tomcat.service    # el servei

Pas a pas guiat

💡

Cada pas ve dins d'una capsa de color que indica qui l'ha de fer: AdministradorServidorClient. Els fitxers de configuració no porten capsa.

Part 1 · Instal·lació

2.1 · Connecta't al servidor per SSH

Administrador
bash — administrador
ssh isard_ssh@192.168.1.10

➜ Obre una sessió de terminal xifrada al servidor per SSH.

💻→

A partir d'aquí, tot el que escrius s'executa al servidor, no a l'administrador. Per tornar a l'administrador quan acabis, escriu exit.

2.2 · Crea l'usuari de sistema tomcat

Administrador → Servidor · per SSH

Tomcat no s'ha d'executar mai com a root: si algú en trenca una aplicació, tindria el control de tot el servidor. Li crearàs un usuari propi, sense contrasenya i sense terminal.

bash — administrador → servidor (SSH)
sudo mkdir /opt/tomcat

➜ Crea la carpeta on instal·laràs Tomcat.

bash — administrador → servidor (SSH)
sudo useradd -r -U -d /opt/tomcat -s /usr/sbin/nologin tomcat

➜ Crea l'usuari tomcat. -r el fa de sistema, -U crea també un grup tomcat, -d li assigna /opt/tomcat com a carpeta personal i -s /usr/sbin/nologin impedeix que s'hi pugui iniciar sessió.

2.3 · Descarrega Tomcat 10.1

Administrador → Servidor · per SSH

Tomcat publica una versió nova de la branca 10.1 cada poques setmanes, i el servidor de descàrregues només guarda la més recent. Primer, esbrina quina és:

bash — administrador → servidor (SSH)
VER=$(curl -s https://dlcdn.apache.org/tomcat/tomcat-10/ | grep -oP 'v\K10\.1\.[0-9]+' | sort -V | tail -1)
echo $VER

➜ Llegeix el llistat de versions del servidor oficial d'Apache, n'extreu les 10.1.x, es queda amb la més alta i la desa a la variable VER. L'echo l'ha de mostrar, per exemple 10.1.NN.

💡

Si echo $VER surt buit, obre tomcat.apache.org/download-10.cgi, mira la versió que s'hi anuncia i escriu-la a mà: VER=10.1.NN (canviant NN pel número real). La variable només dura mentre no tanquis la sessió SSH.

bash — administrador → servidor (SSH)
cd /tmp

➜ Et mou a la carpeta de fitxers temporals per fer-hi la descàrrega.

bash — administrador → servidor (SSH)
wget https://dlcdn.apache.org/tomcat/tomcat-10/v$VER/bin/apache-tomcat-$VER.tar.gz

➜ Descarrega el paquet de Tomcat. $VER es substitueix pel número de versió.

bash — administrador → servidor (SSH)
wget https://downloads.apache.org/tomcat/tomcat-10/v$VER/bin/apache-tomcat-$VER.tar.gz.sha512

➜ Descarrega el fitxer amb la suma de verificació SHA-512 que publica Apache per a aquest paquet.

bash — administrador → servidor (SSH)
sha512sum -c apache-tomcat-$VER.tar.gz.sha512

➜ Calcula la suma del fitxer descarregat i la compara amb l'oficial. Ha de respondre apache-tomcat-10.1.NN.tar.gz: OK. Si diu FAILED, el fitxer està malmès o no és l'original: torna'l a descarregar.

2.4 · Descomprimeix-lo a /opt/tomcat

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo tar -xzf apache-tomcat-$VER.tar.gz -C /opt/tomcat --strip-components=1

➜ Descomprimeix el paquet. -C /opt/tomcat indica on, i --strip-components=1 treu la carpeta apache-tomcat-10.1.NN/ del principi perquè els fitxers quedin directament a /opt/tomcat.

bash — administrador → servidor (SSH)
sudo chown -R tomcat:tomcat /opt/tomcat

➜ Fa que tota la carpeta sigui de l'usuari i el grup tomcat. -R ho aplica a totes les subcarpetes.

bash — administrador → servidor (SSH)
sudo ls -l /opt/tomcat

➜ Llista el contingut. Hi has de veure bin, conf, lib, logs, temp, webapps i work, tots de tomcat tomcat.

💡

Algunes carpetes de Tomcat (conf, logs) només les pot llegir l'usuari tomcat. Per això, per mirar-les com a isard_ssh, cal sudo davant de ls, cat o tail.

2.5 · Crea el servei de systemd

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo nano /etc/systemd/system/tomcat.service

➜ Crea el fitxer del servei. Els serveis propis de l'administrador van a /etc/systemd/system/.

Escriu-hi aquest contingut. Revisa que JAVA_HOME sigui la ruta que et va sortir a l'A1.0:

/etc/systemd/system/tomcat.service
[Unit]
Description=Apache Tomcat 10.1
After=network.target                       # arrenca quan ja hi ha xarxa

[Service]
Type=forking                               # startup.sh engega Java en segon pla i acaba
User=tomcat                                # s'executa com a tomcat, no com a root
Group=tomcat

Environment="JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64"   # systemd NO llegeix /etc/environment
Environment="CATALINA_HOME=/opt/tomcat"
Environment="CATALINA_BASE=/opt/tomcat"
Environment="CATALINA_PID=/opt/tomcat/temp/tomcat.pid"       # on desa el número de procés
Environment="CATALINA_OPTS=-Xms256M -Xmx512M"                 # memòria inicial i màxima de Java

ExecStart=/opt/tomcat/bin/startup.sh
ExecStop=/opt/tomcat/bin/shutdown.sh

[Install]
WantedBy=multi-user.target                 # s'activa en l'arrencada normal del sistema
Administrador → Servidor · per SSH

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

bash — administrador → servidor (SSH)
sudo systemctl daemon-reload

➜ Fa que systemd torni a llegir els fitxers de serveis i descobreixi tomcat.service.

bash — administrador → servidor (SSH)
sudo systemctl enable --now tomcat

➜ enable fa que Tomcat arrenqui sol cada cop que s'engega el servidor, i --now l'engega ara mateix.

bash — administrador → servidor (SSH)
systemctl status tomcat

➜ Mostra l'estat del servei. Prem q per sortir.

sortida esperada
● tomcat.service - Apache Tomcat 10.1
     Loaded: loaded (/etc/systemd/system/tomcat.service; enabled; ...)   # enabled → arrenca amb el sistema
     Active: active (running) since ...                                  # ⚠ EL MÉS IMPORTANT
   Main PID: 2345 (java)
     CGroup: /system.slice/tomcat.service
             └─2345 /usr/lib/jvm/java-21-openjdk-amd64/bin/java ... org.apache.catalina.startup.Bootstrap start

2.6 · Comprova el port 8080

Administrador → Servidor · per SSH

Java triga uns segons a arrencar del tot. Espera una mica i mira els ports:

bash — administrador → servidor (SSH)
sudo ss -tlnp | grep java

➜ Llista els ports TCP en escolta i filtra els que són del procés java (Tomcat).

sortida esperada
LISTEN 0 100  *:8080                 *:*  users:(("java",pid=2345,...))   # ⚠ connector HTTP, obert a la xarxa
LISTEN 0 1    [::ffff:127.0.0.1]:8005  *:*  users:(("java",pid=2345,...))   # port d'aturada, només local

El 8005 és el port per on shutdown.sh diu a Tomcat que s'aturi. Només escolta a 127.0.0.1: des de fora no s'hi pot arribar.

bash — administrador → servidor (SSH)
sudo grep -n '<Connector port' /opt/tomcat/conf/server.xml

➜ Busca a server.xml on es defineix el connector. -n mostra el número de línia.

sortida esperada
NN:    <Connector port="8080" protocol="HTTP/1.1"    # aquí es tria el port

2.7 · Obre Tomcat des del client

Client
🔎 Comprova-ho al navegador http://192.168.1.10:8080

Al navegador del client, obre aquesta adreça. A l'A1.0 fallava; ara ha de sortir la pàgina d'inici de Tomcat, amb el gat, el títol Apache Tomcat/10.1.NN i el missatge If you're seeing this, you've successfully installed Tomcat. Congratulations!. És l'aplicació ROOT.

Si prems Manager App, et sortirà 403 Access Denied: per defecte el Manager només s'obre des del mateix servidor. El configuraràs a l'A1.3.

Part 2 · Desplegament d'una aplicació

2.8 · Desplega sample.war

Administrador → Servidor · per SSH

El paquet de Tomcat porta, dins de la documentació, l'aplicació d'exemple oficial sample.war. Té una pàgina HTML, un JSP i un servlet: perfecta per provar-ho tot.

bash — administrador → servidor (SSH)
sudo ls -l /opt/tomcat/webapps

➜ Mostra les aplicacions que ja hi ha desplegades: ROOT, docs, examples, host-manager i manager.

bash — administrador → servidor (SSH)
sudo install -o tomcat -g tomcat -m 644 /opt/tomcat/webapps/docs/appdev/sample/sample.war /opt/tomcat/webapps/

➜ Copia sample.war a webapps i alhora en fixa el propietari (-o, -g) i els permisos (-m 644). És com un cp seguit d'un chown i un chmod.

💡

No cal reiniciar res. Tomcat revisa webapps cada pocs segons (autoDeploy): quan hi troba un .war nou, el descomprimeix en una carpeta amb el mateix nom i el posa en marxa.

bash — administrador → servidor (SSH)
sudo tail -n 20 /opt/tomcat/logs/catalina.out

➜ Mostra les últimes 20 línies del registre principal de Tomcat. Hi ha d'aparèixer el desplegament.

sortida esperada (resumida)
... INFO ... HostConfig.deployWAR Deploying web application archive [/opt/tomcat/webapps/sample.war]
... INFO ... HostConfig.deployWAR Deployment of web application archive [/opt/tomcat/webapps/sample.war] has finished in [NNN] ms   # ⚠ desplegada
bash — administrador → servidor (SSH)
sudo ls /opt/tomcat/webapps/sample

➜ Mostra el contingut de l'aplicació descomprimida: index.html, hello.jsp, images, META-INF i WEB-INF (on hi ha web.xml i les classes del servlet).

2.9 · Prova l'aplicació des del client

Client
🔎 Comprova-ho al navegador http://192.168.1.10:8080/sample/

Ha de sortir la pàgina d'inici de l'aplicació d'exemple, Sample "Hello, World" Application, amb dos enllaços. Prem el del JSP i després el del servlet: totes dues pàgines les genera Java en el moment, no existeixen com a HTML al disc.

2.10 · Retira i torna a desplegar l'aplicació

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo mv /opt/tomcat/webapps/sample.war /tmp/

➜ Treu el .war de webapps. En pocs segons Tomcat replega l'aplicació i esborra la carpeta sample. Al navegador, /sample/ donarà 404 Not Found.

bash — administrador → servidor (SSH)
sudo mv /tmp/sample.war /opt/tomcat/webapps/

➜ Torna a posar el .war a webapps. Tomcat el torna a desplegar sol. Recarrega /sample/ al client: ha de tornar a funcionar.

⚠️

No esborris la carpeta webapps/sample deixant-hi el .war: Tomcat la tornaria a crear. Per retirar una aplicació desplegada des d'un .war, treu sempre el .war.

3

Verificació

Administrador → Servidor · per SSH

Comprova que el servei arrenca amb el sistema i qui l'executa:

bash — administrador → servidor (SSH)
systemctl is-enabled tomcat
systemctl is-active tomcat
ps -o user=,cmd= -C java | cut -c1-80

➜ Les dues primeres diuen si el servei està habilitat i actiu. La tercera mostra l'usuari i l'ordre del procés java, retallada a 80 caràcters.

sortida esperada
enabled                                                       # arrenca amb el servidor
active                                                        # ara funciona
tomcat   /usr/lib/jvm/java-21-openjdk-amd64/bin/java ...      # ⚠ EL MÉS IMPORTANT: usuari tomcat, no root

Comprova el registre d'accessos, on Tomcat apunta cada petició que rep:

bash — administrador → servidor (SSH)
sudo sh -c 'tail -n 5 /opt/tomcat/logs/localhost_access_log.*.txt'

➜ Mostra les últimes peticions. Es fa amb sh -c perquè l'asterisc s'ha d'expandir amb permisos de root: la carpeta logs no la pot llegir isard_ssh.

sortida esperada
192.168.1.30 - - [16/Nov/2026:10:15:02 +0000] "GET /sample/ HTTP/1.1" 200 ...            # IP del client
192.168.1.30 - - [16/Nov/2026:10:15:05 +0000] "GET /sample/hello.jsp HTTP/1.1" 200 ...   # el JSP
Client
bash — client
curl -I http://192.168.1.10:8080/sample/

➜ -I mostra només la capçalera de la resposta de l'aplicació.

sortida esperada
HTTP/1.1 200                     # ⚠ EL MÉS IMPORTANT: l'aplicació respon
Accept-Ranges: bytes
Content-Type: text/html
...
💡

Fixa't que Tomcat respon HTTP/1.1 200 sense el text OK i sense capçalera Server: no diu quin programa és ni quina versió té. Apache, en canvi, sí que ho deia. A l'A1.2 l'usuari ja no veurà el port 8080: entrarà per Apache.

Llista de comprovació

  • sha512sum -c va donar OK abans d'instal·lar.
  • Tomcat és a /opt/tomcat i tot és de l'usuari tomcat.
  • systemctl status tomcat mostra enabled i active (running), i el procés java és de l'usuari tomcat.
  • El port 8080 escolta a tota la xarxa i el 8005 només a 127.0.0.1.
  • Des del client, http://192.168.1.10:8080 mostra la pàgina de Tomcat.
  • http://192.168.1.10:8080/sample/ funciona, igual que el JSP i el servlet.
  • Saps retirar i tornar a desplegar l'aplicació movent el .war.
⚠️

Si el servei no arrenca, mira què ha passat amb sudo journalctl -u tomcat -n 30 i sudo tail -n 30 /opt/tomcat/logs/catalina.out. Les causes habituals són un JAVA_HOME incorrecte al .service, haver oblidat el chown del pas 2.4 o no haver fet daemon-reload després d'editar el servei.
