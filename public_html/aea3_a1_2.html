Integra Apache amb Tomcat com a proxy invers

Posaràs Apache davant de Tomcat. L'usuari escriurà www.app.local, entrarà pel port 80 com en qualsevol web, i Apache passarà la petició a Tomcat, que quedarà darrere sense que el client ho noti.

RA RA3 CA 3.5 · 3.6
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Explicar què és un proxy invers i per què es posa Apache davant d'un servidor d'aplicacions.
  • Activar els mòduls proxy i proxy_http d'Apache.
  • Crear un host virtual www.app.local que reenviï les peticions a Tomcat.
  • Comprovar, amb les capçaleres i els registres, que l'usuari parla amb Apache i Apache parla amb Tomcat.

Prerequisit important

⚠️

Necessites la xarxa de l'A1.0 i Tomcat funcionant com a servei amb sample.war desplegat (A1.1). Comprova-ho abans: systemctl is-active tomcat ha de dir active.

1

Context i teoria mínima

Per què no deixem l'usuari entrar directament al 8080?

A l'A1.1 el client entrava a http://192.168.1.10:8080. Funciona, però en un servei real no es fa així:

  • L'usuari espera escriure un nom (www.app.local), sense port. Sense port, el navegador va al 80 (o al 443 amb HTTPS).
  • Apache és molt bo en la feina "de porta": HTTPS, hosts virtuals, restriccions per IP, registres, fitxers estàtics. Tomcat es pot dedicar a executar Java.
  • Si Tomcat no està exposat, hi ha menys superfície d'atac: només Apache parla amb el món.

Què és un proxy invers?

Un proxy invers és un servidor que rep les peticions dels clients en nom d'un altre servidor que hi ha darrere. El client creu que parla amb Apache; Apache fa la mateixa petició a Tomcat, rep la resposta i la torna al client.

A Apache això ho fan dos mòduls: mod_proxy (el motor de proxy) i mod_proxy_http (la part que sap parlar HTTP amb el servidor de darrere). Dins del host virtual, dues directives fan la feina:

  • ProxyPass / http://127.0.0.1:8080/ → tot el que arribi a /, reenvia-ho a Tomcat.
  • ProxyPassReverse / http://127.0.0.1:8080/ → si Tomcat respon amb una redirecció cap a 127.0.0.1:8080, reescriu-la perquè apunti a www.app.local. Sense això, el navegador del client acabaria intentant anar a una adreça que no és la seva.

Conceptes clau

ConcepteQuè és
Proxy inversServidor que rep les peticions en nom d'un altre i les hi reenvia. Aquí, Apache davant de Tomcat.
BackendEl servidor que hi ha darrere del proxy i fa la feina de debò (Tomcat).
mod_proxy / mod_proxy_httpMòduls d'Apache: el primer és el motor de proxy; el segon li permet parlar HTTP amb el backend.
ProxyPassDiu quines rutes es reenvien i a on. ProxyPass /ruta ! vol dir "aquesta ruta no la reenviïs".
ProxyPassReverseReescriu les redireccions que torna el backend perquè apuntin al nom públic.
ProxyPreserveHost OnPassa a Tomcat el nom original (www.app.local) en lloc de 127.0.0.1.
503 Service UnavailableError que dona Apache quan el backend no respon (per exemple, Tomcat aturat).

Així quedarà la configuració:

estructura
Servidor
/etc/apache2/sites-available/app.conf     # host virtual www.app.local (proxy cap a Tomcat)
/etc/apache2/mods-enabled/proxy*.load     # mòduls proxy i proxy_http activats
/var/log/apache2/app_access.log           # peticions que arriben a Apache
/opt/tomcat/                              # Tomcat de l'A1.1, sense cap canvi

Client
/etc/hosts                                # 192.168.1.10  www.app.local app.local

Pas a pas guiat

💡

Cada pas ve dins d'una capsa de color que indica qui l'ha de fer: AdministradorServidorClient. Els fitxers de configuració no porten capsa.

Part 1 · Apache com a proxy

2.1 · Connecta't al servidor per SSH

Administrador
bash — administrador
ssh isard_ssh@192.168.1.10

➜ Obre una sessió de terminal xifrada al servidor per SSH.

💻→

A partir d'aquí, tot el que escrius s'executa al servidor, no a l'administrador. Per tornar a l'administrador quan acabis, escriu exit.

2.2 · Instal·la Apache

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo apt update

➜ Actualitza la llista de paquets disponibles.

bash — administrador → servidor (SSH)
sudo apt install -y apache2

➜ Instal·la Apache. A Ubuntu, en acabar ja queda engegat i habilitat, escoltant el port 80.

bash — administrador → servidor (SSH)
sudo ss -tlnp | grep -E ':(80|8080) '

➜ Comprova que ara hi ha dos servidors al mateix equip, cadascun al seu port.

sortida esperada
LISTEN 0 511  *:80    *:*  users:(("apache2",pid=...))   # Apache: servidor web
LISTEN 0 100  *:8080  *:*  users:(("java",pid=...))      # Tomcat: servidor d'aplicacions

2.3 · Activa els mòduls de proxy

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo a2enmod proxy proxy_http

➜ Activa mod_proxy i mod_proxy_http. Igual que a l'AEA2 amb ssl, a2enmod crea els enllaços a mods-enabled.

bash — administrador → servidor (SSH)
sudo systemctl restart apache2

➜ Reinicia Apache. Per carregar mòduls nous cal restart, no n'hi ha prou amb reload.

bash — administrador → servidor (SSH)
apache2ctl -M | grep proxy

➜ Llista els mòduls carregats i filtra els de proxy. Han de sortir proxy_module (shared) i proxy_http_module (shared).

2.4 · Crea el host virtual www.app.local

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo nano /etc/apache2/sites-available/app.conf

➜ Crea el fitxer del host virtual nou.

Escriu-hi aquest contingut:

app.conf
<VirtualHost *:80>
    ServerName  www.app.local
    ServerAlias app.local

    # --- Proxy invers cap a Tomcat ---
    ProxyRequests     Off                 # NO fem de proxy obert per a navegar per Internet
    ProxyPreserveHost On                  # Tomcat rep el nom www.app.local

    ProxyPass /manager      !             # les eines d'administració no es publiquen (A1.3)
    ProxyPass /host-manager !

    ProxyPass        / http://127.0.0.1:8080/
    ProxyPassReverse / http://127.0.0.1:8080/

    ErrorLog  ${APACHE_LOG_DIR}/app_error.log
    CustomLog ${APACHE_LOG_DIR}/app_access.log combined
</VirtualHost>
⚠️

L'ordre importa: Apache aplica el primer ProxyPass que coincideix. Les exclusions (!) han d'anar abans del ProxyPass / general. I vigila la barra final: / i http://127.0.0.1:8080/ han d'acabar totes dues amb / o cap de les dues.

💡

Per què excloem /manager? Tomcat només deixa entrar al Manager des de 127.0.0.1. Però, a través del proxy, totes les peticions arriben a Tomcat des de 127.0.0.1, siguin de qui siguin. Si no l'excloguéssim, el Manager quedaria publicat a tota la xarxa. A l'A1.3 l'obrirem de manera controlada.

Administrador → Servidor · per SSH

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

bash — administrador → servidor (SSH)
sudo a2ensite app

➜ Activa el host virtual app.

bash — administrador → servidor (SSH)
sudo apache2ctl configtest

➜ Revisa la sintaxi de tota la configuració sense aplicar-la. Ha de respondre Syntax OK.

bash — administrador → servidor (SSH)
sudo systemctl reload apache2

➜ Recarrega Apache perquè apliqui el host virtual nou sense aturar el servei.

bash — administrador → servidor (SSH)
sudo apache2ctl -S

➜ Mostra els hosts virtuals actius al port 80. Hi ha d'haver 000-default.conf (el per defecte) i www.app.local amb l'àlies app.local.

Part 2 · Accés des del client

2.5 · Fes que el client conegui www.app.local

Client

No tenim servidor DNS, així que el nom s'afegeix a mà al fitxer /etc/hosts del client, com a l'AEA2:

bash — client
sudo nano /etc/hosts

➜ Obre el fitxer on el sistema busca els noms abans de preguntar al DNS.

Afegeix aquesta línia al final:

/etc/hosts — client
192.168.1.10   www.app.local   app.local

Desa i surt. Comprova-ho:

bash — client
getent hosts www.app.local

➜ Pregunta al sistema quina IP té el nom. Ha de respondre 192.168.1.10 www.app.local app.local.

2.6 · Entra a l'aplicació pel port 80

Client
🔎 Comprova-ho al navegador http://www.app.local

Sense port. Ha de sortir la mateixa pàgina de Tomcat de l'A1.1, amb el gat i Apache Tomcat/10.1.NN. L'has demanada a Apache pel port 80, però l'ha generat Tomcat.

🔎 Comprova-ho al navegador http://www.app.local/sample/

Ha de sortir l'aplicació d'exemple. Prova també els enllaços del JSP i del servlet: tot passa per Apache.

🔎 Comprova-ho al navegador http://192.168.1.10

Ara entra per la IP, sense nom. Ha de sortir la pàgina per defecte d'Apache, Apache2 Ubuntu Default Page. La petició no porta el nom www.app.local, així que l'atén el primer host virtual, 000-default, que no fa de proxy.

2.7 · Comprova què passa si Tomcat cau

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo systemctl stop tomcat

➜ Atura Tomcat. Apache continua funcionant, però ja no té ningú a qui passar les peticions.

Client
🔎 Comprova-ho al navegador http://www.app.local/sample/

Recarrega la pàgina. Ara surt 503 Service Unavailable: la resposta és d'Apache, que diu que el servidor de darrere no respon.

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo tail -n 3 /var/log/apache2/app_error.log

➜ Mostra les últimes línies del registre d'errors del host virtual. Hi veuràs Connection refused cap a 127.0.0.1:8080.

bash — administrador → servidor (SSH)
sudo systemctl start tomcat

➜ Torna a engegar Tomcat. Espera uns segons i recarrega la pàgina al client: torna a funcionar.

3

Verificació

Client

Compara les capçaleres de la mateixa aplicació demanada per Apache i directament a Tomcat:

bash — client
curl -I http://www.app.local/sample/
curl -I http://192.168.1.10:8080/sample/

➜ -I mostra només la capçalera de la resposta. La primera passa per Apache; la segona va directament a Tomcat.

sortida esperada
HTTP/1.1 200 OK                        # per Apache
Date: ...
Server: Apache/2.4.NN (Ubuntu)         # ⚠ EL MÉS IMPORTANT: qui respon és Apache
...
HTTP/1.1 200                           # directament a Tomcat (sense "OK" i sense "Server")
...

Comprova que el Manager no es publica pel proxy:

bash — client
curl -s -o /dev/null -w '%{http_code}\n' http://www.app.local/manager/html

➜ -o /dev/null descarta la pàgina i -w imprimeix només el codi de resposta. Ha de sortir 404: Apache no la reenvia a Tomcat.

Administrador → Servidor · per SSH

Compara els dos registres d'accés. Cada servidor veu un client diferent:

bash — administrador → servidor (SSH)
sudo tail -n 2 /var/log/apache2/app_access.log
sudo sh -c 'tail -n 2 /opt/tomcat/logs/localhost_access_log.*.txt'

➜ La primera mostra el que ha rebut Apache; la segona, el que ha rebut Tomcat.

sortida esperada
192.168.1.30 - - [...] "HEAD /sample/ HTTP/1.1" 200 ...   # Apache veu el client real
127.0.0.1 - - [...] "HEAD /sample/ HTTP/1.1" 200 ...      # ⚠ Tomcat veu Apache: la petició li arriba des del mateix servidor
💡

Això demostra que el proxy funciona: per a Tomcat, el client és Apache (127.0.0.1). Si l'aplicació necessités saber la IP real del client, Apache l'envia a la capçalera X-Forwarded-For.

⚠️

De moment, el port 8080 encara està obert a la xarxa: el segon curl ho demostra. Qualsevol pot saltar-se Apache. A l'A1.3 el tancaràs a l'exterior i hi afegiràs HTTPS.

Llista de comprovació

  • apache2ctl -M mostra proxy_module i proxy_http_module.
  • apache2ctl -S mostra el host virtual www.app.local.
  • http://www.app.local i http://www.app.local/sample/ funcionen des del client, sense port.
  • La capçalera Server diu Apache quan entres pel nom.
  • http://www.app.local/manager/html dona 404.
  • Amb Tomcat aturat, Apache respon 503; en tornar-lo a engegar, tot torna a funcionar.
  • El registre de Tomcat mostra 127.0.0.1 com a client i el d'Apache, 192.168.1.30.
