Fes-ho segur: HTTPS i Tomcat tancat

Publicaràs l'aplicació amb HTTPS a Apache i faràs que Tomcat només accepti connexions de la màquina apache.

RA RA3 Màquines apache i tomcat
0

Què faràs

  • Publicar l'aplicació amb HTTPS a Apache.
  • Fer que Tomcat només accepti connexions d'Apache, amb el tallafocs ufw.

Què necessites

  • Haver fet l'A1.2: http://www.app.local/sample/ funciona des del client.
1

Què canviarem

Ara mateix hi ha dos problemes de seguretat:

  • Les dades viatgen sense xifrar (HTTP). Ho arreglarem amb HTTPS a Apache, amb un certificat fet per nosaltres (autofirmat).
  • El client encara pot entrar directament a Tomcat pel 8080, saltant-se Apache. Ho arreglarem amb el tallafocs de la màquina tomcat: només deixarà entrar al 8080 la màquina apache.
2

Pas a pas

💡

Cada pas ve dins d'una capsa de color que diu a quina màquina l'has de fer: ClientAdministradorApacheTomcatDiverses màquines.

Part 1 · HTTPS a Apache

2.1 · Entra a la màquina apache

Administrador
bash — admin
ssh isard@192.168.1.10

➜ Entra a la màquina apache per SSH amb l'usuari isard i la seva contrasenya. Quan el prompt digui isard@apache, ja hi ets.

2.2 · Crea el certificat

Administrador → Apache · per SSH
bash — admin → apache (SSH)
sudo a2enmod ssl

➜ Activa el mòdul d'HTTPS d'Apache.

bash — admin → apache (SSH)
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/app.key -out /etc/ssl/certs/app.crt \
  -subj "/CN=www.app.local"

➜ Crea un certificat autofirmat per a www.app.local, vàlid 365 dies: la clau privada (app.key) i el certificat (app.crt). És una sola ordre en tres línies.

2.3 · Canvia el lloc a HTTPS

Administrador → Apache · per SSH
bash — admin → apache (SSH)
cd /etc/apache2/sites-available
sudo nano app.conf

➜ Torna a obrir el lloc de l'A1.2. Esborra el que hi ha i escriu-hi:

app.conf
# Port 80: envia el client a HTTPS
<VirtualHost *:80>
    ServerName www.app.local
    Redirect / https://www.app.local/
</VirtualHost>

# Port 443: HTTPS i proxy cap a Tomcat
<VirtualHost *:443>
    ServerName www.app.local
    SSLEngine on
    SSLCertificateFile    /etc/ssl/certs/app.crt
    SSLCertificateKeyFile /etc/ssl/private/app.key
    ProxyPass        / http://192.168.1.11:8080/
    ProxyPassReverse / http://192.168.1.11:8080/
</VirtualHost>
  • El primer bloc (port 80) només fa una cosa: redirigir el client a la versió HTTPS.
  • El segon bloc (port 443) és el d'abans, amb HTTPS activat (SSLEngine on) i el certificat que has creat.

Desa i surt. Reinicia Apache:

bash — admin → apache (SSH)
sudo systemctl restart apache2

➜ Reinicia Apache amb el mòdul SSL i el lloc nou. Si dona error, fes sudo apache2ctl configtest per veure la línia que falla.

2.4 · Prova l'HTTPS des del client

Client
🔎 Comprova-ho al navegador del client http://www.app.local/sample/

El navegador canvia sol a https:// i avisa que el certificat no és de confiança: és normal, l'has fet tu. Fes clic a Avançat → Accepta el risc i continua. Ha de sortir l'aplicació amb el cadenat a la barra d'adreces.

Part 2 · Tomcat només per a Apache

2.5 · Entra a la màquina tomcat

Administrador
bash — admin
ssh isard@192.168.1.11

➜ Entra a la màquina tomcat per SSH amb l'usuari isard i la seva contrasenya. Quan el prompt digui isard@tomcat, ja hi ets.

2.6 · Activa el tallafocs

Administrador → Tomcat · per SSH
bash — admin → tomcat (SSH)
sudo ufw allow OpenSSH

➜ Primer de tot, deixa entrar l'SSH. Si actives el tallafocs sense aquesta regla, et quedes fora.

bash — admin → tomcat (SSH)
sudo ufw allow from 192.168.1.10 to any port 8080

➜ Deixa entrar al port 8080 només la màquina apache (192.168.1.10).

bash — admin → tomcat (SSH)
sudo ufw enable

➜ Activa el tallafocs. Et preguntarà si vols continuar: escriu y. A partir d'ara, tot el que no hagis permès queda bloquejat.

bash — admin → tomcat (SSH)
sudo ufw status

➜ Mostra les regles. Han de sortir OpenSSH i 8080 permès des de 192.168.1.10.

2.7 · Comprova que el 8080 ja no s'obre des del client

Client
🔎 Comprova-ho al navegador del client http://192.168.1.11:8080

Ara no ha de carregar: el navegador es queda esperant i acaba donant error de temps d'espera. El tallafocs de tomcat no deixa entrar el client.

🔎 Comprova-ho al navegador del client https://www.app.local/sample/

En canvi, per Apache continua funcionant: Apache sí que pot parlar amb Tomcat.

3

Comprova que ho tens tot

  • http://www.app.local/sample/ et porta sol a https:// i mostra l'aplicació.
  • El navegador mostra el cadenat (amb l'avís de certificat autofirmat).
  • http://192.168.1.11:8080 ja no s'obre des del client.
  • L'admin encara pot entrar per SSH a tomcat.
4

Si alguna cosa falla

ProblemaSolució
Apache no arrenca després del pas 2.3Fes sudo apache2ctl configtest. Si diu Invalid command 'SSLEngine', et falta sudo a2enmod ssl.
https://www.app.local no carregaComprova que has reiniciat Apache i que l'ordre openssl ha creat els dos fitxers (ls /etc/ssl/certs/app.crt /etc/ssl/private/app.key amb sudo).
503 Service Unavailable després d'activar ufwLa regla del 8080 no té la IP d'apache. Fes sudo ufw status i, si cal, torna a fer sudo ufw allow from 192.168.1.10 to any port 8080.
L'admin ja no pot entrar per SSH a tomcatHas activat ufw sense sudo ufw allow OpenSSH. Ves a la màquina tomcat directament (al seu escriptori d'IsardVDI) i fes-ho allà.
