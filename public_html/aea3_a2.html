Tomcat i Apache amb Docker Compose

Muntaràs la mateixa arquitectura de l'A1.2, Apache davant de Tomcat, però amb contenidors. Faràs servir les imatges oficials, volums per a les aplicacions i els registres, i un fitxer de Docker Compose que aixeca els dos contenidors connectats per una xarxa interna.

RA RA3 CA 3.2 · 3.5 · 3.6 · 3.8
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Fer servir les imatges oficials tomcat i httpd de Docker Hub.
  • Distingir un bind mount (carpeta del servidor) d'un volum amb nom (gestionat per Docker).
  • Escriure un fitxer compose.yaml amb dos serveis i una xarxa interna.
  • Fer que Apache trobi Tomcat pel nom del servei i que Tomcat no tingui cap port publicat.
  • Desplegar una aplicació copiant un .war al volum.

Prerequisits

  • La xarxa de l'A1.0 i la configuració de proxy de l'A1.2: aquí la tornaràs a escriure, ara per a contenidors.
  • El client amb www.app.local a /etc/hosts apuntant a 192.168.1.10.
  • Els conceptes bàsics de Docker de l'AEA2: imatge, contenidor, docker run, docker ps.
⚠️

Al servidor ja hi ha l'Apache i el Tomcat de l'A1, que ocupen els ports 80, 443 i 8080. Els aturaràs mentre dura aquesta activitat i, al final, els tornaràs a engegar. No els desinstal·lis: les activitats A3 hi tornen.

1

Context i teoria mínima

Per què contenidors?

A l'A1 has instal·lat Java, Tomcat i Apache a mà, pas per pas, i has deixat fitxers per tot el servidor. Amb contenidors, cada servei ve en una imatge ja preparada, i tota l'arquitectura queda descrita en un sol fitxer de text (compose.yaml). Qualsevol altra persona, amb aquest fitxer, aixeca exactament el mateix amb una ordre.

Les dues imatges oficials

ImatgeQuè portaDetalls importants
tomcat:10.1-jdk21 Tomcat 10.1 amb Java 21 (Eclipse Temurin).Instal·lat a /usr/local/tomcat. La carpeta webapps ve buida per seguretat: les aplicacions d'exemple i el Manager són a webapps.dist.
httpd:2.4Apache HTTP Server 2.4 oficial.Instal·lat a /usr/local/apache2. No té a2enmod ni sites-available: tot es configura a conf/httpd.conf. Els registres van a la sortida del contenidor.

Volums: dues maneres de guardar dades

El que s'escriu dins d'un contenidor desapareix quan l'esborres. Per conservar dades o per posar-hi fitxers des de fora es fan servir volums:

  • Bind mount → una carpeta del servidor que apareix dins del contenidor. La faràs servir per a webapps: copies un .war al servidor i Tomcat el veu a l'instant.
  • Volum amb nom → un espai que crea i gestiona Docker. El faràs servir per als registres de Tomcat: sobreviuen encara que esborris el contenidor.

Conceptes clau

ConcepteQuè és
Docker ComposeEina que aixeca diversos contenidors a partir d'un fitxer compose.yaml. S'executa amb docker compose.
ServeiCada contenidor descrit al compose.yaml (aquí, apache i tomcat).
Xarxa de ComposeXarxa privada entre contenidors. Dins d'ella, cada servei es pot trobar pel seu nom: Docker fa de DNS.
ports: "80:80"Publica un port: el 80 del servidor porta al 80 del contenidor. Un servei sense ports no es veu des de fora.
Bind mount./carpeta:/ruta. Una carpeta del servidor dins del contenidor.
Volum amb nomnom:/ruta. Espai gestionat per Docker que persisteix encara que s'esborri el contenidor.

Així quedarà el projecte:

estructura
~/aea3-docker/
├── compose.yaml          # els dos serveis, la xarxa i els volums
├── apache/
│   ├── httpd.conf        # configuració principal d'Apache, amb els mòduls de proxy activats
│   └── app.conf          # host virtual www.app.local → tomcat:8080
└── webapps/
    └── sample.war        # l'aplicació que es desplegarà

Pas a pas guiat

💡

Cada pas ve dins d'una capsa de color que indica qui l'ha de fer: AdministradorServidorClient. Els fitxers de configuració no porten capsa.

Part 1 · Preparació

2.1 · Connecta't al servidor per SSH

Administrador
bash — administrador
ssh isard_ssh@192.168.1.10

➜ Obre una sessió de terminal xifrada al servidor per SSH.

💻→

A partir d'aquí, tot el que escrius s'executa al servidor, no a l'administrador. Per tornar a l'administrador quan acabis, escriu exit.

2.2 · Atura l'Apache i el Tomcat de l'A1

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo systemctl stop apache2 tomcat

➜ Atura els dos serveis per alliberar els ports. Continuen habilitats: si reinicies el servidor, tornaran a engegar-se i ocuparan el port 80. Si et passa, torna a fer aquesta ordre.

bash — administrador → servidor (SSH)
sudo ss -tlnp | grep -E ':(80|443|8080) '

➜ Comprova que cap d'aquests ports està en ús. No ha de sortir cap línia.

2.3 · Instal·la Docker i Docker Compose

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
sudo apt update

➜ Actualitza la llista de paquets disponibles.

bash — administrador → servidor (SSH)
sudo apt install -y docker.io docker-compose-v2

➜ Instal·la Docker (docker.io) i el connector de Compose (docker-compose-v2), tots dos dels repositoris d'Ubuntu. Si ja tens Docker instal·lat des del repositori oficial de Docker, salta aquest pas.

bash — administrador → servidor (SSH)
sudo usermod -aG docker isard_ssh

➜ Afegeix isard_ssh al grup docker perquè pugui fer servir Docker sense sudo. Com a l'A1.0, el canvi de grup s'aplica en tornar a iniciar sessió.

bash — administrador → servidor (SSH)
exit

➜ Tanca la sessió SSH. Torna a entrar amb ssh isard_ssh@192.168.1.10.

bash — administrador → servidor (SSH)
docker version --format '{{.Server.Version}}'
docker compose version

➜ La primera mostra la versió del motor de Docker; la segona, la de Compose. Si la primera dona permission denied, no has tornat a iniciar sessió.

Part 2 · El projecte

2.4 · Crea les carpetes i descarrega les imatges

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
mkdir -p ~/aea3-docker/apache ~/aea3-docker/webapps && cd ~/aea3-docker

➜ Crea la carpeta del projecte amb les subcarpetes apache i webapps, i hi entra. Totes les ordres següents s'executen des d'aquí.

bash — administrador → servidor (SSH)
docker pull tomcat:10.1-jdk21
docker pull httpd:2.4

➜ Descarrega les dues imatges oficials de Docker Hub. La part de després dels dos punts és l'etiqueta: la branca de Tomcat amb Java 21, i la branca 2.4 d'Apache.

bash — administrador → servidor (SSH)
docker run --rm tomcat:10.1-jdk21 ls /usr/local/tomcat/webapps /usr/local/tomcat/webapps.dist

➜ Engega un contenidor d'un sol ús (--rm l'esborra en acabar) per mirar-ne les carpetes. Veuràs que webapps és buida i que ROOT, manager, docs… són a webapps.dist.

2.5 · Prepara la configuració d'Apache

Administrador → Servidor · per SSH

La imatge httpd no té a2enmod. El procediment que recomana la seva documentació és copiar el httpd.conf de la imatge, modificar-lo i muntar-lo al contenidor.

bash — administrador → servidor (SSH)
docker run --rm httpd:2.4 cat /usr/local/apache2/conf/httpd.conf > apache/httpd.conf

➜ Engega un contenidor d'un sol ús, n'imprimeix la configuració per defecte i la desa a apache/httpd.conf.

bash — administrador → servidor (SSH)
sed -i \
  -e 's|^#LoadModule proxy_module |LoadModule proxy_module |' \
  -e 's|^#LoadModule proxy_http_module |LoadModule proxy_http_module |' \
  apache/httpd.conf

➜ Treu el # de les dues línies que carreguen mod_proxy i mod_proxy_http. És el que feia a2enmod proxy proxy_http a l'A1.2. -i modifica el fitxer directament.

bash — administrador → servidor (SSH)
echo 'Include conf/extra/app.conf' >> apache/httpd.conf

➜ Afegeix al final una línia que carrega el fitxer del host virtual. >> afegeix sense esborrar.

bash — administrador → servidor (SSH)
grep -E '^(LoadModule proxy|Include conf/extra/app)' apache/httpd.conf

➜ Comprova els tres canvis.

sortida esperada
LoadModule proxy_module modules/mod_proxy.so              # sense #
LoadModule proxy_http_module modules/mod_proxy_http.so    # sense #
Include conf/extra/app.conf                               # afegida al final

Ara crea el host virtual:

bash — administrador → servidor (SSH)
nano apache/app.conf

➜ Crea el fitxer del host virtual dins del projecte.

apache/app.conf
<VirtualHost *:80>
    ServerName  www.app.local
    ServerAlias app.local

    ProxyRequests     Off
    ProxyPreserveHost On

    ProxyPass        / http://tomcat:8080/       # "tomcat" és el NOM DEL SERVEI, no una IP
    ProxyPassReverse / http://tomcat:8080/
</VirtualHost>
💡

Compara'l amb el de l'A1.2: l'única diferència important és tomcat en lloc de 127.0.0.1. Ara Tomcat és un altre contenidor, amb una altra IP dins de la xarxa de Docker, i Docker resol el nom tomcat a aquesta IP. No hi posem ErrorLog ni CustomLog: la imatge envia els registres a la sortida del contenidor, i els veuràs amb docker compose logs.

2.6 · Posa l'aplicació a webapps

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
wget -P webapps https://tomcat.apache.org/tomcat-10.1-doc/appdev/sample/sample.war

➜ Descarrega l'aplicació d'exemple oficial dins de la carpeta webapps del projecte (-P indica la carpeta de destinació).

2.7 · Escriu el compose.yaml

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
nano compose.yaml

➜ Crea el fitxer que descriu tota l'arquitectura.

compose.yaml
services:

  tomcat:
    image: tomcat:10.1-jdk21
    container_name: app-tomcat
    restart: unless-stopped                          # es torna a engegar sol si cau
    volumes:
      - ./webapps:/usr/local/tomcat/webapps          # bind mount: aplicacions
      - tomcat-logs:/usr/local/tomcat/logs           # volum amb nom: registres
    networks:
      - interna
    # sense "ports": Tomcat NO es publica fora de Docker

  apache:
    image: httpd:2.4
    container_name: app-apache
    restart: unless-stopped
    ports:
      - "80:80"                                      # port 80 del servidor → port 80 del contenidor
    volumes:
      - ./apache/httpd.conf:/usr/local/apache2/conf/httpd.conf:ro
      - ./apache/app.conf:/usr/local/apache2/conf/extra/app.conf:ro   # :ro → només lectura
    depends_on:
      - tomcat                                       # engega primer Tomcat
    networks:
      - interna

networks:
  interna:                                           # xarxa privada dels dos contenidors

volumes:
  tomcat-logs:                                       # Docker el crea i el gestiona
⚠️

És YAML, com el Netplan de l'A1.0: només espais, mai tabuladors, i el sagnat marca què va dins de què. Els comentaris amb # els pots deixar o treure.

Administrador → Servidor · per SSH

Desa i surt.

bash — administrador → servidor (SSH)
docker compose config --quiet && echo "compose.yaml correcte"

➜ Valida el fitxer sense engegar res. Si hi ha un error de sintaxi o de sagnat, el mostra; si no, escriu compose.yaml correcte.

Part 3 · En marxa

2.8 · Aixeca els contenidors

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
docker compose up -d

➜ Crea la xarxa, el volum i els dos contenidors, i els engega en segon pla (-d).

bash — administrador → servidor (SSH)
docker compose ps

➜ Mostra els contenidors del projecte i els seus ports.

sortida esperada (resumida)
NAME         IMAGE               SERVICE   STATUS         PORTS
app-apache   httpd:2.4           apache    Up 5 seconds   0.0.0.0:80->80/tcp   # ⚠ publicat
app-tomcat   tomcat:10.1-jdk21   tomcat    Up 6 seconds   8080/tcp             # ⚠ només intern
bash — administrador → servidor (SSH)
docker compose logs tomcat | grep -i deploy

➜ Mostra els registres del contenidor de Tomcat i filtra els desplegaments. Ha de sortir que ha desplegat /usr/local/tomcat/webapps/sample.war.

bash — administrador → servidor (SSH)
ls -l webapps

➜ Com que webapps és un bind mount, la carpeta sample que ha creat Tomcat en descomprimir el .war apareix també al servidor. És de root perquè el contenidor de Tomcat s'executa com a root.

2.9 · Prova-ho des del client

Client
⚠️

A l'A1.3 el navegador va rebre una redirecció permanent (301) de http://www.app.local a https://, i la recorda. Ara no hi ha HTTPS: fes les proves en una finestra privada o amb curl.

🔎 Comprova-ho al navegador http://www.app.local/sample/

En una finestra privada, ha de sortir l'aplicació d'exemple, igual que a l'A1.2. Ara, però, l'Apache i el Tomcat que la serveixen són contenidors.

🔎 Comprova-ho al navegador http://www.app.local/

Ha de sortir un 404 de Tomcat. És correcte: la imatge oficial no porta l'aplicació ROOT ni el Manager a webapps. Només hi ha el que tu hi has posat.

2.10 · Inspecciona la xarxa interna

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
docker network ls

➜ Llista les xarxes de Docker. Hi ha d'haver aea3-docker_interna: Compose li posa davant el nom de la carpeta del projecte.

bash — administrador → servidor (SSH)
docker compose exec apache getent hosts tomcat

➜ Executa getent dins del contenidor apache per preguntar quina IP té el nom tomcat. Respon una IP privada de Docker (per exemple 172.18.0.2 tomcat): així és com Apache troba Tomcat.

2.11 · Desplega una segona aplicació en calent

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
cp webapps/sample.war webapps/demo.war

➜ Copia el .war amb un altre nom a la carpeta del servidor. Com que és un bind mount, Tomcat el veu dins del contenidor i el desplega a /demo en pocs segons, sense reiniciar res.

🔎 Comprova-ho al navegador http://www.app.local/demo/

Des del client (finestra privada): ha de sortir l'aplicació d'exemple a la ruta nova.

2.12 · Comprova que els registres persisteixen

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
docker compose exec tomcat ls logs

➜ Llista els registres de Tomcat dins del contenidor. Hi ha d'haver un localhost_access_log.*.txt amb les visites que has fet.

bash — administrador → servidor (SSH)
docker compose down

➜ Atura i esborra els contenidors i la xarxa. Els volums amb nom no s'esborren.

bash — administrador → servidor (SSH)
docker volume ls

➜ Llista els volums. aea3-docker_tomcat-logs continua existint, encara que ja no hi hagi cap contenidor.

bash — administrador → servidor (SSH)
docker compose up -d
docker compose exec tomcat sh -c 'tail -n 3 logs/localhost_access_log.*.txt'

➜ Torna a crear els contenidors i mostra les últimes visites. Hi continuen les d'abans del down: el volum ha conservat els registres.

💡

Si volguessis esborrar també els volums, faries docker compose down -v. Fes-ho només quan vulguis perdre aquestes dades.

Verificació

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
docker compose ps --format 'table {{.Service}}\t{{.Status}}\t{{.Ports}}'
docker network inspect aea3-docker_interna --format '{{range .Containers}}{{.Name}} {{.IPv4Address}}{{"\n"}}{{end}}'

➜ La primera resumeix l'estat i els ports dels serveis. La segona mostra quins contenidors hi ha a la xarxa interna i amb quina IP.

sortida esperada
SERVICE   STATUS          PORTS
apache    Up 2 minutes    0.0.0.0:80->80/tcp      # únic port publicat
tomcat    Up 2 minutes    8080/tcp                # ⚠ EL MÉS IMPORTANT: intern
app-tomcat 172.18.0.2/16                          # les IP poden variar
app-apache 172.18.0.3/16
Client
bash — client
curl -I http://www.app.local/sample/
curl -m 5 -s -o /dev/null http://192.168.1.10:8080/ && echo "8080: obert" || echo "8080: tancat"

➜ La primera mostra la capçalera de l'aplicació. La segona intenta arribar directament a Tomcat pel 8080.

sortida esperada
HTTP/1.1 200 OK
Server: Apache/2.4.NN (Unix)       # ⚠ "(Unix)": és l'Apache del contenidor, no el d'Ubuntu
...
8080: tancat                       # Tomcat no es veu des de fora

Llista de comprovació

  • docker compose ps mostra apache i tomcat en marxa, i només apache amb port publicat.
  • http://www.app.local/sample/ funciona des del client i la capçalera Server diu (Unix).
  • Dins del contenidor apache, el nom tomcat es resol a una IP de la xarxa interna.
  • Copiar un .war a ./webapps el desplega sense reiniciar.
  • Després d'un docker compose down i up -d, els registres de Tomcat continuen al volum tomcat-logs.
  • El client no pot arribar al port 8080.

En acabar

Administrador → Servidor · per SSH
bash — administrador → servidor (SSH)
docker compose down
sudo systemctl start tomcat apache2

➜ Atura els contenidors i torna a engegar el Tomcat i l'Apache de l'A1, que tornen a ocupar els ports 80, 443 i 8080.
