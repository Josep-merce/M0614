Apache i Tomcat amb Docker

Faràs el mateix que a l'A1.2, Apache davant de Tomcat, però amb dos contenidors en una sola màquina, aixecats amb Docker Compose.

RA RA3 Una sola màquina Docker
0

Què faràs

  • Instal·lar Docker en una màquina Ubuntu.
  • Aixecar Apache i Tomcat en dos contenidors amb un sol fitxer: compose.yaml.
  • Obrir l'aplicació al navegador de la mateixa màquina.

Què necessites

  • Una sola màquina Ubuntu 26.04 amb Internet. Pot ser una màquina nova d'IsardVDI: no cal la xarxa de quatre màquines de l'A1.
  • Entendre què fa el proxy invers de l'A1.2: aquí fem el mateix, però amb contenidors.
1

Què és Docker

Un contenidor és un programa que s'executa amb tot el que necessita a dins (sistema, Java, configuració...). Es crea a partir d'una imatge: nosaltres farem servir les imatges oficials httpd (Apache) i tomcat.

Amb Docker Compose escrius en un fitxer, compose.yaml, quins contenidors vols i com es connecten, i els aixeques tots amb una sola ordre. A l'A1 necessitaves dues màquines per a Apache i Tomcat; aquí n'hi ha prou amb una.

2

Pas a pas

💡

Tota l'activitat es fa en una sola màquina: obre-hi un terminal i ves fent els passos en ordre.

2.1 · Instal·la Docker

La teva màquina
bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2

➜ Instal·la Docker i Docker Compose.

bash
sudo docker run --rm hello-world

➜ Prova Docker amb un contenidor de prova. Ha de sortir Hello from Docker!

2.2 · Prepara la carpeta i l'aplicació

La teva màquina
bash
mkdir -p ~/app/webapps
cd ~/app

➜ Crea la carpeta del projecte, app, amb una subcarpeta webapps per a les aplicacions, i hi entra.

bash
wget -P webapps https://tomcat.apache.org/tomcat-10.1-doc/appdev/sample/sample.war

➜ Baixa l'aplicació d'exemple de l'A1.1 dins de webapps.

2.3 · Escriu la configuració d'Apache

La teva màquina
bash
nano app.conf

➜ Crea el fitxer de configuració per al contenidor d'Apache. Escriu-hi:

app.conf
LoadModule proxy_module modules/mod_proxy.so
LoadModule proxy_http_module modules/mod_proxy_http.so

<VirtualHost *:80>
    ProxyPass        / http://tomcat:8080/
    ProxyPassReverse / http://tomcat:8080/
</VirtualHost>
  • Les dues línies LoadModule activen el proxy (a l'A1.2 ho feies amb a2enmod).
  • ProxyPass és el mateix de l'A1.2, però en lloc d'una IP hi ha tomcat: el nom del contenidor. Docker sap a quina IP és.

Desa (Ctrl+O, Enter) i surt (Ctrl+X).

2.4 · Escriu el compose.yaml

La teva màquina
bash
nano compose.yaml

➜ Crea el fitxer que diu quins contenidors volem. Escriu-hi:

compose.yaml
services:

  tomcat:
    image: tomcat:10.1
    volumes:
      - ./webapps:/usr/local/tomcat/webapps

  apache:
    image: httpd:2.4
    ports:
      - "8080:80"
    volumes:
      - ./app.conf:/usr/local/apache2/conf/extra/app.conf
    command: httpd-foreground -c "Include conf/extra/app.conf"
  • tomcat i apache → els dos contenidors (serveis). Docker els connecta per una xarxa interna i cadascú troba l'altre pel nom.
  • image → la imatge oficial de la qual surt cada contenidor.
  • volumes → posa una carpeta o fitxer de la màquina dins del contenidor: la nostra carpeta webapps passa a ser el webapps de Tomcat, i el nostre app.conf entra a la configuració d'Apache.
  • ports: "8080:80" → el port 8080 de la màquina va al port 80 del contenidor d'Apache. El primer número és el de la màquina; el segon, el de dins del contenidor. No xoca amb el 8080 de Tomcat: aquell és dins del seu contenidor i no es publica. Tomcat no té ports: només s'hi arriba a través d'Apache.
  • command → engega Apache i li diu que llegeixi també el nostre app.conf.
⚠️

En YAML els espais compten: copia el sagnat exactament, sense tabuladors.

Desa i surt.

2.5 · Aixeca els contenidors

La teva màquina
bash
sudo docker compose up -d

➜ Baixa les dues imatges (el primer cop triga una mica) i engega els dos contenidors en segon pla (-d).

bash
sudo docker compose ps

➜ Llista els contenidors. Tots dos han d'estar Up. L'apache mostra 0.0.0.0:8080->80/tcp i el tomcat només 8080/tcp (intern).

2.6 · Prova-ho

La teva màquina
🔎 Comprova-ho al navegador de la mateixa màquina http://localhost:8080/sample/

Obre-ho al navegador d'aquesta mateixa màquina. Ha de sortir l'aplicació d'exemple de l'A1.1: has entrat pel contenidor d'Apache i Apache l'ha demanada al de Tomcat.

Si la màquina no té escriptori, prova-ho des del terminal:

bash
curl http://localhost:8080/sample/

➜ Ha de sortir el codi HTML de la pàgina, amb el títol Sample "Hello, World" Application.

2.7 · En acabar

La teva màquina
bash
sudo docker compose down

➜ Atura i esborra els dos contenidors. Els fitxers de ~/app es queden: amb sudo docker compose up -d els tornes a aixecar.

3

Comprova que ho tens tot

  • sudo docker compose ps mostra els dos contenidors Up.
  • http://localhost:8080/sample/ mostra l'aplicació.
  • Saps explicar per què a app.conf hi ha tomcat en lloc d'una IP.
4

Si alguna cosa falla

ProblemaSolució
up diu port is already allocated o address already in useJa hi ha un altre programa al port 8080 de la màquina, per exemple el Tomcat de l'A1.1. Atura'l (sudo systemctl stop tomcat10) i torna a fer sudo docker compose up -d.
up dona un error de YAMLRevisa el sagnat de compose.yaml: espais, no tabuladors, exactament com a l'exemple.
El contenidor apache no està UpMira l'error amb sudo docker compose logs apache. Normalment és una falta d'escriptura a app.conf.
503 Service UnavailableTomcat encara arrenca o ha fallat: espera uns segons i mira sudo docker compose logs tomcat.
/sample/ dona error 404Comprova que sample.war és a ~/app/webapps (ls webapps) i espera uns segons que Tomcat el desplegui.
