Tomcat a una EC2 del Learner Lab

Portaràs al núvol el servidor d'aplicacions de l'A1: llançaràs una EC2 Ubuntu, t'hi connectaràs per SSH, hi instal·laràs Java 21 i Tomcat 10.1 com a servei, i hi posaràs Apache davant amb HTTPS per servir la mateixa aplicació des de la IP pública.

RA RA3 CA 3.2 · 3.6 · 3.7 · 3.8
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Llançar una EC2 Ubuntu t3.micro al Learner Lab amb el parell de claus vockey.
  • Obrir només els ports 22, 80 i 443 amb un grup de seguretat.
  • Repetir al núvol, per SSH, la instal·lació de l'A1: Java 21, Tomcat 10.1 com a servei i l'aplicació sample.war.
  • Posar Apache amb HTTPS davant de Tomcat i deixar Tomcat escoltant només a 127.0.0.1.

Prerequisits

  • Accés a AWS Academy · Learner Lab (ja el vas fer servir a l'AEA2).
  • Un terminal a la teva màquina per fer ssh, com a l'AEA2 · A3.
  • Haver fet les activitats A1.0–A1.3: aquí les ordres són les mateixes, però més resumides.
⚠️

Al Learner Lab només pots treballar a les regions us-east-1 (N. Virginia) i us-west-2 (Oregon). En aquesta activitat farem servir us-east-1. El laboratori té temps i pressupost limitats: fes les captures a mesura que avances i, en acabar, atura la instància (pas 3).

1

Context i teoria mínima

Al final de l'A1.3 tenies al servidor de l'aula una arquitectura completa: Apache amb HTTPS a la porta i Tomcat darrere, escoltant només dins del servidor. Ara la muntaràs igual en una EC2. Hi ha tres diferències respecte a l'aula:

  • No hi ha xarxa interna ni màquina d'administrador. Administres l'EC2 directament des de la teva màquina, per SSH amb una clau.
  • El tallafoc és el grup de seguretat. Només hi obrirem el 22, el 80 i el 443. El 8080 quedarà tancat dues vegades: al grup de seguretat i a Tomcat (address="127.0.0.1").
  • No hi ha nom de domini. L'accés és per la IP pública, que canvia cada cop que s'engega la instància. El certificat s'emetrà per a aquesta IP i la redirecció a HTTPS no podrà dur cap adreça escrita.

Pas a pas guiat

Part 1 · La instància

2.1 · Obre el Learner Lab a us-east-1

  1. Entra a AWS Academy i obre el teu Learner Lab.
  2. Prem Start Lab i espera que el punt del costat d'AWS es posi verd.
  3. Fes clic a AWS per obrir la consola.
  4. A dalt a la dreta, comprova que la regió és N. Virginia (us-east-1). Si no ho és, canvia-la.

2.2 · Llança l'EC2

  1. Cerca EC2, entra-hi i prem Launch instance.
  2. Name: tomcat-aea3.
  3. Application and OS Images: tria Ubuntu i, a la llista, Ubuntu Server 24.04 LTS, arquitectura 64-bit (x86).
  4. Instance type: t3.micro.
  5. Key pair (login): tria vockey. No en creïs cap de nova.
  6. Network settings → Create security group, i marca els tres ports següents.
  7. Configure storage: deixa els 8 GiB per defecte.
  8. Prem Launch instance.
PortOpció a marcarPer a què
22Allow SSH traffic from · AnywhereAdministrar l'EC2 des del teu terminal.
80Allow HTTP traffic from the internetRebre l'HTTP i redirigir-lo a l'HTTPS.
443Allow HTTPS traffic from the internetAccés web xifrat.
💡

No obris el 8080: a l'A1.3 vas aprendre que Tomcat no ha d'estar exposat. Quan la instància estigui Running, copia'n la Public IPv4 address: és la IP-PUBLICA d'aquesta guia.

2.3 · Descarrega la clau i connecta't per SSH

  1. Torna a la pàgina del Learner Lab i prem AWS Details.
  2. Al costat de SSH key, prem Download PEM. Es descarrega labsuser.pem.

Obre un terminal a la teva màquina, a la carpeta on s'ha desat la clau:

bash — la teva màquina
chmod 400 labsuser.pem

➜ Deixa la clau llegible només per a tu. SSH no accepta claus amb permisos oberts.

bash — la teva màquina
ssh -i labsuser.pem ubuntu@IP-PUBLICA

➜ Obre la sessió SSH a l'EC2. -i indica la clau i ubuntu és l'usuari de les AMI d'Ubuntu. Accepta la fingerprint amb yes.

💻→

A partir d'aquí, tot el que escrius s'executa a l'EC2. El prompt serà del tipus ubuntu@ip-172-31-…. Per tornar a la teva màquina, escriu exit.

Part 2 · Java i Tomcat

2.4 · Instal·la Java 21

bash — la teva màquina → EC2 (SSH)
sudo apt update
sudo apt install -y openjdk-21-jdk-headless

➜ Actualitza la llista de paquets i instal·la el JDK 21 sense interfície gràfica, com a l'A1.0.

bash — la teva màquina → EC2 (SSH)
java -version
readlink -f $(which java)

➜ La primera ha de dir 21. La segona mostra la ruta real de Java: /usr/lib/jvm/java-21-openjdk-amd64/bin/java. Sense el /bin/java final, és el JAVA_HOME que posaràs al servei.

2.5 · Instal·la Tomcat 10.1

bash — la teva màquina → EC2 (SSH)
sudo mkdir /opt/tomcat
sudo useradd -r -U -d /opt/tomcat -s /usr/sbin/nologin tomcat

➜ Crea la carpeta de Tomcat i l'usuari de sistema tomcat, sense terminal, com a l'A1.1.

bash — la teva màquina → EC2 (SSH)
VER=$(curl -s https://dlcdn.apache.org/tomcat/tomcat-10/ | grep -oP 'v\K10\.1\.[0-9]+' | sort -V | tail -1)
echo $VER

➜ Esbrina la versió 10.1 més recent i la desa a VER. Si surt buida, posa-la a mà mirant tomcat.apache.org/download-10.cgi: VER=10.1.NN.

bash — la teva màquina → EC2 (SSH)
cd /tmp
wget https://dlcdn.apache.org/tomcat/tomcat-10/v$VER/bin/apache-tomcat-$VER.tar.gz
wget https://downloads.apache.org/tomcat/tomcat-10/v$VER/bin/apache-tomcat-$VER.tar.gz.sha512
sha512sum -c apache-tomcat-$VER.tar.gz.sha512

➜ Descarrega el paquet i la seva suma SHA-512, i comprova que coincideixen. L'última ordre ha de respondre OK.

bash — la teva màquina → EC2 (SSH)
sudo tar -xzf apache-tomcat-$VER.tar.gz -C /opt/tomcat --strip-components=1
sudo chown -R tomcat:tomcat /opt/tomcat

➜ Descomprimeix Tomcat directament a /opt/tomcat i fa que tot sigui de l'usuari tomcat.

2.6 · Tanca el 8080 abans d'engegar

A l'A1.3 vas editar server.xml amb nano. Aquí ho faràs amb una sola ordre, abans que Tomcat arrenqui per primer cop:

bash — la teva màquina → EC2 (SSH)
sudo sed -i 's|<Connector port="8080"|<Connector port="8080" address="127.0.0.1"|' /opt/tomcat/conf/server.xml
sudo grep -n '<Connector port="8080"' /opt/tomcat/conf/server.xml

➜ La primera afegeix address="127.0.0.1" al connector HTTP. La segona ho comprova: la línia ha de sortir com <Connector port="8080" address="127.0.0.1" protocol="HTTP/1.1".

2.7 · Crea el servei de systemd

bash — la teva màquina → EC2 (SSH)
sudo nano /etc/systemd/system/tomcat.service

➜ Crea el fitxer del servei. És el de l'A1.1 amb un canvi: menys memòria, perquè la t3.micro només té 1 GiB.

/etc/systemd/system/tomcat.service
[Unit]
Description=Apache Tomcat 10.1
After=network.target

[Service]
Type=forking
User=tomcat
Group=tomcat

Environment="JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64"
Environment="CATALINA_HOME=/opt/tomcat"
Environment="CATALINA_BASE=/opt/tomcat"
Environment="CATALINA_PID=/opt/tomcat/temp/tomcat.pid"
Environment="CATALINA_OPTS=-Xms128M -Xmx384M"       # CANVI: t3.micro = 1 GiB

ExecStart=/opt/tomcat/bin/startup.sh
ExecStop=/opt/tomcat/bin/shutdown.sh

[Install]
WantedBy=multi-user.target
bash — la teva màquina → EC2 (SSH)
sudo systemctl daemon-reload
sudo systemctl enable --now tomcat
systemctl is-active tomcat

➜ Fa que systemd llegeixi el servei nou, l'habilita i l'engega. L'última ha de respondre active.

2.8 · Desplega l'aplicació

bash — la teva màquina → EC2 (SSH)
sudo install -o tomcat -g tomcat -m 644 /opt/tomcat/webapps/docs/appdev/sample/sample.war /opt/tomcat/webapps/

➜ Copia l'aplicació d'exemple que porta Tomcat a webapps, amb l'usuari i els permisos correctes, com a l'A1.1. Tomcat la desplega sola en pocs segons.

bash — la teva màquina → EC2 (SSH)
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/sample/

➜ Prova l'aplicació des de dins de l'EC2, directament a Tomcat. Ha de respondre 200. Des de fora encara no hi pots arribar: falta Apache.

Part 3 · Apache amb HTTPS al davant

2.9 · Instal·la Apache i activa els mòduls

bash — la teva màquina → EC2 (SSH)
sudo apt install -y apache2
sudo a2enmod proxy proxy_http ssl rewrite

➜ Instal·la Apache i activa quatre mòduls: proxy i proxy_http per al proxy invers (A1.2), ssl per a l'HTTPS (A1.3) i rewrite per a la redirecció, que aquí no pot dur la IP escrita.

bash — la teva màquina → EC2 (SSH)
sudo a2dissite 000-default

➜ Desactiva el lloc per defecte d'Apache. Com que accedim per IP i no per nom, si el deixéssim actiu atendria totes les peticions del port 80 en lloc del nostre.

2.10 · Genera el certificat per a la IP pública

bash — la teva màquina → EC2 (SSH)
IP=$(curl -s https://checkip.amazonaws.com) && echo $IP

➜ Pregunta a un servei d'AWS quina és la IP pública de l'EC2 i la desa a IP. Ha de coincidir amb la de la consola.

bash — la teva màquina → EC2 (SSH)
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/app.key \
  -out /etc/ssl/certs/app.crt \
  -subj "/C=ES/ST=Barcelona/L=Barcelona/O=Institut La Merce/OU=DAW/CN=$IP" \
  -addext "subjectAltName=IP:$IP"

➜ Genera el certificat autofirmat com a l'A1.3, però emès per a la IP pública: subjectAltName=IP: indica que el nom del certificat és una adreça IP.

2.11 · Crea el host virtual

bash — la teva màquina → EC2 (SSH)
sudo nano /etc/apache2/sites-available/app.conf

➜ Crea el fitxer del host virtual. Escriu-hi aquest contingut:

app.conf
# --- Port 80: redirigeix a HTTPS, sigui quina sigui la IP ---
<VirtualHost *:80>
    RewriteEngine On
    RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]
</VirtualHost>

# --- Port 443: HTTPS + proxy cap a Tomcat ---
<VirtualHost *:443>
    SSLEngine on
    SSLCertificateFile    /etc/ssl/certs/app.crt
    SSLCertificateKeyFile /etc/ssl/private/app.key

    ProxyRequests     Off
    ProxyPreserveHost On

    ProxyPass /manager      !               # les eines d'administració no es publiquen a Internet
    ProxyPass /host-manager !

    ProxyPass        / http://127.0.0.1:8080/
    ProxyPassReverse / http://127.0.0.1:8080/

    ErrorLog  ${APACHE_LOG_DIR}/app_error.log
    CustomLog ${APACHE_LOG_DIR}/app_access.log combined
</VirtualHost>
💡

A l'A1.3 la redirecció era Redirect permanent / https://www.app.local/, amb el nom escrit. Aquí la IP pot canviar, així que fem servir mod_rewrite: %{HTTP_HOST} és l'adreça que ha escrit l'usuari i %{REQUEST_URI}, la ruta. També excloem el Manager: en un servidor a Internet, no s'ha de publicar.

bash — la teva màquina → EC2 (SSH)
sudo a2ensite app
sudo apache2ctl configtest
sudo systemctl restart apache2

➜ Activa el host virtual, en revisa la sintaxi (ha de dir Syntax OK) i reinicia Apache perquè carregui els mòduls i obri el 443.

2.12 · Obre l'aplicació des del navegador

🔎 Comprova-ho al navegador http://IP-PUBLICA/sample/

Escriu-la amb http. El navegador ha de saltar a https://IP-PUBLICA/sample/ i mostrar l'avís de seguretat del certificat autofirmat. Accepta'l (a Firefox: Avançat → Accepta el risc). Ha de sortir l'aplicació d'exemple, ara des d'AWS. Al cadenat, el certificat és per a la teva IP-PUBLICA i l'emissor és Institut La Merce.

🔎 Comprova-ho al navegador https://IP-PUBLICA/

Ha de sortir la pàgina d'inici de Tomcat. Si hi prems Manager App, has de rebre un 404: Apache no el publica.

Verificació

Connectat per SSH a l'EC2:

bash — la teva màquina → EC2 (SSH)
systemctl is-enabled tomcat apache2
sudo ss -tlnp | grep -E ':(80|443|8080) '

➜ La primera comprova que els dos serveis arrencaran sols amb la instància. La segona mostra on escolta cada un.

sortida esperada
enabled                                                                  # tomcat
enabled                                                                  # apache2
LISTEN 0 511  *:80                     *:*  users:(("apache2",...))       # Apache HTTP (redirecció)
LISTEN 0 511  *:443                    *:*  users:(("apache2",...))       # Apache HTTPS
LISTEN 0 100  [::ffff:127.0.0.1]:8080  *:*  users:(("java",...))          # ⚠ Tomcat només dins de l'EC2

Des de la teva màquina (substitueix IP-PUBLICA):

bash — la teva màquina
curl -I http://IP-PUBLICA/sample/
curl -k -I https://IP-PUBLICA/sample/
curl -m 5 -s -o /dev/null http://IP-PUBLICA:8080/ && echo "8080: obert" || echo "8080: tancat"

➜ La primera prova la redirecció, la segona l'HTTPS (-k accepta el certificat autofirmat) i la tercera intenta arribar a Tomcat directament.

sortida esperada
HTTP/1.1 301 Moved Permanently
Location: https://IP-PUBLICA/sample/       # redirecció a HTTPS
...
HTTP/1.1 200 OK                            # ⚠ EL MÉS IMPORTANT: l'aplicació respon per HTTPS
Server: Apache/2.4.NN (Ubuntu)             # l'Apache de l'EC2
...
8080: tancat                               # Tomcat no és accessible des d'Internet

Llista de comprovació

  • L'EC2 és a us-east-1, és t3.micro, fa servir la clau vockey i té un grup de seguretat amb només 22, 80 i 443.
  • Hi entres per SSH amb labsuser.pem i l'usuari ubuntu.
  • java -version diu 21 i Tomcat 10.1 funciona com a servei amb l'usuari tomcat.
  • Tomcat escolta només a 127.0.0.1:8080 i el 8080 no respon des de fora.
  • http://IP-PUBLICA/sample/ redirigeix a https://IP-PUBLICA/sample/ i mostra l'aplicació, amb un certificat emès per a la IP pública.
  • /manager no es publica.

En acabar

⚠️

Quan hagis fet les captures, a la consola d'EC2 selecciona la instància i fes Instance state → Stop instance. En tornar-la a engegar tindrà una IP pública nova: Tomcat i Apache arrencaran sols, però hauràs de tornar a generar el certificat (pas 2.10) i fer sudo systemctl reload apache2. Quan acabis l'AEA3, fes Terminate instance per no gastar pressupost.
