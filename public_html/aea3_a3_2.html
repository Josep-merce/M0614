Tomcat a una EC2 amb Docker Compose

Portaràs al núvol l'arquitectura de l'A2: llançaràs una EC2 Ubuntu al Learner Lab, t'hi connectaràs per SSH i hi aixecaràs Apache i Tomcat amb Docker Compose. Hi afegiràs HTTPS i la redirecció des d'HTTP, i serviràs la mateixa aplicació des de la IP pública.

RA RA3 CA 3.2 · 3.6 · 3.8
0

Objectius i prerequisits

En aquesta activitat aprendràs a:

  • Llançar una EC2 Ubuntu t3.micro al Learner Lab amb el parell de claus vockey.
  • Obrir només els ports 22, 80 i 443 amb un grup de seguretat.
  • Instal·lar Docker a l'EC2 i aixecar-hi el mateix projecte de Compose de l'A2.
  • Afegir HTTPS al contenidor d'Apache i redirigir l'HTTP cap a l'HTTPS.

Prerequisits

  • Accés a AWS Academy · Learner Lab (ja el vas fer servir a l'AEA2).
  • Un terminal a la teva màquina per fer ssh, com a l'AEA2 · A3.
  • Haver fet l'A2: aquí tornaràs a escriure el mateix compose.yaml, amb dos canvis.
  • Haver fet l'A3.1: allà vas instal·lar Tomcat a mà a una EC2; aquí faràs el mateix amb contenidors.
⚠️

Al Learner Lab només pots treballar a les regions us-east-1 (N. Virginia) i us-west-2 (Oregon). En aquesta activitat farem servir us-east-1. El laboratori té temps i pressupost limitats: fes les captures a mesura que avances i, en acabar, atura la instància (pas 3).

1

Context i teoria mínima

A l'A2 tota l'arquitectura cabia en una carpeta: compose.yaml, la configuració d'Apache i el .war. Aquest és l'avantatge dels contenidors: per portar-la al núvol no cal tornar a instal·lar Java ni Tomcat, només cal Docker a la màquina de destinació.

Respecte a l'A2, hi farem dos canvis:

  • HTTPS al contenidor d'Apache. Ara el servidor és a Internet: tot ha d'anar xifrat. El certificat serà autofirmat, emès per a la IP pública de l'EC2, ja que no tenim nom de domini.
  • Límit de memòria de Java. Una t3.micro té només 1 GiB de RAM. Li direm a Tomcat que no en faci servir més de 384 MB.

2

Pas a pas guiat

Part 1 · La instància

2.1 · Obre el Learner Lab a us-east-1

  1. Entra a AWS Academy i obre el teu Learner Lab.
  2. Prem Start Lab i espera que el punt del costat d'AWS es posi verd.
  3. Fes clic a AWS per obrir la consola.
  4. A dalt a la dreta, comprova que la regió és N. Virginia (us-east-1). Si no ho és, canvia-la.

2.2 · Llança l'EC2

  1. Cerca EC2, entra-hi i prem Launch instance.
  2. Name: tomcat-aea3.
  3. Application and OS Images: tria Ubuntu i, a la llista, Ubuntu Server 24.04 LTS, arquitectura 64-bit (x86).
  4. Instance type: t3.micro.
  5. Key pair (login): tria vockey. No en creïs cap de nova.
  6. Network settings → Create security group, i marca els tres ports següents.
  7. Configure storage: deixa els 8 GiB per defecte.
  8. Prem Launch instance.
PortOpció a marcarPer a què
22Allow SSH traffic from · AnywhereAdministrar l'EC2 des del teu terminal.
80Allow HTTP traffic from the internetRebre l'HTTP i redirigir-lo a l'HTTPS.
443Allow HTTPS traffic from the internetAccés web xifrat.
💡

No obris el 8080. Tomcat no ha de ser accessible des de fora: només Apache hi parla, per la xarxa interna de Docker. Quan la instància estigui Running, copia'n la Public IPv4 address: és la IP-PUBLICA d'aquesta guia.

2.3 · Descarrega la clau i connecta't per SSH

  1. Torna a la pàgina del Learner Lab i prem AWS Details.
  2. Al costat de SSH key, prem Download PEM. Es descarrega labsuser.pem.

Obre un terminal a la teva màquina, a la carpeta on s'ha desat la clau:

bash — la teva màquina
chmod 400 labsuser.pem

➜ Deixa la clau llegible només per a tu. SSH no accepta claus amb permisos oberts.

bash — la teva màquina
ssh -i labsuser.pem ubuntu@IP-PUBLICA

➜ Obre la sessió SSH a l'EC2. -i indica la clau i ubuntu és l'usuari de les AMI d'Ubuntu. Accepta la fingerprint amb yes.

💻→

A partir d'aquí, tot el que escrius s'executa a l'EC2. El prompt serà del tipus ubuntu@ip-172-31-…. Per tornar a la teva màquina, escriu exit.

Part 2 · Docker i el projecte

2.4 · Instal·la Docker a l'EC2

bash — la teva màquina → EC2 (SSH)
sudo apt update

➜ Actualitza la llista de paquets disponibles.

bash — la teva màquina → EC2 (SSH)
sudo apt install -y docker.io docker-compose-v2

➜ Instal·la Docker i Docker Compose dels repositoris d'Ubuntu, igual que a l'A2.

bash — la teva màquina → EC2 (SSH)
sudo usermod -aG docker ubuntu

➜ Afegeix l'usuari ubuntu al grup docker. Surt amb exit i torna a entrar amb el mateix ssh perquè s'apliqui.

bash — la teva màquina → EC2 (SSH)
docker compose version

➜ Comprova que Compose funciona sense sudo.

2.5 · Prepara la configuració d'Apache

bash — la teva màquina → EC2 (SSH)
mkdir -p ~/aea3-docker/apache/certs ~/aea3-docker/webapps && cd ~/aea3-docker

➜ Crea la carpeta del projecte, com a l'A2, i a més apache/certs per al certificat.

bash — la teva màquina → EC2 (SSH)
docker run --rm httpd:2.4 cat /usr/local/apache2/conf/httpd.conf > apache/httpd.conf

➜ Descarrega la imatge httpd:2.4 i en desa la configuració per defecte.

bash — la teva màquina → EC2 (SSH)
sed -i \
  -e 's|^#LoadModule proxy_module |LoadModule proxy_module |' \
  -e 's|^#LoadModule proxy_http_module |LoadModule proxy_http_module |' \
  -e 's|^#LoadModule ssl_module |LoadModule ssl_module |' \
  -e 's|^#LoadModule rewrite_module |LoadModule rewrite_module |' \
  apache/httpd.conf
echo 'Include conf/extra/app.conf' >> apache/httpd.conf

➜ Activa els mòduls de proxy, com a l'A2, i dos més: ssl per a l'HTTPS i rewrite per a la redirecció. Després afegeix l'Include del host virtual.

bash — la teva màquina → EC2 (SSH)
grep -cE '^LoadModule (proxy|proxy_http|ssl|rewrite)_module ' apache/httpd.conf

➜ Compta quantes d'aquestes quatre línies estan actives. Ha de respondre 4.

2.6 · Genera el certificat per a la IP pública

bash — la teva màquina → EC2 (SSH)
IP=$(curl -s https://checkip.amazonaws.com) && echo $IP

➜ Pregunta a un servei d'AWS quina és la IP pública de l'EC2 i la desa a la variable IP. Ha de coincidir amb la de la consola.

bash — la teva màquina → EC2 (SSH)
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout apache/certs/app.key \
  -out apache/certs/app.crt \
  -subj "/C=ES/ST=Barcelona/L=Barcelona/O=Institut La Merce/OU=DAW/CN=$IP" \
  -addext "subjectAltName=IP:$IP"

➜ Genera el certificat autofirmat i la clau, com a l'A1.3. Ara el nom del certificat és la IP pública: subjectAltName=IP: indica que és una adreça IP i no un nom de domini. No cal sudo: els fitxers queden dins del projecte.

2.7 · Escriu el host virtual amb HTTPS

bash — la teva màquina → EC2 (SSH)
nano apache/app.conf

➜ Crea el fitxer del host virtual. Escriu-hi aquest contingut:

apache/app.conf
Listen 443                                             # el httpd.conf de la imatge només escolta el 80

# --- Port 80: redirigeix a HTTPS, sigui quina sigui la IP ---
<VirtualHost *:80>
    RewriteEngine On
    RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]
</VirtualHost>

# --- Port 443: HTTPS + proxy cap a Tomcat ---
<VirtualHost *:443>
    SSLEngine on
    SSLCertificateFile    /usr/local/apache2/conf/certs/app.crt
    SSLCertificateKeyFile /usr/local/apache2/conf/certs/app.key

    ProxyRequests     Off
    ProxyPreserveHost On
    ProxyPass        / http://tomcat:8080/
    ProxyPassReverse / http://tomcat:8080/
</VirtualHost>
💡

A l'A1.3 la redirecció era Redirect permanent / https://www.app.local/, amb el nom escrit. Aquí no hi ha nom i la IP pública pot canviar, així que fem servir mod_rewrite: %{HTTP_HOST} és l'adreça que ha escrit l'usuari i %{REQUEST_URI}, la ruta. Així la redirecció funciona amb qualsevol IP.

2.8 · Posa l'aplicació i escriu el compose.yaml

bash — la teva màquina → EC2 (SSH)
wget -P webapps https://tomcat.apache.org/tomcat-10.1-doc/appdev/sample/sample.war

➜ Descarrega la mateixa aplicació d'exemple de l'A1 i l'A2 a la carpeta webapps.

bash — la teva màquina → EC2 (SSH)
nano compose.yaml

➜ Crea el fitxer de Compose. És el de l'A2 amb els canvis marcats:

compose.yaml
services:

  tomcat:
    image: tomcat:10.1-jdk21
    container_name: app-tomcat
    restart: unless-stopped
    environment:
      CATALINA_OPTS: "-Xms128m -Xmx384m"            # NOU: Java no passa de 384 MB (t3.micro = 1 GiB)
    volumes:
      - ./webapps:/usr/local/tomcat/webapps
      - tomcat-logs:/usr/local/tomcat/logs
    networks:
      - interna

  apache:
    image: httpd:2.4
    container_name: app-apache
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"                                   # NOU: HTTPS
    volumes:
      - ./apache/httpd.conf:/usr/local/apache2/conf/httpd.conf:ro
      - ./apache/app.conf:/usr/local/apache2/conf/extra/app.conf:ro
      - ./apache/certs:/usr/local/apache2/conf/certs:ro   # NOU: certificat i clau
    depends_on:
      - tomcat
    networks:
      - interna

networks:
  interna:

volumes:
  tomcat-logs:
bash — la teva màquina → EC2 (SSH)
docker compose config --quiet && echo "compose.yaml correcte"

➜ Valida el fitxer sense engegar res.

Part 3 · En marxa

2.9 · Aixeca els contenidors

bash — la teva màquina → EC2 (SSH)
docker compose up -d

➜ Descarrega la imatge de Tomcat, crea la xarxa, el volum i els dos contenidors, i els engega en segon pla.

bash — la teva màquina → EC2 (SSH)
docker compose logs apache | tail -n 5

➜ Mostra les últimes línies del registre d'Apache. Ha de sortir resuming normal operations. Si surt un error del certificat o de SSLEngine, revisa els passos 2.5 i 2.6.

2.10 · Obre l'aplicació des del navegador

🔎 Comprova-ho al navegador http://IP-PUBLICA/sample/

Escriu-la amb http. El navegador ha de saltar a https://IP-PUBLICA/sample/ i mostrar l'avís de seguretat del certificat autofirmat. Accepta'l (a Firefox: Avançat → Accepta el risc). Ha de sortir l'aplicació d'exemple, ara servida des d'AWS. Al cadenat, el certificat és per a la teva IP-PUBLICA i l'emissor és Institut La Merce.

🔎 Comprova-ho al navegador http://IP-PUBLICA:8080/

Ha de quedar carregant i acabar amb un error de temps d'espera: el grup de seguretat no deixa passar el 8080, i a més Docker no el publica.

3

Verificació

Connectat per SSH a l'EC2:

bash — la teva màquina → EC2 (SSH)
docker compose ps --format 'table {{.Service}}\t{{.Status}}\t{{.Ports}}'
docker stats --no-stream --format 'table {{.Name}}\t{{.MemUsage}}'

➜ La primera mostra els serveis i els seus ports. La segona fa una foto de la memòria que fa servir cada contenidor.

sortida esperada
SERVICE   STATUS         PORTS
apache    Up 3 minutes   0.0.0.0:80->80/tcp, 0.0.0.0:443->443/tcp   # ⚠ 80 i 443 publicats
tomcat    Up 3 minutes   8080/tcp                                   # intern
NAME         MEM USAGE / LIMIT
app-tomcat   2NN MiB / 9NN MiB          # per sota del límit de Java
app-apache   NN MiB / 9NN MiB

Des de la teva màquina (substitueix IP-PUBLICA):

bash — la teva màquina
curl -I http://IP-PUBLICA/sample/
curl -k -I https://IP-PUBLICA/sample/
curl -m 5 -s -o /dev/null http://IP-PUBLICA:8080/ && echo "8080: obert" || echo "8080: tancat"

➜ La primera prova la redirecció, la segona l'HTTPS (-k accepta el certificat autofirmat) i la tercera intenta arribar a Tomcat directament.

sortida esperada
HTTP/1.1 301 Moved Permanently
Location: https://IP-PUBLICA/sample/       # redirecció a HTTPS
...
HTTP/1.1 200 OK                            # ⚠ EL MÉS IMPORTANT: l'aplicació respon per HTTPS
Server: Apache/2.4.NN (Unix)               # l'Apache del contenidor
...
8080: tancat                               # Tomcat no és accessible des d'Internet

Llista de comprovació

  • L'EC2 és a us-east-1, és t3.micro, fa servir la clau vockey i té un grup de seguretat amb només 22, 80 i 443.
  • Hi entres per SSH amb labsuser.pem i l'usuari ubuntu.
  • docker compose ps mostra apache amb els ports 80 i 443, i tomcat sense cap port publicat.
  • http://IP-PUBLICA/sample/ redirigeix a https://IP-PUBLICA/sample/ i mostra l'aplicació.
  • El certificat està emès per a la IP pública de l'EC2.
  • El port 8080 no respon des de fora.

En acabar

⚠️

Quan hagis fet les captures, a la consola d'EC2 selecciona la instància i fes Instance state → Stop instance. Una instància aturada no consumeix hores de càlcul. En tornar-la a engegar tindrà una IP pública nova: els contenidors s'aixecaran sols (restart: unless-stopped), però hauràs de tornar a generar el certificat (pas 2.6) i fer docker compose restart apache. Quan acabis l'AEA3, fes Terminate instance per no gastar pressupost.
