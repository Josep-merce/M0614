Primeres passes amb Git i GitHub

El Propietari crearà el repositori compartit de la parella amb una pàgina web bàsica, i el Col·laborador s'hi afegirà i en clonarà una còpia. Al final, tots dos tindreu exactament els mateixos fitxers al vostre ordinador.

Objectius i prerequisits

Aquesta és la primera de les 4 activitats de l'AEA6, i totes es fan en parella amb els mateixos dos rols:

  • Propietari: crea el repositori compartit i en manté el control principal.
  • Col·laborador: s'hi afegeix i hi treballa des del seu propi compte de GitHub.

Decidiu ara qui farà de qui, i mantingueu el mateix rol a la resta d'activitats de l'AEA6 (A2 a A6).

Prerequisits

  • Cada membre de la parella ha de tenir un compte de GitHub. Si encara no en teniu, aneu a github.com/signup i creeu-vos-en un (és gratuït: només us demanarà un correu electrònic, una contrasenya i un nom d'usuari).
  • Un editor de codi. Podeu fer servir Visual Studio Code o NetBeans, el que us vagi millor.
  • Un terminal (el que ja ve al sistema).

Repositori de treball

L'AEA6 és independent de la resta del mòdul: no fem servir el repositori personal del curs ni cap branca aea6. Tota la feina (aquesta activitat i les 3 següents) es fa en un únic repositori compartit entre els dos membres de la parella, anomenat aea6-usuari1-usuari2 (per exemple, aea6-marta-jordi). Aquest mateix repositori és el que s'entrega — no cal copiar res enlloc més.

1

Context i teoria mínima

Què farem en aquesta activitat

Instal·lareu Git al vostre ordinador, el Propietari crearà un repositori a GitHub i hi pujarà una pàgina web molt bàsica. El Col·laborador s'hi afegirà com a segon usuari, en clonarà una còpia i comprovareu que tots dos veieu el mateix.

Termes nous que apareixeran:

  • Git: un programa que fem servir al terminal per guardar l'historial dels canvis del projecte. Funciona al vostre ordinador (en local), sense necessitat d'internet.
  • GitHub: un servei web (una pàgina d'internet) que allotja una còpia central del projecte perquè diverses persones puguin treballar-hi i sincronitzar els canvis. Fa d'"intermediari" entre els vostres dos ordinadors.
  • Repositori: la carpeta del projecte, amb tots els fitxers i l'historial de canvis. En tindreu una còpia a GitHub (remota) i una còpia a cada ordinador (local).
  • Commit: una "fotografia" desada d'un moment concret del projecte, amb un missatge que explica què s'ha canviat.
  • Clone: descarregar per primera vegada una còpia completa del repositori des de GitHub al teu ordinador.
  • Push: enviar els teus commits des del teu ordinador cap a GitHub.
2

Pas a pas guiat

Anirem molt a poc a poc: cada comanda surt sola, amb una explicació de què fa exactament abans de continuar amb la següent.

2.1 · Instal·lar Git

Ambdós

Cadascú al seu ordinador:

bash
sudo apt update

➜ apt update actualitza la llista de programes disponibles per instal·lar. No instal·la res encara, només mira quines versions hi ha.

bash
sudo apt install -y git

➜ apt install git instal·la el programa Git. El -y respon "sí" automàticament quan et pregunti si vols continuar.

2.2 · Configurar el teu nom i correu

Ambdós

Cada commit que facis queda signat amb un nom i un correu. Ho configures una sola vegada:

bash
git config --global user.name "El teu nom"

➜ git config --global desa una preferència que s'aplicarà a tots els projectes del teu ordinador, no només aquest. user.name és el nom que apareixerà als teus commits.

bash
git config --global user.email "el-teu-correu@exemple.com"

➜ El mateix, però per al correu. Fes servir el mateix correu que tens associat al teu compte de GitHub.

2.3 · Crear el repositori a GitHub

Propietari
  1. Ves a GitHub i fes clic a New repository.
  2. Al camp "Repository name", escriu aea6-usuari1-usuari2 (substituint pels vostres dos noms d'usuari de GitHub).
  3. Deixa la marca Public seleccionada.
  4. No marquis "Add a README file" ni cap altra opció: el repositori ha de quedar completament buit.
  5. Fes clic a Create repository.

2.4 · Clonar el repositori al teu ordinador

Propietari
bash
cd ~/Documents

➜ cd (change directory) et mou a la carpeta Documents. És on desarem el projecte.

bash
git clone https://github.com/EL-TEU-USUARI/aea6-usuari1-usuari2.git

➜ git clone descarrega una còpia completa del repositori de GitHub al teu ordinador, dins d'una carpeta nova amb el mateix nom. Copia aquesta URL exacta des del botó verd Code del teu repositori a GitHub.

bash
cd aea6-usuari1-usuari2

➜ Entres dins de la carpeta que git clone acaba de crear.

2.5 · Crear la pàgina inicial

Propietari

Dins d'aquesta carpeta, crea un fitxer index.html amb aquest contingut:

index.html
<!DOCTYPE html>
<html lang="ca">
<head>
  <meta charset="UTF-8">
  <title>El nostre projecte AEA6</title>
</head>
<body>
  <h1>Projecte AEA6</h1>
  <p>Pàgina de pràctiques de Git i GitHub en parella.</p>
</body>
</html>

➜ És una pàgina HTML mínima, només per tenir alguna cosa a versionar. L'ampliareu a les properes activitats.

2.6 · Fer el primer commit

Propietari
bash
git add index.html

➜ git add marca aquest fitxer com "a punt per guardar" al següent commit. Sense aquest pas, Git no el tindria en compte.

bash
git commit -m "Primera versió de la pàgina"

➜ git commit guarda una "fotografia" d'aquest estat del projecte. El text darrere de -m és el missatge que explica què has fet.

bash
git push origin main

➜ git push envia aquesta fotografia des del teu ordinador cap a GitHub, a la branca main. Ara sí que apareixerà al repositori remot.

2.7 · Afegir el Col·laborador al repositori

Propietari
  1. Al repositori a GitHub, ves a Settings.
  2. Al menú de l'esquerra, fes clic a Collaborators.
  3. Fes clic a Add people i escriu el nom d'usuari de GitHub del teu company/a.
Col·laborador
  1. Revisa el correu associat al teu compte de GitHub.
  2. Obre el correu de la invitació (o la notificació a GitHub.com).
  3. Fes clic a Accept invitation.

2.8 · Clonar el repositori com a Col·laborador

Col·laborador

Un cop acceptada la invitació, fas exactament el mateix que ha fet el Propietari al pas 2.4:

bash
cd ~/Documents
bash
git clone https://github.com/USUARI-DEL-PROPIETARI/aea6-usuari1-usuari2.git

➜ Fixa't que ara la URL porta el nom d'usuari del Propietari, no el teu, perquè és ell qui ha creat el repositori.

bash
cd aea6-usuari1-usuari2

Comprova que ja tens l'index.html que ha creat el Propietari:

bash
cat index.html

➜ cat mostra el contingut d'un fitxer per pantalla. Si veus el mateix HTML que ha escrit el Propietari, tot ha anat bé.

2.9 · Comprovar que tots dos teniu la mateixa còpia

Ambdós

Cadascú al seu terminal, dins de la carpeta del projecte:

bash
git log --oneline

➜ git log mostra l'historial de commits. --oneline el mostra en una sola línia per commit, en lloc de tot el detall. Els dos heu de veure exactament el mateix identificador de commit ("Primera versió de la pàgina").

3

Verificació

  • git --version funciona correctament als dos ordinadors.
  • El repositori aea6-usuari1-usuari2 existeix a GitHub amb l'index.html pujat pel Propietari.
  • El Col·laborador apareix com a col·laborador acceptat del repositori.
  • git log --oneline mostra el mateix commit als dos ordinadors.
4

Com s'entrega aquesta activitat

No cal copiar res enlloc ni afegir a ningú més: com que heu creat el repositori com a públic (pas 2.2), el professor ja hi pot accedir directament amb l'enllaç. El mateix repositori aea6-usuari1-usuari2 és l'entrega, tant d'aquesta activitat com de les 3 següents.

El professor demanarà l'enllaç del repositori i hi comprovarà:

  • Que existeix i té l'index.html inicial.
  • Que apareixen els dos com a col·laboradors (Settings → Collaborators).
  • L'historial de commits (git log --oneline o la pestanya Commits a GitHub), que mostra l'autor de cada canvi.
💡

Aquest mateix repositori seguirà creixent a la resta de l'AEA6 (A2 a A6): no en creareu cap de nou.

5

Errors freqüents

ProblemaCausaSolució
git push demana usuari i contrasenya i la rebutja GitHub ja no accepta contrasenyes normals per Git; cal un token d'accés personal. Genera'n un a GitHub → Settings → Developer settings → Personal access tokens i fes-lo servir com a contrasenya.
El Col·laborador no veu la invitació al repositori La invitació ha arribat a un correu diferent del que fa servir habitualment. Revisa el correu associat al compte a Settings → Emails, o accepta-la des de la notificació a GitHub.com.
git clone dona error "repository not found" La URL del repositori està mal copiada, o el repositori encara és privat i no s'ha acceptat la invitació. Torna a copiar la URL exacta des del botó verd Code a GitHub.
git commit demana configurar identitat Encara no s'ha executat git config --global user.name/email. Executa les dues comandes del pas 2.1 abans de tornar a fer commit.
