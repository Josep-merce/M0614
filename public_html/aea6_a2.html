1

Context i teoria mínima

Què farem en aquesta activitat

Cadascú treballarà a la seva pròpia branca del repositori: el Propietari afegirà una capçalera a la pàgina i el Col·laborador un peu de pàgina. Els dos canvis es fusionaran a la branca principal amb un Pull Request. També crearàs un token d'accés personal, una mesura de seguretat per autenticar-te des del terminal.

Termes nous que apareixeran:

  • Branca (branch): una còpia paral·lela del projecte on pots treballar tu sol sense afectar la còpia principal. La branca principal es diu main.
  • Pull Request (PR): una proposta que fas des de GitHub: "vull incorporar els canvis de la meva branca a main". L'altra persona pot revisar-lo abans d'acceptar-lo.
  • Merge: fusionar els canvis d'una branca dins d'una altra. Quan acceptes un Pull Request, GitHub fa un merge.
  • Token d'accés personal: una contrasenya especial que fem servir per identificar-nos davant de GitHub des del terminal, en lloc de la contrasenya del compte.

Per què cal un token d'accés

Al pas 2.9 configurareu la mesura de seguretat que hem esmentat als termes nous: perquè GitHub, per motius de seguretat, ja no accepta la contrasenya del compte des del terminal. Fem servir un token: si algú te'l roba, el pots revocar sense haver de canviar la contrasenya del compte.

2

Pas a pas guiat

Anirem molt a poc a poc: cada comanda surt sola, amb una explicació de què fa exactament abans de continuar amb la següent.

💡

Els passos 2.2-2.3 (Propietari) i 2.4-2.6 (Col·laborador) es poden fer alhora, cadascú al seu ordinador: no cal esperar que l'altre acabi.

2.1 · Crear la vostra branca

Propietari
bash
git checkout -b feature/header

➜ Crea una branca nova anomenada feature/header i et hi situa.

Col·laborador
bash
git checkout -b feature/footer

➜ El mateix, però amb una branca anomenada feature/footer.

2.2 · Propietari: afegir la capçalera

Propietari

Obre index.html i afegeix això just després de l'obertura del <body>:

index.html
<header>
  <nav>
    <a href="#">Inici</a>
    <a href="#">Sobre nosaltres</a>
  </nav>
</header>

➜ Un <header> amb un <nav> a dins: dos enllaços senzills de navegació.

2.3 · Propietari: pujar el canvi

Propietari
bash
git add index.html

➜ Marca l'index.html modificat com "a punt per guardar".

bash
git commit -m "Afegeix capçalera de navegació"

➜ Guarda una "fotografia" d'aquest canvi, amb un missatge que l'explica.

bash
git push origin feature/header

➜ Envia aquest commit a GitHub, però a la teva branca feature/header, no a main.

2.4 · Col·laborador: afegir el peu de pàgina

Col·laborador

Obre index.html i afegeix això just abans de tancar el </body>:

index.html
<footer>
  <p>Contacte: aea6@lamerce.cat</p>
</footer>

➜ Un <footer> amb un paràgraf de contacte, igual de senzill que la capçalera del Propietari.

2.5 · Col·laborador: pujar el canvi

Col·laborador
bash
git add index.html

➜ Marca l'index.html modificat com "a punt per guardar".

bash
git commit -m "Afegeix peu de pàgina"
bash
git push origin feature/footer

➜ Igual que al pas 2.3, però pujant a la teva branca feature/footer.

2.6 · Obrir el Pull Request

Ambdós
  1. Ves al repositori a GitHub. Hi apareixerà un avís groc amb la teva branca acabada de pujar.
  2. Fes clic a Compare & pull request.
  3. Revisa el resum de canvis que es mostra.
  4. Fes clic a Create pull request.

➜ Cadascú fa aquests 4 clics amb la seva pròpia branca: el Propietari amb feature/header, el Col·laborador amb feature/footer.

2.7 · Revisar-vos mútuament i fer el merge

Ambdós
  1. Obre el Pull Request del teu company/a (no el teu).
  2. Ves a la pestanya Files changed i mira quines línies ha afegit.
  3. Deixa un comentari curt (per exemple, "Tot correcte").
  4. Fes clic a Merge pull request.

➜ Repetiu-ho amb els dos Pull Requests (l'ordre no importa, ja que toqueu parts diferents del fitxer i no hi haurà conflicte).

2.8 · Actualitzar la vostra còpia local

Ambdós
bash
git checkout main

➜ Et poses a la branca main, on ara ja hi ha els dos Pull Requests fusionats.

bash
git pull origin main

➜ Baixes aquests canvis al teu ordinador. Obre index.html: ara hi han d'aparèixer tant el <header> com el <footer>, encara que cadascú només hagi editat una part.

2.9 · Seguretat: crear un token d'accés personal

💡

Aquest pas el fan tots dos, cadascú al seu propi compte de GitHub. Cadascú tindrà el seu token.

Ambdós — Pas A: obrir la pàgina dels tokens
  1. A GitHub, fes clic a la teva foto de perfil (a dalt a la dreta) → Settings.
  2. Baixa fins al final del menú de l'esquerra i fes clic a Developer settings.
  3. Fes clic a Personal access tokens → Tokens (classic).
Ambdós — Pas B: generar el token
  1. Fes clic al botó Generate new token → Generate new token (classic). Potser et demanarà que confirmis la contrasenya del compte.
  2. A Note, escriu un nom qualsevol, per exemple: Ordinador de l'escola.
  3. A Expiration, tria 90 days.
  4. A Select scopes, marca la casella repo (s'activaran soles les de sota).
  5. Baixa fins al final i fes clic a Generate token.
Ambdós — Pas C: copiar i desar el token
⚠️

El token només es veu una vegada. Copia'l ara mateix (clica la icona ⧉ al costat) i enganxa'l en un lloc segur (una nota al mòbil, un gestor de contrasenyes...). Si el perds, hauràs de generar-ne un altre.

La propera vegada que Git et demani Password for 'https://...', en lloc de la contrasenya de GitHub, enganxa aquest token. El nom d'usuari sí que és el de GitHub.

Després del merge, git pull no baixa els canvis de l'altre Estàs situat a la teva branca feature/... en lloc de main. Fes git checkout main abans de git pull origin main.
