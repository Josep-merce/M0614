1

Context i teoria mínima

Què farem en aquesta activitat

Aprendreu la sintaxi bàsica de Markdown (uns quants símbols per donar format al text) i l'aplicareu al fitxer README.md del vostre repositori, per documentar la instal·lació, configuració i ús de Git que heu fet a les activitats anteriors.

Termes nous que apareixeran:

  • Markdown: un format de text senzill on escrius amb el teclat normal, amb uns quants símbols especials (com #, *, -...), i el text acaba mostrant-se amb format (títols, negreta, llistes...). L'extensió dels fitxers Markdown és .md.
  • README.md: el fitxer principal de documentació d'un repositori. Escrit en Markdown, GitHub el mostra automàticament a la portada del repositori.

Sintaxi de Markdown

A l'esquerra de cada exemple hi ha el que escrius; a la dreta, com es veu un cop desat.

Capçaleres

Escrius
# Títol 1 ## Títol 2 ### Títol 3
Es veu

Títol 1

Títol 2

Títol 3

➜ Com més coixinets (#) al davant, més petit és el títol. Cal deixar un espai entre els coixinets i el text.

Llistes

Escrius
- Element 1 - Element 2 - Element 2a 1. Primer pas 2. Segon pas
Es veu
  • Element 1
  • Element 2
    • Element 2a
  1. Primer pas
  2. Segon pas

➜ Un guió (-) fa una llista sense ordre; un número seguit de punt (1.) fa una llista ordenada. La indentació (espais al davant) crea sub-elements.

Negreta i cursiva

Escrius
**Això és negreta** *Això és cursiva*
Es veu

Això és negreta

Això és cursiva

➜ Dos asteriscs a cada costat (**text**) per negreta; un asterisc (*text*) per cursiva.

Enllaços i imatges

Escrius
[GitHub](https://github.com) ![Text alternatiu](imatge.png)
Es veu

GitHub

🖼️ imatge.png

➜ Un enllaç és [text que es veu](adreça). Una imatge és exactament el mateix, però amb un signe d'exclamació ! al davant.

Blocs de codi

Escrius
```bash git status ```
Es veu
git status

➜ Tres cometes inclinades ``` abans i després del text el converteixen en un bloc de codi, amb lletra de programació. És exactament el que fareu servir sense saber-ho a l'A4 i l'A5, a les pàgines de la Wiki.

Taules

Escrius
| Nom | Rol | |-----|-----| | Anna | Propietària | | Jordi | Col·laborador |
Es veu
NomRol
AnnaPropietària
JordiCol·laborador

➜ Una línia amb guions (|-----|-----|) separa la capçalera de la resta de files. Cada columna es separa amb una barra vertical |.

Pas a pas guiat

Ara aplicareu això que acabeu de veure per documentar, de veritat, la instal·lació, la configuració i l'ús de Git que heu fet fins ara.

2.1 · Preparar la branca

Propietari
bash
git checkout main
bash
git pull origin main
bash
git checkout -b docs/readme

➜ Les tres comandes de sempre: et poses al dia amb main i crees la branca docs/readme.

2.2 · Propietari: documentar la instal·lació i la configuració

Propietari

Obre (o crea) el README.md i escriu-hi això, fent servir el que heu vist a la secció 1:

README.md
## Instal·lació i configuració de Git

Instal·lació a Ubuntu/Debian:

```bash
sudo apt install git
```

Configuració del nom i correu (una sola vegada):

```bash
git config --global user.name "El teu nom"
git config --global user.email "el-teu-correu@exemple.com"
```

➜ Fixa't que has fet servir un títol (##) i dos blocs de codi (```bash). Això documenta la part "instal·lació i configuració" del criteri d'avaluació.

bash
git add README.md
bash
git commit -m "Documenta la instal·lació i configuració de Git"
bash
git push origin docs/readme

➜ El cicle de sempre. Encara no obris el Pull Request: el Col·laborador ha d'afegir la seva part primer.

2.3 · Col·laborador: documentar l'ús

Col·laborador
bash
git fetch origin
bash
git checkout docs/readme

Afegeix això a sota del que ha escrit el Propietari, dins del mateix README.md:

README.md
## Ús del control de versions

Cada canvi es fa en una branca pròpia (`feature/...`). En acabar,
es puja amb `git push` i s'obre un **Pull Request** a GitHub perquè
l'altra persona el revisi abans de fusionar-lo a `main`.

La branca `main` té activada la protecció de branca: no s'hi pot
fer `git push` directament, només mitjançant un Pull Request
revisat. L'autenticació es fa amb un *token d'accés personal* en
lloc de contrasenya.

| Branca | Autor |
|--------|-------|
| feature/header | Propietari |
| feature/footer | Col·laborador |

➜ Aquí has fet servir un títol, negreta (**Pull Request**), cursiva (*token d'accés personal*) i una taula. Això documenta la part "ús" del criteri d'avaluació.

bash
git add README.md
bash
git commit -m "Documenta l'ús del control de versions"
bash
git push origin docs/readme

2.4 · Fusionar la documentació

💡

Aquí feu un únic Pull Request entre els dos, no un per persona com a l'A2. Com que tots dos heu pujat commits a la mateixa branca docs/readme (en lloc de tenir cadascú la seva pròpia branca), els dos commits ja hi són junts: només cal un Pull Request per portar-los tots dos a main.

Ambdós

Obrir el Pull Request (ho fa qui vulgui dels dos, no cal repetir-ho):

  1. Ves al repositori a GitHub. Hi apareixerà un avís groc amb la branca docs/readme acabada de pujar.
  2. Fes clic a Compare & pull request.
  3. Revisa el resum de canvis: hi hauria d'aparèixer 2 commits, un amb el teu nom i un altre amb el del teu company/a.
  4. Fes clic a Create pull request.

Revisar-lo i fer el merge (ara sí, cadascú fa la seva part):

  1. Ves a la pestanya Files changed del Pull Request i mira que hi surtin les dues seccions del README, la teva i la del teu company/a.
  2. Deixa un comentari curt (per exemple, "Tot correcte").
  3. Fes clic a Merge pull request.

➜ A diferència de l'A2, aquí no cal que cadascú revisi el Pull Request de l'altre per separat: com que és un de sol, entre tots dos ja n'hi ha prou.

Actualitzar la còpia local (cadascú al seu ordinador):

bash
git checkout main

➜ Et mou de la branca docs/readme a main, al teu ordinador.

bash
git pull origin main

➜ Baixa a main el resultat del merge (el README complet, amb les dues seccions), que acaba de fer GitHub.

Verificació

  • El README.md inclou les seccions "Instal·lació i configuració de Git" i "Ús del control de versions".
  • Cada secció fa servir com a mínim un títol, un bloc de codi, i (a la segona) negreta, cursiva i una taula.
  • El Pull Request docs/readme apareix fusionat, amb un commit de cada membre.

Errors freqüents

ProblemaCausaSolució
El títol no es veu més gran, es veu tal qual (amb els #) Falta l'espai entre els coixinets i el text. Escriu ## Títol, no ##Títol.
El bloc de codi es veu tot en una línia, sense format Falten les cometes inclinades d'obertura o tancament (```). Comprova que hi ha exactament 3 cometes abans i després del codi, cada una en la seva pròpia línia.
La taula no es veu com a taula Falta la línia de guions just sota la capçalera, o el nombre de columnes no coincideix a totes les files. Revisa que totes les files tinguin el mateix nombre de barres verticals |.
El Col·laborador no veu la secció que ha escrit el Propietari No ha fet git fetch i git checkout docs/readme abans d'editar. Repeteix el pas 2.3 des del principi.
