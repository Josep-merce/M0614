Eines de documentació automàtica

Crearem un petit fitxer JavaScript i en generarem la documentació automàticament amb JSDoc. Anirem molt a poc a poc, explicant cada comanda.

Objectius i prerequisits

Continueu al mateix repositori compartit (aea6-usuari1-usuari2). Aquesta activitat és autònoma: crearem el codi que documentarem des de zero, no cal cap fitxer d'activitats anteriors.

  • Haver completat l'A1: index.html amb header i footer.

1

Context i teoria mínima

Què farem en aquesta activitat

Un fitxer .js conté codi JavaScript: instruccions que fan que la pàgina reaccioni i faci coses (comprovar un text, calcular alguna cosa, mostrar un missatge), a diferència de l'HTML (que defineix el contingut) i el CSS (que defineix l'aparença). Crearem un fitxer js/main.js amb un parell de funcions petites.

Un cop escrites, les documentarem: al costat de cada funció hi escriurem una petita fitxa que expliqui què fa, què li has de donar i què retorna — així qualsevol altra persona (o tu mateix d'aquí unes setmanes) ho pot entendre sense haver de llegir tot el codi. Farem servir JSDoc, una eina que llegeix aquesta fitxa i genera sola una pàgina web amb tota la documentació, sense que l'hàgim d'escriure a mà. Instal·lareu JSDoc amb npm, el gestor de paquets que fan servir els projectes reals de JavaScript.

Termes nous que apareixeran:

  • JSDoc: una eina que llegeix comentaris especials del codi JavaScript (els que comencen per /**) i genera una web de documentació amb totes les funcions descrites.
  • npm (Node Package Manager): un programa que descarrega, instal·la i gestiona automàticament altres programes de JavaScript (paquets). Ve amb Node.js.
  • Paquet (package): una eina o llibreria de JavaScript que es pot instal·lar amb npm. JSDoc és un paquet.
  • package.json: un fitxer petit que fa de "DNI" del vostre projecte: hi surt el nom, la versió i, sobretot, la llista de paquets que necessita per funcionar.
  • node_modules/: la carpeta on npm descarrega els paquets instal·lats. Pot pesar molt i mai es puja a GitHub.
  • Dependència de desenvolupament: un paquet que només fa falta mentre programes (com JSDoc), no quan algú visita la teva pàgina web final.

Com funciona la generació automàtica

💡

JSDoc no és l'única eina d'aquest tipus: cada llenguatge té la seva. Javadoc fa el mateix per a Java, Doxygen per a C/C++/PHP/Python, i Sphinx per a Python. Totes funcionen igual: llegeixen comentaris del codi i generen una web de documentació.

2

Pas a pas guiat

Aquesta activitat té moltes comandes noves. Anirem molt a poc a poc: cada comanda surt sola, amb una explicació de què fa exactament abans de continuar amb la següent.

2.1 · Crear la branca de documentació

Propietari

Igual que a l'A2 i l'A3, primer et poses al dia amb main i crees una branca nova per a aquesta feina:

bash
git checkout main

➜ checkout main vol dir "posa't a la branca main", per assegurar-te que parteixes de la versió més recent.

bash
git pull origin main

➜ pull origin main baixa qualsevol canvi que hi hagi a GitHub i que tu encara no tinguis al teu ordinador.

bash
git checkout -b docs/jsdoc

➜ checkout -b docs/jsdoc crea una branca nova anomenada docs/jsdoc i et hi situa. Tot el que facis a partir d'ara no afectarà main fins que no ho fusioneu amb un Pull Request.

2.2 · Crear el fitxer JavaScript a documentar

Propietari

A l'explorador de fitxers de VS Code (a l'esquerra), fes clic dret sobre el nom de la carpeta del projecte i tria New File…. Escriu com a nom js/main.js (amb la barra inclosa): VS Code crearà la carpeta js i el fitxer main.js a dins, tots dos alhora.

Escriu-hi aquest contingut:

js/main.js
/**
 * Comprova si un camp de text no està buit.
 * @param {string} valor - El text a comprovar.
 * @returns {boolean} true si té contingut, false si està buit.
 */
function campOmplert(valor) {
  return valor.trim().length > 0;
}

/**
 * Mostra un missatge diferent segons si un text té contingut o no.
 * @param {string} valor - El text a comprovar.
 */
function mostrarMissatge(valor) {
  alert(campOmplert(valor) ? "Gràcies!" : "Cal omplir el camp.");
}

➜ Dues funcions: la primera comprova si un text té contingut; la segona la fa servir per mostrar un missatge diferent segons el resultat. Són el que documentarem als pròxims passos.

Desa el fitxer (Ctrl + S) i puja'l:

bash
git add js/main.js
bash
git commit -m "Afegeix funcions de JavaScript"
bash
git push origin docs/jsdoc

➜ Igual que sempre: add prepara, commit desa una fotografia, push la puja a la teva branca docs/jsdoc.

2.3 · Què és npm, i instal·lar-lo

💡

npm és un gestor de paquets: un programa que descarrega i instal·la eines de programació (com JSDoc) de forma automàtica, en lloc d'haver-les de baixar a mà. Ve inclòs amb Node.js, l'entorn que permet executar JavaScript fora del navegador.

Propietari

Comprova primer si ja el tens:

bash
node --version
npm --version

➜ Si totes dues comandes retornen un número de versió, ja els tens i pots saltar al pas 2.4. Si no, instal·la'ls:

bash
sudo apt update

➜ Actualitza la llista de programes disponibles.

bash
sudo apt install nodejs npm -y

➜ Instal·la Node.js i npm junts. Torna a executar node --version i npm --version per confirmar-ho.

2.4 · Inicialitzar el projecte amb npm

Propietari

Assegura't d'estar a la carpeta del projecte (on hi ha l'index.html) i executa:

bash
npm init -y

➜ npm init crea un fitxer nou anomenat package.json, que és com el "DNI" del projecte: hi diu el nom, la versió, i (més endavant) quines eines necessita per funcionar. El -y respon "sí" a totes les preguntes automàticament, perquè no calen personalitzar-les ara.

2.5 · Instal·lar JSDoc com a eina del projecte

Propietari
bash
npm install jsdoc --save-dev

Aquesta comanda té 3 parts:

  • npm install — descarrega i instal·la un paquet.
  • jsdoc — el nom del paquet que volem: l'eina que genera la documentació.
  • --save-dev — apunta a package.json que aquesta eina només fa falta mentre desenvolupem el projecte, no quan algú visita la pàgina web final.

Un cop acabi, veuràs que ha aparegut una carpeta nova: node_modules/. A dins hi ha JSDoc i tot el que necessita per funcionar. Aquesta carpeta pot arribar a pesar molts megabytes.

2.6 · Dir-li a Git que ignori node_modules/

Propietari

node_modules/ mai s'ha de pujar a GitHub: pesa massa, i qualsevol altra persona la pot regenerar sola amb npm install (com faràs al pas 2.8). Obre (o crea) el fitxer .gitignore i afegeix-hi aquesta línia:

.gitignore
node_modules/

➜ Amb això, Git deixarà d'avisar-te sobre aquesta carpeta i mai la inclourà en un commit.

2.7 · Pujar la configuració inicial

Propietari

Fes commit dels 3 fitxers nous (mai de node_modules/):

bash
git add package.json package-lock.json .gitignore

➜ git add marca aquests fitxers com "a punt per guardar".

bash
git commit -m "Configura npm i JSDoc com a dependència de desenvolupament"

➜ git commit guarda una "fotografia" d'aquest estat del projecte, amb un missatge que explica què has fet.

bash
git push origin docs/jsdoc

➜ git push envia aquesta fotografia a GitHub, a la branca docs/jsdoc (encara no a main).

2.8 · El Col·laborador es posa al dia

Col·laborador
bash
git fetch origin

➜ git fetch mira què ha canviat a GitHub, sense aplicar-ho encara al teu ordinador.

bash
git checkout docs/jsdoc

➜ Et situes a la branca que ha creat el Propietari (ara ja la veus, perquè acabes de fer fetch).

bash
npm install

➜ npm install sense cap nom darrere llegeix el package.json que ha pujat el Propietari i instal·la exactament les mateixes eines (JSDoc) al teu propi node_modules/ local. Per això no calia pujar-lo a GitHub.

2.9 · Generar la documentació

Col·laborador
bash
npx jsdoc js/main.js -d docs

Aquesta comanda també té diverses parts:

  • npx jsdoc — executa l'eina JSDoc que acabem d'instal·lar.
  • js/main.js — el fitxer que volem llegir i documentar.
  • -d docs — destination (destí): la carpeta on volem que es guardi la web generada, en aquest cas docs/.

Obre docs/index.html amb el navegador: hi apareixen campOmplert i mostrarMissatge documentades.

docs/index.html

Globals

campOmplert

mostrarMissatge

campOmplert(valor) → boolean

Comprova si un camp de text no està buit.

2.10 · Pujar els canvis i fusionar-los

Col·laborador
bash
git add package.json package-lock.json docs/
bash
git commit -m "Genera documentació amb JSDoc"
bash
git push origin docs/jsdoc
Ambdós

A GitHub, obriu el Pull Request des de docs/jsdoc cap a main (amb els commits dels dos), reviseu-lo i fusioneu-lo. Després, cadascú fa git checkout main i git pull origin main per actualitzar la seva còpia local.

3

Verificació

  • package.json existeix i té jsdoc com a devDependency.
  • node_modules/ apareix al .gitignore i no s'ha pujat mai a GitHub.
  • docs/index.html mostra campOmplert i mostrarMissatge documentades.
  • El Pull Request docs/jsdoc apareix fusionat, amb commits dels dos membres.

Errors freqüents

ProblemaCausaSolució
npx jsdoc: command not found No s'ha executat npm install a la carpeta del projecte, o no hi ha package.json. Comprova que estàs dins de la carpeta del projecte i que node_modules/jsdoc existeix.
node_modules/ apareix a git status El .gitignore no s'ha creat o no conté la línia correcta. Revisa que el fitxer .gitignore existeix a l'arrel del projecte i conté exactament node_modules/.
El Col·laborador no té les mateixes dependències que el Propietari No ha fet npm install després de baixar la branca docs/jsdoc. Executa git checkout docs/jsdoc seguit de npm install abans de generar la documentació.
