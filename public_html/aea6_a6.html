Objectius i prerequisits

Última activitat de l'AEA6, al mateix repositori compartit (aea6-usuari1-usuari2). Configurareu un robot que revisa automàticament el codi cada vegada que algú fa push, sense que ningú hagi de fer-ho a mà.

Prerequisits

  • Haver completat l'A1-A5: index.html, style.css, js/main.js amb campOmplert(), i la branca main protegida.
💡

Com sempre, main segueix protegida: tots els canvis es faran a una branca nova, ci/actions, i es fusionaran amb un Pull Request al final.

1

Context i teoria mínima

Què farem en aquesta activitat

Configurareu una "sentinella" que revisi automàticament el vostre codi cada vegada que algú pugi un canvi al repositori. Aquesta sentinella és un workflow de GitHub Actions: un fitxer de configuració que li diu a GitHub què ha d'executar i quan.

Termes nous que apareixeran:

  • Integració contínua (CI, Continuous Integration): la pràctica de comprovar el codi automàticament cada vegada que canvia, en lloc de fer-ho a mà de tant en tant.
  • GitHub Actions: l'eina de CI integrada a GitHub. No cal instal·lar-la: només cal desar un fitxer de configuració al repositori i GitHub s'encarrega d'executar-lo.
  • Workflow: (en anglès, "flux de treball"): una llista de passos que GitHub executa automàticament quan passa alguna cosa al repositori (per exemple, un push). Cada workflow és un fitxer .yml desat a .github/workflows/.
  • YAML: un format de text senzill per escriure fitxers de configuració, basat en indentacions (espais al davant de cada línia). Els workflows de GitHub Actions s'escriuen en YAML.
2

Pas a pas guiat

Anirem molt a poc a poc: cada comanda i cada línia del fitxer de configuració surt sola, amb la seva explicació.

2.1 · Crear la branca

Propietari
bash
git checkout main
bash
git pull origin main
bash
git checkout -b ci/actions

➜ Les tres comandes de sempre: et poses al dia amb main i crees una branca nova, ci/actions.

2.2 · Crear la carpeta del workflow

Propietari
bash
mkdir -p .github/workflows

➜ mkdir -p crea la carpeta .github i, a dins, la carpeta workflows, totes dues d'un cop. GitHub Actions només busca fitxers de configuració exactament en aquesta ruta.

2.3 · Crear el fitxer de configuració

Propietari
bash
nano .github/workflows/ci.yml

➜ Obre l'editor per crear el fitxer ci.yml. El nom del fitxer el pots triar tu; l'important és que estigui dins de .github/workflows/ i acabi en .yml.

2.4 · Escriure el workflow, línia a línia

Propietari

Comença amb el nom del workflow:

ci.yml
name: Comprovacions de qualitat

➜ El nom que es mostrarà a la pestanya "Actions" de GitHub.

Indica quan s'ha d'executar:

ci.yml
on: push

➜ on: push vol dir "executa't cada vegada que algú faci git push", a qualsevol branca.

Defineix un "job" (una feina):

ci.yml
jobs:
  comprovar:

➜ jobs pot contenir diverses feines; nosaltres només en tindrem una, que anomenem comprovar.

Indica on s'ha d'executar:

ci.yml
    runs-on: ubuntu-latest

➜ GitHub farà servir un ordinador virtual amb Ubuntu (la mateixa distribució que feu servir vosaltres) per executar les comprovacions.

Ara la llista de passos. El primer sempre és descarregar el codi:

ci.yml
    steps:
      - uses: actions/checkout@v4

➜ uses: actions/checkout@v4 és una acció ja feta per GitHub que descarrega el teu repositori a l'ordinador virtual. Sense això, l'ordinador virtual no tindria els teus fitxers.

Segon pas: comprovar que index.html existeix:

ci.yml
      - name: Comprova que index.html existeix
        run: test -f index.html

➜ name és només l'etiqueta descriptiva d'aquest pas. run executa una comanda de terminal normal: test -f comprova que un fitxer existeix, i falla (atura tot el workflow) si no el troba.

Tercer pas: comprovar que js/main.js no té errors de sintaxi:

ci.yml
      - name: Comprova la sintaxi del JavaScript
        run: node --check js/main.js

➜ node --check llegeix un fitxer JavaScript i comprova que estigui ben escrit (claus tancades, punts i comes, etc.), sense arribar a executar-lo. Si hi ha un error d'escriptura, aquest pas falla.

2.5 · Veure el fitxer complet

.github/workflows/ci.yml
name: Comprovacions de qualitat

on: push

jobs:
  comprovar:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Comprova que index.html existeix
        run: test -f index.html
      - name: Comprova la sintaxi del JavaScript
        run: node --check js/main.js
⚠️

La indentació (els espais al principi de cada línia) és obligatòria en YAML: si una línia no comença amb el mateix nombre d'espais que les del seu grup, el fitxer no és vàlid. Copia-la exactament com es mostra.

2.6 · Pujar el workflow

Propietari
bash
git add .github/workflows/ci.yml
bash
git commit -m "Afegeix workflow de integració contínua"
bash
git push origin ci/actions

2.7 · Veure el resultat a la pestanya Actions

Propietari
  1. Al repositori a GitHub, fes clic a la pestanya Actions (a dalt).
  2. Hi veuràs una execució en marxa, amb un punt groc (en procés).
  3. Fes-hi clic a sobre per veure el detall dels 3 passos executant-se.
  4. Quan acabi, el punt es tornarà verd ✅ (tot correcte) o vermell ❌ (alguna comprovació ha fallat).

2.8 · Col·laborador: comprovar que també s'executa al seu Pull Request

Col·laborador
bash
git fetch origin
bash
git checkout ci/actions

Afegeix un petit comentari al final de js/main.js, per exemple:

js/main.js
// Revisat pel Col·laborador
bash
git add js/main.js
bash
git commit -m "Afegeix comentari de revisió"
bash
git push origin ci/actions

➜ En pujar aquest commit a la mateixa branca, el workflow es torna a executar automàticament. Ves a la pestanya Actions i comprova que hi apareix aquesta segona execució, també en verd.

2.9 · Fusionar els canvis

Ambdós

A GitHub, obriu el Pull Request des de ci/actions cap a main (amb els commits dels dos). Fixeu-vos que, dins del mateix Pull Request, GitHub mostra si la comprovació de CI ha passat o no abans de deixar-vos fer el merge. Reviseu-lo i fusioneu-lo. Després, cadascú fa git checkout main i git pull origin main.

3

Verificació

  • El fitxer .github/workflows/ci.yml existeix, amb la indentació correcta.
  • La pestanya Actions mostra com a mínim 2 execucions, totes en verd.
  • El Pull Request ci/actions apareix fusionat, amb commits dels dos membres.

5

Errors freqüents

ProblemaCausaSolució
El workflow no apareix a la pestanya Actions El fitxer no està exactament a .github/workflows/, o no acaba en .yml. Comprova la ruta i el nom del fitxer amb ls .github/workflows/.
L'execució surt en vermell ❌ des del primer pas Un error d'indentació al fitxer YAML. Revisa que cada nivell (jobs:, comprovar:, steps:...) tingui exactament els espais indicats a l'exemple del pas 2.5.
Falla el pas "Comprova la sintaxi del JavaScript" Hi ha un error d'escriptura real a js/main.js (per exemple, una clau { sense tancar). Executa node --check js/main.js al teu propi ordinador per veure l'error exacte abans de tornar a pujar-ho.
El Pull Request no deixa fer merge El workflow encara s'està executant, o ha fallat. Espera que acabi (punt groc → verd), o soluciona l'error que indica en vermell.
